# 节奏单元与音块时间轴 · Demo 0.3

本轮按用户确认实施：采用时间轴，块内禁止额外起音，块外空白自由。继续保留网页 demo，
不在本轮迁移桌面。傅立叶／本底 BPM 仍作为待验证思路，没有选出唯一 BPM 后永久量化素材。

## 节奏单元

音素对齐保留不变，新增可重新派生的 `rhythm-groups-v1`。
相邻元音在没有辅音／静音且边界间隙不超过 35 ms 时合并，覆盖重复长音、ei/ou 和 kai/kui；
N 向前附着，但 N 后面的元音另起。MFA 的长元音符号与原生标签仍完整保留。
合并仅改变节奏点，不把整组时长误认为其中每个元音的时长；指定音素时查该音的连续延长段。
有明显重新发音但模型没有标出间隔时，可在界面拆分；覆盖记录关联具体对齐版本，默认结果不标为人工验证。

长停顿必须是模型静音或未标注空隙，至少 250 ms，并在分离人声上通过低能量检查。
两侧各保留 30 ms 边缘，AP／呼吸／未知音不自动视为可删静音，长元音也不作为停顿。
所有语音段共享一个速度倍率；只有这些静音中心可以压缩或延长，不会移动单个音素强行对拍。

## 查询与匹配

- 音块左沿是要求起点，半开区间 `[start, end)` 禁止其他起点，右沿不是音尾约束。
- 未覆盖区域不限制额外起点；要排除密集语音，可把音块拉长覆盖不应再次起音的区间。
- 支持不固定边界、固定首点、固定末点、首末同时固定。前文／尾部即使超出所画区域也保留。
- 有序一对一对应搜索最多保留 96 个假设；对每个假设用线性规划连续求倍率、平移和静音长度，
  不再只抽样固定的倍率／偏移。最终再次检查实际时间映射满足块内排除规则。
- 匹配点残差分为容差内和近似；两类均不得违反音块覆盖区。搜索可能漏解，未声称全局穷尽。
- 原圆点查询 JSON 可继续经旧路径使用；新 UI、试听和对齐导出使用音块查询。
- 画布上限 1,024 拍、64 块；每句上限 128 节奏单元。画布宽度不是导出文件时长。

## 试听与导出

`仅原句节奏点` 按原始间隔播放点击声，`原句＋节奏点` 在一个音频缓冲内叠加语音与点击，
两者不依赖独立运行的节拍器。`试听所画节奏` 单独播放音块的起点。

`对齐播放` 用搜索的具体分段时间映射渲染语音，同时叠加低音素材起点和高音目标起点。
这版的“对齐”是保持连读比例后的最佳有界匹配，未承诺每个元音精确落拍；界面显示剩余偏差。
FFmpeg atempo 保音高变速的实际瞬态也可能有偏移，模型时间戳不能代替人工边界验收。

调整静音时保留两侧保护区，编辑边缘加短淡化，伸长部分不循环可能残留的说话声。
对齐导出与预览共用一份时间映射；WAV 不含点击声，TextGrid 中音素与节奏点沿同一映射转换。
文件保留原前文和尾部，必要时补查询原点前后静音，清单给出文件时间与查询时间的换算。
版本／分组改变后，旧结果不能继续用于对齐导出，需重新检索。

接口：`RhythmQuery` 新增 `notes/span_beats/boundary/adjust_pauses`；
详情增加 `rhythms`；新增 `POST /api/cues/{id}/preview` 与节奏拆分接口；
导出可携带原查询和预期分析／节奏版本。音频缓存、时间映射和拆分均保留来源记录。

## 验证与仍需听检的部分

- 43 项测试通过；单元与集成测试覆盖长音／元音链／鼻音、人工拆分、密集起点、自由留白、首尾约束、连续倍率、
  可调静音、长音保护、点击定位、导出 TextGrid 与版本校验。
- 同一批 24 句：HubertFA 原始 167 起点合并为 136 单元，MFA 134 起点合并为 120 单元。
  没有重新运行模型，也没有覆盖旧音素标签；数量减少不是准确率证据。
- 两个后端均实际完成三种预览与对齐导出；本机 24 句默认四点查询约 0.6 秒，不能外推全库性能。
- 浏览器验证了拖画／删除音块、手工拆分与恢复，以及纯点击、叠加和匹配试听。
- 尚未实现连续语音内部的局部变速、自然语言筛选、音高筛选、自动 BPM 决策或自动编排。
