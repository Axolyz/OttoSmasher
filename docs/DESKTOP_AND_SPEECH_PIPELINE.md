# 多界面 helper 与人声前处理修正 · 2026-09-12

用户确认：网页可以继续用作 demo，等工作流成熟后再迁移桌面；优先要求能可靠拖出实际文件，
暂不为 REAPER 或 HiFiShifter 做专用插件。这不撤销最初文档中的独立多界面要求。

## 产品界面与可保留的架构

现在的网页是算法与数据流程验证界面，不能视为已交付最初文档的 P0 闭环。
原片画面／精确截取、无字幕采样、独立采样管理、版本与标签管理以及原生文件拖放仍然缺失。

| 独立工具 | 职责 | 不应依赖 |
| --- | --- | --- |
| 检索与浏览 | 台词、节奏、上下文、来源筛选 | 启动完整 DAW 或所有模型 |
| 播放器／截取器 | 视频、波形、选区、细定位，支持无字幕媒体 | 必须先有台词记录 |
| 采样管理器 | 标签、评分、多个处理版本、即时试听、拖入／拖出 | 检索和播放器窗口必须常驻 |
| 处理任务界面 | 分离、分析、队列、失败与重试 | 用户持续开着浏览器 |

可以保留 Python 的导入、数据库、音频处理、分析与查询；界面调用这些操作，不将算法写进页面。
当前数据库仍以字幕 cue 为中心，需要继续增加独立的 Sample、AudioVersion 与候选选区对象。
手工音频可以没有 cue；分析必须关联实际 AudioVersion，不能仅靠“属于哪句字幕”判断输入。
本次的 `audio_lineage` 已记录输入版本，后续应规范成独立资产表，而非假定数据库已经完整。

桌面界面可用 PySide6/Qt，或 Electron 的原生宿主；现在不必锁定最终界面框架。
Qt 支持 `QDrag + QMimeData.setUrls`，Electron 支持 `webContents.startDrag`：
[Qt 官方说明](https://doc.qt.io/qtforpython-6/overviews/qtgui-dnd.html)、
[Electron 官方示例](https://www.electronjs.org/docs/latest/tutorial/native-file-drag-drop)。
因此“使用网页技术”不等于“只能拖一个网页链接”，但普通浏览器 demo 不能代替真实 DAW 验收。

交接规则：拖动开始前已经有稳定、可读取的普通 WAV／视频文件；文件名包含台词或标题、版本、
简短 ID；不在拖动事件中等待分离／渲染，也不随预览关闭就删除文件。字幕、来源和处理历史通过
资产 ID／清单关联。原生宿主只负责文件拖放、系统剪贴板与多窗口等交互。
本次仅准备了可选 Qt 依赖，没有开发或宣称验收桌面拖放。

## 修正的语音流水线

此前“分离只做一个独立试验、实际对齐继续读原混音”的顺序不满足这个素材库的语音检索目标。
全库混音能量起点也只是瞬态诊断，不是 4,515 句都已有语音节奏分析。

新的默认链路：

1. 从选定原片音轨提取 44.1 kHz 双声道上下文；不要先做单声道 16 kHz 再分离。
2. pymss / HyperACE v2 / MLX，明确选择 `vocals` stem，保存模型／配置哈希与输入来源。
3. 分离上下文比对齐窗口前后额外各 3 秒；分离后才裁到字幕前后各 0.65 秒的对齐窗口。
4. 检查分离输出的时长，再生成音素对齐所需的单声道 16 kHz 派生文件。
5. HubertFA／MFA 对齐，以及音素能量、节奏特征，读取同一份分离人声。
6. 试听与导出明确选择原混音或分离人声。更换版本改变缓存键、文件名和来源清单。

原混音保留用于 A/B、参考画面同步与非人声音效制作，未修改任何原片。
分离失败或人声文件校验失败会报错，不能自动回退混音继续生成“人声结果”。
旧的混音音素结果仍在数据库中作为诊断；正常音素检索和页面详情不再使用它们。
只有显式选择“原混音能量（诊断）”才检索原来的能量起点。

## 本次落地与验证范围

- 同一批 24 句完成 pymss 双声道上下文分离；HubertFA 和 MFA 都各产出 24 句分离后对齐。
- 24 句的能量特征也重新从分离人声计算，新增原混音／人声 A/B 与所选版本导出。
- 分离缓存保存源音轨、窗口、模型哈希、stem、文件哈希与原片时间原点。
- 19 项测试通过：覆盖混音结果排除、禁止静默回退、缓存校验、试听／导出版本一致性及可读文件名。
- 24 份分离缓存重复读取后文件时间未变；浏览器 A/B 播放与导出成功，核对清单确认音频和标注关联同一人声资产。
- 4 个真实原速／变速人声导出时长误差均小于 14 ms；这只验证渲染时长，不代表音素精度。
- 仍是诊断样本，还没有对 12 集执行全量分离／音素对齐。

分离不是准确率保证：伴奏残留、呼吸／清辅音损失、字幕读音和长音表示仍可能影响结果。
本次 HubertFA 的“小于 20 ms 音素”标记从原混音的 16 句变成分离后的 19 句，这不是准确率指标，
不能据此断言改善或退化，更不能用“全部运行成功”声称识别已经正确。MFA 仍有 3 句出现 `spn`。需要结合 A/B 与人工边界检查。

后续先稳定声音版本、切点和查询，再迁移桌面多界面；不因 demo 存在而取消原始 helper 工作流。
