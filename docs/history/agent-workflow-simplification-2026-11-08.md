# 工作流改动复查与收紧

日期：2026-11-08。接续 [第一轮评估](agent-workflow-review-2026-11-08.md)，以所有者本轮补充为准。第一轮记录保留当时快照；其中 review.py、PATH 检测、flatten.preview、flatten.submitMany 和独立 separation 主题已撤回，不是现行能力。

## 红线

真实字幕的格式、标注习惯和例外没有穷尽的列表。方法中保留模糊空间，是为了让 agent 先理解来源，不能将有限示例变成固定的识别器。机械代码只处理明确的数据契约、传输、数学换算与状态；不决定“这是不是人名”“是否换人”“这段够不够好”“核验是否足够”。目的地的字幕导入规则仍有确定契约，这与理解任意原始字幕不同。

不能仅以“不自动改字幕”证明某个脚本没有越界。固定的候选规则会决定哪些内容进入视野，形式化台账也可能让模型误把文件存在、状态填满或退出码为零当成完成。即使有免责声明，也不值得把这种偏置变成默认工具。

## 全部新增机械部分的处置

| 部分 | 复查结论与处理 |
|---|---|
| review.py 的括号正则与 labelled/unlabelled 模式 | 删除。它只能覆盖有限形式，且先依赖 app parser 的 line 分类，可能在统计前就漏掉未理解的输入；没有再增加正则或兜底类别 |
| 同一助手的 0.2 秒短句、10 ms 能量、分位数门槛和 40 ms 邻域 | 删除。阈值虽只标候选，仍会固化选择偏好；任务临时分析可按当前素材选择，但不作为内置通用规则 |
| 同一助手的固定 cue ±1 s 上下文包、证据／状态清单和 check 退出码 | 随助手整体删除。exports.wav 和 Mapping 已提供机械能力，无需再维护一套报告格式或完成认证。记录仍建议保留，形式由任务决定 |
| 字幕统计、拆行、边界和声纹指引 | 保留方法并收紧表述。例子不是封闭列表；先读原文、样式和轨道，形成假设后实听核验，再按来源写临时统计。未解析不等于无标签，脚本无报告不等于正确。起止、换人和声音归属继续由上下文判断 |
| speaker_embed.py | 本轮及上轮未改原脚本。它接受明确时间段，解码并输出向量／短片段提示，不识别字幕格式、不自动分类角色、不拆行；模型最短输入补零不等于边界正确性。原实验数字继续标明局限 |
| audio_probe.py | 保留传输适配。只调用请求中指定的 MCP 工具、保留错误、保存返回图片，不解释字幕。在传输边界用 SDK 的 by_alias 序列化为标准 MCP JSON，统一读协议字段 isError，不猜不同 Python 字段名。取消脚本强设 turbo，尊重现有环境和请求的模型选项 |
| LinkClient.iter_results 与 --wait | 保留一种分页实现，--wait 复用它，删除重复循环。只处理公开 API 的 offset/limit 和失败条目，没有内容筛选 |
| 公共 argparse 参数、BOM、JSON 与等待输出 | 保留确定修复：避免子解析器覆盖公共参数、支持标准 UTF-8 BOM、坏 JSON 给传参提示、默认不刷进度、非交互调用不刷临时 session note。没有按作品或 Windows 会话增加专用行为 |
| LinkClient.from_env 与 jobs.get | 复用已有同种运行实例发现规则；直接按 ID 查询任务，避免最近 500 项窗口漏任务。保留，不增加新的实例选择算法 |
| jobs.summaries、会话创建物与 samples.metrics | 保留必要的读取能力。分别投影持久化任务字段／实际调度顺序，按已有 actor_session 筛选，复用已有缓存有效性规则。它们不解释素材，也不需要新表、推理或按情境特判 |
| spectrum.get.frequencies | 保留，复用既有数学函数给出行中心频率，不另猜 log/mel 频率轴 |
| Studio 模型缓存 | 保留嵌套文件身份及显式刷新：修复已确认的子目录新增文件不使根目录 mtime 改变的问题。不重写 stem、不替 Studio 装模型，不按模型名字加例外 |
| flatten.alignmentIssue | 保留，暴露既有不可用分支，不放宽对齐要求、不自动换处理范围、不改声音算法 |
| flatten.preview | 删除包装端点及类型／测试。已有 open 和 estimate 可获取冻结输入、处理区间和缓存估算；估算仍不代替提交校验或实际成品质检 |
| flatten.submitMany 及专用重试分支 | 删除。逐项不同参数可以在 otto run 中复用现有 open / estimate / submit；统一参数的 submitBatch 原样保留。没有为任务脚本额外扩充 worker 持久化格式。两接口均未发布，没有日用数据兼容负担 |
| 连接权限特判 | 删除上轮新增 PermissionError 提示分支，恢复通用异常传递；真正有问题的是公共错误说明预设“端点过期”等原因。改为中性说明并保留原始 reason，权限问题的当前办法写 README |
| Windows PATH 检测与开场白分支 | 按所有者说明全部撤回。这是本机旧开发版残留，不作为产品缺陷；删 where.exe 调用、辅助函数、字段、文案及专用测试 |
| 长菜单与缩放 | 保留共享组件限高／滚动和原生快捷键修复。移除上轮额外设的缩放 [-4,4] 范围，沿用 Electron 的能力；没有在各页面堆窗口尺寸特判 |
| 中英 separation 主题 | 删除。必要的刷新与复用说明并回已有 prepare 的分离小节，不新建别名或重复入口 |
| 自动更新与清理 | 未新增。沿用原 skill 同步机制：内置已移除的文件若未改可清理，用户改过的保留；不碰用户字幕、数据库、日用应用或权限配置 |

## 文档与已知问题

README 中英版增加“已知问题”，列出 Windows IPC 沙箱、外部音频工具成本、字幕／声纹质量边界、新建物不能撤销、诊断不足、导出／MIDI 和部分 Windows DAW 交互限制。Windows 使用 Codex 以外的 LLM agent，当前按所有者反馈建议由用户开启 Full Access；不声称每个宿主已验证，也不由应用或脚本自行改权限。

这里没有尝试用新增代码解决全部反馈。未实现的增强仍留在 ROADMAP；PATH 残留不再列作待修缺陷。DECISIONS、ARCHITECTURE、用户说明和两种语言的现行指南已同步，不让历史快照冒充当前接口。

## 验证边界

继续沿用现有 pytest、CoreProc、fake_studio、Vitest 和 Playwright，只跑相关范围。删除的测试只针对一并删除的助手／API／PATH 分支，保留原有产品测试和确定缺陷回归。

便携客户端继续用真实 audio-mcp 0.4.0 对合成短 WAV 验证 audio_view / audio_analyze；未下载 ASR 模型。Windows 实机、第三方宿主 Full Access 行为、较低能力模型遵循和真实字幕全流程质量仍未验证，不以测试通过替代这些结论。

本轮定向结果：pytest 104 项、Vitest 12 项、Playwright 3 项通过，API 目录核对、typecheck、i18n:check 与 git diff --check 通过。audio-mcp 正常 view／analyze 成功；额外以不存在的 WAV 验证首项错误、次项成功仍逐项保存且最终退出 1。没有通过增加宽容回退来吞错误。
