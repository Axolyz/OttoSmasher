# Agent 工作流改进：评估与实施记录

日期：2026-11-08。基于 0.1.5 源码（起点 `716623b`）、所有者确认的方案及 OttoFeedback。没有构建发布包，没有操作日用发布版或日常工作区。

## 判断依据与边界

阅读 `AGENT-WORKFLOW-FINDINGS.md`、`AGENT-WORKFLOW-FINDINGS-subtitles.md`、`OTTO-AGENT-CLI-ISSUES-2026-11-08.md`，选择性核对 UTF-16 大会话里的用户纠正、调用及末尾结果，并看了 `image.png`。反馈里的“最终完成”多次被后文推翻，不能把自报准确率、任务成功或最终总结当成内容验收。

本会话此前使用软件时同样暴露了问题：最初漏接音频工具；不确定名字与换人拆行混为一谈；语义检索过分依赖字面和高音，选成了被欺负的尖叫；预告台词所配画面不是说话角色；工程修订后时间索引可能只更新部分。现在把这些写进对应任务的方法与完成条件，而不是加一套必须逐步推进的工作流引擎。

Windows 报告中的现象只在能从源码或当前回归确认时记为已修。Windows 实机、原 DSH 沙箱、较低能力模型的指令遵循改善均未验证。真实字幕只做了读取与核验助手试跑，未宣称重新验证对轴、声纹或内容判断质量。

## 指令与技能的取舍

- `otto guide workflow` 统一范围、精度和完成证据：已有适用偏好就复用，否则只问一次 quick / standard / fine。精细字幕要求全范围筛查、所有可疑起止／换人／重叠逐项核验，普通场景抽查；逐句全检另行明确。精度降低必须说明并取得同意，不能因模型能力较低而降低正确性要求。
- 确定性机械操作交给脚本与接口；方法给默认路线与依赖，内容判断保留自由度。`review.py` 生成带输入指纹的候选清单、导出带上下文和 mapping 的音频包、核对证据与待办；筛查不自动修改边界，核验通过也不能证明模型真的听看过。
- 新 `otto guide audio` 先发现已有能力，再用真实短片段逐项验证。便携 stdio 客户端解决没有宿主 MCP 的接法；返回图片另存供实际查看。CLI 可看图和测量不等于转写已验证，不把整个任务挡在配置问题上。
- 从 `7b4c8da` 之前恢复中文应用指南，保留现行英文位置，补齐同名主题及新行为。技能仍是可编辑中英两份，原有“用户修改不覆盖、删除不补回、冲突留 .new”机制不变。
- `2ca9887` 删除的 picking-lines 值得恢复，但原版步骤太泛。重写为语义、角色、语气、正负情绪、跨情境重组和画面核验的选材技能。高 F0 不等于开心；他人对角色说的话不能用角色自己的宣言代替。
- 同次删除的 separating-audio 不恢复为独立技能：核心操作大多是确定接口，独立入口增加阅读与维护。改放 `otto guide separation`，讲复用、整轨／局部／多段成本、stem 角色和新建物副作用。
- 保持命名管道／本地端点；不改 TCP、不放宽沙箱或 ACL、不改 PyMSS Studio 环境、不换分析算法、不新增数据库工作流或迁移。

## 连接反馈（AGENT-WORKFLOW-FINDINGS.md）

| 节 | 结论 |
|---|---|
| 1 沙箱拒绝命名管道 | 保持命名管道。PermissionError 明确端点及本地 IPC 权限问题，提示检查宿主沙箱／ACL；不猜成端点过期、不改保护。本机无法验证原 DSH 沙箱 |
| 2 旧命令抢 PATH | Windows 发布版设置页检测 where.exe 的首个解析结果；冲突时显示路径，开场白用完整命令路径，不覆盖别人的 shim。纯函数单测通过，实机未验证 |
| 3 连接错误误导 | 区分权限错误与失效端点；保留原始异常信息，不泛化成“重启就好” |
| 4 stderr note | 同 C5 |
| 5 工作区不一致 | LinkClient.from_env 无显式环境变量时复用 CLI 的同种运行实例发现；显式工作区优先，不把发布版和源码版混连 |
| 6 横向参照 | 作为设计参考，不把别的工具的 TCP 或权限策略当本项目要求 |
| 7 优先级 | 修确定缺陷和可观测性，沙箱限制如实说明，不为“能连接”绕过边界 |

## 界面截图与额外实际使用问题

截图显示的是长右键菜单的内容越过弹层背景，不是要重做页面布局。共享 Popover 限高，Menu 内滚动，短窗口可见最后一项；增加现有 sources e2e。Windows 没有应用菜单，补原生缩放键处理，现有 shell e2e 通过 Electron 原生输入验证缩小／放大／恢复；本机 macOS 通过，Windows 未验证。

选台词、音色、OP/ED 的精度与事实核验复用同一契约。工程变动后索引须更新全部依赖行，或明确哪些仍属旧快照；不把部分更新的音素时间表宣称与当前工程全部一致。

## 验证与后续复测

沿用现有 pytest 单元／CoreProc 集成、fake_studio、Vitest、Playwright 和 API 目录生成检查，无独立测试平台。本机定向结果：pytest 109 项、Vitest 13 项、Playwright 3 项通过；API 目录核对、typecheck、i18n:check、git diff --check 通过。不跑全量 e2e。

真实 CC 只读试跑：`ゆるゆり　なちゅやちゅみ＋.S01E01.JA.srt`，SHA-256 `976a50ab43c6b8de880104d8c9502031b165a4b7c4fe7c4767d28d5c8cc35e38`。337 句、11 类原始行标注组合、218 个初始候选，fine 有待办时检查不通过；独立开发工作区的原素材／台词／采样仍为零。原字幕未改，包含原文的中间 JSON 不提交。

audio-mcp 0.4.0 通用客户端：用本项目缓存启动真实 MCP server，对合成的 2 秒 220 Hz 含前后静音 WAV 调 audio_view 和 audio_analyze 均成功；PNG 已实际打开，能看到约 0.2–1.8 秒稳态及两侧静音。没有下载转写模型，transcribe 与真实日语转写质量未验证；这不是字幕端到端验收。

以下是下一轮原环境／模型复测场景，尚未执行，不能把文档测试当其通过：

| 场景 | 应观察到的行为 |
|---|---|
| 未指定精度、已有 stems 的四集字幕 | 只问一次精度，复用 stems，实际验证所需音频能力，不重复分离 |
| 两行明确换人，第二人未知 | 按轮次拆开，已知者保留，未知者待定，不写 other 或全 cue 留空来掩盖换人 |

| PowerShell、旧 shim、IPC 被拒 | 分别诊断 PATH、JSON、权限；用完整路径／参数文件，不绕过沙箱、不推断应用没开 |
