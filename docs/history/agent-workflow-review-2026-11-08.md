# Agent 工作流改进：评估与实施记录

日期：2026-11-08。基于 0.1.5 源码（起点 `716623b`）、所有者确认的方案及 OttoFeedback。开发和测试使用隔离工作区，本轮为源码改动。

本记录是第一轮快照，后续取舍见 [工作流改动复查与收紧](agent-workflow-simplification-2026-11-08.md)。

## 资料与判断依据

阅读 `AGENT-WORKFLOW-FINDINGS.md`、`AGENT-WORKFLOW-FINDINGS-subtitles.md`、`OTTO-AGENT-CLI-ISSUES-2026-11-08.md`，选择性核对 UTF-16 大会话里的用户纠正、调用及末尾结果，并看了 `image.png`。反馈里的“最终完成”多次被后文推翻，因此结合调用和后续纠正判断实际完成情况。

本会话此前使用软件时同样暴露了问题：最初漏接音频工具；不确定名字与换人拆行混为一谈；语义检索过分依赖字面和高音，选成了被欺负的尖叫；预告台词所配画面不是说话角色；工程修订后时间索引可能只更新部分。现在把这些写进对应任务的方法与完成条件，供 agent 结合当前任务选择。

Windows 报告中的现象只在能从源码或当前回归确认时记为已修。Windows 实机、原 DSH 沙箱、较低能力模型的指令遵循改善均未验证。真实字幕只做了读取与核验助手试跑，对轴、声纹和内容判断质量留待进一步实测。

## 指令与技能的取舍

- `otto guide workflow` 统一范围、精度和完成证据：已有适用偏好就复用，否则只问一次 quick / standard / fine。精细字幕要求全范围筛查、所有可疑起止／换人／重叠逐项核验，普通场景抽查；逐句全检另行明确。精度降低必须说明并取得同意，各档都保留未知和未决项。
- 确定性机械操作交给脚本与接口；方法给默认路线与依赖，内容判断保留自由度。`review.py` 生成带输入指纹的候选清单、导出带上下文和 mapping 的音频包、核对证据与待办；筛查不自动修改边界，实际听看和判断由 agent 完成。
- 新 `otto guide audio` 先发现已有能力，再用真实短片段逐项验证。便携 stdio 客户端解决没有宿主 MCP 的接法；返回图片另存供实际查看。看图、测量和转写分别试用，配置期间继续其他准备。
- 从 `7b4c8da` 之前恢复中文应用指南，保留现行英文位置，补齐同名主题及新行为。技能仍是可编辑中英两份，原有“用户修改不覆盖、删除不补回、冲突留 .new”机制不变。
- `2ca9887` 删除的 picking-lines 值得恢复，但原版步骤太泛。重写为语义、角色、语气、正负情绪、跨情境重组和画面核验的选材技能。检索时兼顾语气、情绪和对话双方。
- 同次删除的 separating-audio 不恢复为独立技能：核心操作大多是确定接口，独立入口增加阅读与维护。改放 `otto guide separation`，讲复用、整轨／局部／多段成本、stem 角色和新建物副作用。
- 沿用命名管道／本地端点、PyMSS Studio 环境、分析算法和数据结构。

## 界面截图与额外实际使用问题

截图显示的是长右键菜单的内容越过弹层背景，不是要重做页面布局。共享 Popover 限高，Menu 内滚动，短窗口可见最后一项；增加现有 sources e2e。Windows 没有应用菜单，补原生缩放键处理，现有 shell e2e 通过 Electron 原生输入验证缩小／放大／恢复；本机 macOS 通过，Windows 未验证。

选台词、音色、OP/ED 的精度与事实核验复用同一契约。工程变动后一起更新索引的相关行，仍属旧快照的注明输入版本。

## 验证与后续复测

沿用现有 pytest 单元／CoreProc 集成、fake_studio、Vitest、Playwright 和 API 目录生成检查，无独立测试平台。本机定向结果：pytest 109 项、Vitest 13 项、Playwright 3 项通过；API 目录核对、typecheck、i18n:check、git diff --check 通过。不跑全量 e2e。

真实 CC 只读试跑：`ゆるゆり　なちゅやちゅみ＋.S01E01.JA.srt`，SHA-256 `976a50ab43c6b8de880104d8c9502031b165a4b7c4fe7c4767d28d5c8cc35e38`。337 句、11 类原始行标注组合、218 个初始候选，fine 有待办时检查不通过；独立开发工作区的原素材／台词／采样仍为零。原字幕未改，包含原文的中间 JSON 不提交。

audio-mcp 0.4.0 通用客户端：用本项目缓存启动真实 MCP server，对合成的 2 秒 220 Hz 含前后静音 WAV 调 audio_view 和 audio_analyze 均成功；PNG 已实际打开，能看到约 0.2–1.8 秒稳态及两侧静音。没有下载转写模型，transcribe 与真实日语转写质量未验证；字幕端到端质量仍待实测。
