# 字幕对轴与说话人识别：探索记录

记录这两件事试过哪些模型、流程架构怎么一步步定下来、依据和局限是什么。留给以后要接着做、或想换模型的人，免得重走一遍。

**这是过程记录，不是现行规矩。** 现行决定看 [DECISIONS §4、§12](../DECISIONS.md)，agent 的实际做法看 `core/ottosmasher/cli/guide/skills/` 里的 `retiming-lines`、`cleaning-subtitles`、`grouping-speakers`，未结的事看 [ROADMAP L54](../ROADMAP.md)。

**读数字前要知道：**

- 数字都是当时会话和实验记录里的结果，除特别注明外没有重跑。
- 模型比较和整套流程都只在《孤独摇滚》（12 集，Netflix 日语 CC 字幕）上做过，换作品不一定成立。
- 实验脚本和中间结果留在所有者本机，没有进仓库（里面有字幕原文，还写死了本机路径）。第 4 节写了做法，可以照着重建。

## 结论速览

| 问题 | 结论 | 主要依据 |
|---|---|---|
| 对齐器能不能自己找到台词在哪 | **不能**，只能精修。它总会把整句塞进窗口，也不报失败 | 时间错开后起止大多差 1–2 秒（§1.4） |
| 对轴怎么做 | 先用带词时间的转写或音量起止粗对，再用 pydomino 精修，用分离后的人声 | 同上；经 otto 跑通（§1.6） |
| 对轴放进应用吗 | 不放。应用开放 `speech.align`，判断交给 agent | §1.6 |
| 一条字幕两个人，怎么切开 | 用对齐，两行各当一句。不用说话人切分模型 | 真实换人两半都对：对齐 63%，pyannote 11%，Nemotron 12%（§2.3） |
| 声纹用哪个 | `anime_speaker_embedding`（按角色） | 跨集认人：anime 87%，ReDimNet2+ 80%，ResNet293 72%（§2.4） |
| 瓶颈在哪 | 声纹本身，特别是短句和相近的声音，不在分组算法 | 用全部标注当样本，找回率上限也只有约 63%（§2.6） |
| 说话人功能放进应用吗 | 不放。做成 skill，脚本和做法随说明走，模型第一次用时才下载 | §2.7 |

## 1. 字幕对轴

### 1.1 起点：旧版留下的选型

重写前，旧版并存过多个对齐模型。规格 14 把 narabas、HubertFA、MFA、SOFA、Yohane、Qwen3-ForcedAligner 列为已退役，2026-10-04 所有者收敛为**只用 pydomino**（规格 18 D9）。规格只留了结论，没有留比较数字，所以这里说不出当时各模型差多少。

字幕自动校正（SubPlz、sub-align 一类）同时被移出主流程，放到独立实验里（规格 02「字幕预处理」）。

### 1.2 整集自动对轴工具（2026-09）

在《兽娘动物园》12 集上，用分离后的人声跑了两个现成工具，都在 CPU 上：

| 工具 | 做法 | 条数变化 | 每集用时（中位数） | 能不能逐行对回原字幕 |
|---|---|---|---|---|
| [SubPlz](https://github.com/kanjieater/SubPlz)（Whisper `turbo`） | 转写后和字幕文字匹配，重新分组 | 4730 → 4434 | 约 12.5 分钟 | 不能 |
| [sub-align](https://github.com/Jim-Elijah/sub-align)（`--margin 1.5`） | VAD + 强制对齐 | 4607 → 4607 | 约 2.5 分钟 | 能 |

**两边的结果都没有验证过准确度**（结果文件里 `verified` 全是 false），所以这轮只说明它们跑得通，不说明谁更准。SubPlz 会改变条数，这对要保留原字幕结构、说话人标注的流程是硬伤。

### 1.3 生产任务里的做法（2026-10-25、26）

另一个 agent 整理 bangumi 字幕时，配合使用过这些工具，用完都删了：

- 多语言句向量（MiniLM，ONNX）：逐句匹配日中字幕。
- mlx-whisper（`small`、`large-v3-turbo`）：转写疑点，核对内容。
- Matplotlib：画波形、音高、频谱给 agent 看。

这轮的中间产物（`agent-*` 文件夹）已在 2026-10-31 按所有者要求删除，详细数字查不到了。留下来的经验写进了 skill `cleaning-subtitles`：

- 别的版本的字幕可能整体错开、从 CM 处错开，或少一整段对白。要在开头、中间、结尾抽查，把剪辑点定位到具体某一句。
- Whisper 容易漏尖声感叹和人群喊话；提示里写了角色名时，还可能编出没人说过的话。所以**转写只用来核对**。
- 对齐成功不能证明窗口是对的。

### 1.4 对齐器的能力边界（2026-10-29、30）

想知道 pydomino 能不能直接拿来对轴，用已分析的台词试了两轮：

| 试验 | 结果 |
|---|---|
| 20 句，时间错开 ±0.5–1.5 秒，窗口放宽到前后 2 秒 | 每次都“成功”，但起止大多差 1–2 秒 |
| 60 句，窗口放宽到前后 0.5 秒 | 约一半句子的起点或终点偏 0.3 秒以上 |
| 60 句，时间错开 0.5 秒以上 | 几乎都对不好 |

**结论：对齐器只会把整句塞进给它的窗口，不会自己找这句话在哪。** 窗口要紧贴说话，前后各留 0.1–0.2 秒。

试过加“可疑”标记（看音素长度、窗口两端空白、换窗口重对稳不稳定），要么漏掉大半，要么把三到四成好结果也标成可疑，**所以没有加**。结果里只给 `edges`、`longestPhone` 这些事实。

### 1.5 粗对用什么

| 工具 | 情况 |
|---|---|
| [audio-mcp](https://github.com/mshark1/audio-mcp) 的 `audio_transcribe`（faster-whisper `turbo`） | **在用**。只跑 CPU，30 秒台词转写 8.6 秒。给词级时间，日语的词较长，精度约零点一到零点几秒，够粗对。只认 `turbo` 这个名字，写 `large-v3-turbo` 会报错 |
| Qwen3-ASR 1.7B + Qwen3-ForcedAligner 0.6B（GGUF） | **下载了，没测**。2026-10-30 的调研：两个文件来自不同的转换工具（CrispASR 与 predict-woo 系），不一定能在同一个程序里加载；CrispASR 的对齐器按空格切词，它自己说不太适合日语；没找到动画日语的独立评测；audio-mcp 也换不了引擎。所有者定“接 Qwen 以后再说” |
| [earshot](https://github.com/Leonxlnx/earshot) | 只看过说明，没有语音识别，不适用 |

### 1.6 架构：怎么定下来的

1. 规格阶段，自动对轴不进主流程，用户在外部校正后再导入。
2. 2026-10-25，所有者提出“上下文优先”：判断类、算法本身不稳的事不进应用，应用只给原子能力。字幕清洗属于这一类。
3. 2026-10-29，试验结果不好，一度决定不开放对齐命令。
4. 2026-10-30，所有者反对：“语音对齐的就业面很广，远不止字幕对轴的需求”，同时担心“把一堆 agent 能力和一个 C 端 app 打包在一起”。讨论后定了判断标准：**没有 agent 时应用自己也需要、也在维护的能力，就开放；不需要的（ASR、OCR、抠图）交给外部工具。** agent 自己 clone 上游，得不到和应用一致、带用户辞典和素材上下文的结果。

现在的分工：

```
带词时间的转写 / 音量起止      audio-mcp 等外部工具（粗对，0.1–0.2 秒内）
        ↓ 外部工具的时间用 exports.wav 返回的 mapping 换回原片秒
speech.align                  应用（精修，不写资料库）
        ↓ agent 判断结果可不可信
edits.apply                   应用（写回段，来源可查、可撤销）
```

**端到端验证：** 全季 1838 条两行字幕经 `otto` 用 `speech.align` 的 `lines` 切行，1834 条成功（修掉一个 bug 后其余 4 条也能跑）。85% 的边界和实验差不到 1 毫秒，98% 差不到 0.1 秒，个别差 0.3–1.3 秒（实验用 ffmpeg 重采样，应用用 `resample_poly`）。

## 2. 说话人识别

### 2.1 起点

旧版做过角色声纹聚类，规格 02 记为“实测质量不可用，已退役”。2026-10-30 所有者决定重新试验：“超级实验性质”，不做内置流程和页面，必须先分离。

### 2.2 第一轮：摇曳百合 1 集（2026-10-30）

所有者最初指定 WeSpeaker 的最好模型加 sklearn 聚类。在一集分离人声上，字幕标了单个说话人的 110 句：

| 模型 | 同人 / 异人分错率（50% = 瞎猜） | 每人 3 句参考的归类准确率 |
|---|---|---|
| WeSpeaker ResNet34 | 42% | 42% |
| WeSpeaker ResNet293 | 43% | 41% |
| WeSpeaker CAM++ | 43% | 41% |

同一句切成两半，两半的相似度也只有 0.07–0.64。这些模型用名人采访训练，分不开动画里几个都是少女音、又在表演的声线。

换成在视觉小说配音上训练的 [anime_speaker_embedding](https://pypi.org/project/anime-speaker-embedding/)，并只留干净标签（单行、只标一人、1 秒以上，47 句）。这时发现之前的低分有一大部分是**标签本身不干净**：

| | 每人 3 句参考 | 每人 5 句参考 | 盲聚类纯度 |
|---|---|---|---|
| anime（按角色） | 84–86% | 91–92% | 87% |
| ResNet293 | 71–79% | 76–89% | 68–72% |

时序信息（整集 332 句，只在那 47 句上打分）：

| 做法 | ARI | 纯度 |
|---|---|---|
| 普通层次聚类 | 0.44 | 85% |
| 先按时间合并成发言段再聚类 | 0.47 | 94% |
| 普通聚类 + 简易时间平滑 | 0.35 | 64% |

简易平滑反而变差，因为它把不同的人粘在了一起。样本太小，只够选模型，不够调时序算法。

**讨论过但没做的：VBx。** 它是能利用时序的主流聚类后端，但依赖按声纹模型训练的 PLDA，而动画模型没有现成的。也看过一个带 VBx 的现成项目，只开放“整段音频进、片段出”的入口，接不进字幕句、自己的声纹和标签，自带的声纹又是 ResNet34，所以没用。后面的实验表明瓶颈在声纹，这条就没再追。

### 2.3 字幕规律和换人边界

**所有者给出的规律，是整个方案的基础：**

- 换人必换行，换行不一定换人。所以**按行拆开后，一行只有一个人**。
- CC 字幕的标注是为了消除歧义才加的，不是为了标明“这句是谁说的”。标了的句子偏向难辨认的情况（画外音、人群），字幕标签既不能当标准答案，也不能盲目当样本。
- 《孤独摇滚》的规则特别严：两行字幕换人，当且仅当两行都标。核对 1839 条两行字幕：两行都标 229，只标第一行 474，都不标 1136，只标第二行 0。**这一点不能推广**（§2.5）。

**边界实验。** 所有者见过长句对齐不好，所以要求和 pyannote 正面比，后来又加了 Nemotron。实验自己解析 SRT，没有用应用的规则。

拼接测试（两句不同人的台词拼起来，真实边界已知，误差 < 0.3 秒的比例）：

| | 对齐 | Nemotron 3 Diarization | pyannote segmentation-3.0 | 按字数比例切 |
|---|---|---|---|---|
| 一般句子（480 对） | **91%** | 14% | 25% | 62% |
| 长句（拼起来 7 秒以上） | **96%** | 25% | 32% | 68% |
| 抢话（剪掉停顿紧贴着拼） | **82%** | 17% | 15% | 47% |

真实换人字幕（192 条）：

| | 对齐 | Nemotron | pyannote | 按字数比例切 |
|---|---|---|---|---|
| 两半都认对（用 anime 声纹判断） | **63%** | 12% | 11% | 50% |
| 发现了第二个人 | — | 22% | 16% | — |
| 不用标注判断换没换人（AUC） | 0.91 | 0.55 | 0.57 | 0.93 |

- 长句并没有让对齐在换行处变差，所有者担心的情况在这份数据里没有出现。
- 切分模型输的原因是**分不开动画里的几个女声**：同一个 10 秒窗口里不同人的两句，pyannote 约 25%、Nemotron 19% 能分开，男声对女声是 57%、62%。原混音上也一样，不是分离造成的。
- 按比例切判断换没换人的 AUC 略高于对齐，但实际切点差很多。判断和切开是两回事。
- [SUPlime-L](https://huggingface.co/rewayai/suplime-large)（CC BY-NC 4.0）下载了，所有者决定不测。

### 2.4 声纹模型

同样的数据，主要角色 8 人：

| | anime（按角色） | ReDimNet2+ | ResNet293 |
|---|---|---|---|
| 同人 / 异人错误率（越低越好） | **0.32** | 0.34 | 0.39 |
| 同一集，每人 5 句参考 | **78%** | 71% | 53% |
| 跨集：1–3 集当参考，认 4–12 集 | **87%** | 80% | 72% |
| 跨集，1 秒以内 | **66%** | 51% | — |
| 跨集，1–2 秒 | **84%** | 77% | — |
| 跨集，2–4 秒 | **95%** | 92% | 79% |
| 跨集，4 秒以上 | **100%** | — | 84% |
| 盲分组的纯度 | **86%** | 61% | 57% |
| 速度 | 13628 段 180 秒 | 13628 段 769 秒 | 11518 段 1138 秒 |

- **ReDimNet2+ 对音量敏感**：同一段放大 4 倍，前后余弦相似度只有 0.76。试过峰值归一化，结果几乎一样。
- **anime 的版权问题：** 模型许可是 MIT，但训练数据是爬来的视觉小说配音，有灰色地带。所以**应用不分发它**，脚本第一次运行时才从 Hugging Face 下载。想避开的话，ReDimNet2+（Apache-2.0）能用，代价是跨集认人从 87% 降到约 80%。

### 2.5 字幕标注习惯差别很大

只看文字统计 bangumi 里的日语字幕（一秒钟就能算完）：

| 来源举例 | 相邻两条都标注时是同一个人 | 只标第二行的两行字幕 |
|---|---|---|
| 孤独摇滚、悠哉日常大王 WEB、摇曳露营 Amazon | 3–13% | 0–1 条 |
| 兽娘动物园、小林家的龙女仆、摇曳百合、点兔原版 | 9–16% | 几十到上千条 |
| 摇曳露营 Netflix、NEW GAME、珈百璃 Netflix | 21–30% | 80–160 条 |
| 幸运星、点兔字幕组版 | 37–47% | 一两百到四百多条 |

所以 skill 要求 agent **按来源先给标注做体检**，再决定规律能用多硬。

### 2.6 流程实验

目标随讨论变了两次，这比算法选择影响更大：

1. **“把所有人分好组”**：盲聚类分得太碎，15 个人分成约 49 组。
2. **“每组尽量纯，组数可以多”**：所有者接受一季 100 组以内。
3. **“把主要角色找准，其余的都可以不管”**：路人可以留在待定。这其实更像“认人”，不像“分组”。所有者接着指出，一个角色可能有两套声线，分开反而是新信息，不必压成一组，所以算法上**一个角色可以挂几个声线组**。

**没有标注时**（只用“换人必换行”，标注只用来打分；门槛在 1–6 集挑，在 7–12 集打分；主要角色 8 人）：

| 目标准确率 | 实际准确率 | 找回率 | 话少的集 | 1 秒以内 | 1–2 秒 | 2 秒以上 |
|---|---|---|---|---|---|---|
| 95% | 94% | 65% | 74% | 36% | 70% | 79% |
| 97% | 95% | 62% | 72% | 26% | 69% | 79% |

- 听 20 组命名就够，听到 30、40 组找回率也不再升。
- 用全部标注当样本的上限也只有约 63%，所以**瓶颈在声纹，不在分组**。
- 贡献最明显的是场景加成（60 秒内已出场的角色放宽门槛）：目标 97% 时，去掉它找回率从 62% 掉到 51%。
- “其他人”的反面参考只能用确认过的组。没命名的组里混着主要角色的碎片，拿来当反面，ひとり的找回率从 57% 掉到 26%。

**有标注时**（标注当声音样本，每类取最像的 5 条，差距门槛在样本内部交叉验证；按条 5 折藏标注打分）：

| 指标 | 结果 |
|---|---|
| 准确率 / 找回率 | 95% / 73%（1 秒以内 49%，1–2 秒 77%，2 秒以上 85%） |
| 准确率 97% 时 | 找回率 66% |
| 样本 30% / 10% | 找回率 65% / 53% |
| 样本 10%，自训练一轮 | 61% |

2026-11-04 用保存的声纹重跑过这张表的前两行：95.2% / 73.0%，97.1% / 66.2%，和记录一致。

**一个反直觉的结果：**“最像的几条”只在样本干净时才好。没有标注时，样本来自分组，混着别人的句子，改用它反而更差：找回率 65% → 60%，1 秒以内 36% → 14%。所以两种情况的做法不同。

### 2.7 架构：从内置命令到 skill

这件事的架构改了四次，每次都是往“应用做得更少”的方向走：

| 轮次 | 方案 | 为什么放弃 |
|---|---|---|
| 1 | Core 加 `speaker.embed`、`speaker.cluster`，模型随包 | 分组参数和流程都是判断，写死在应用里不合适 |
| 2 | 加 `speaker.assign`，参考模式 | 同上，而且没有标注的字幕用不了 |
| 3 | 只内置确定的计算（切行、声纹、相似度、分组、校准），判断交给 agent | 所有者追问：“这些内置计算你还是觉得非常有必要内置，而不是可以像字幕对轴一样……交给 agent 自己做吗” |
| 4（现在） | **skill**：做法写进 `grouping-speakers`，附一个算声纹的脚本，应用只补通用能力 | — |

逐项拆开后发现现有命令基本够用，内置的好处只是“不用装东西”。代价却不小：实验性算法进 Core、多一个 sklearn 依赖、发布包要分发有版权灰色地带的模型。

只有声纹脚本值得现成给：16 kHz 单声道、数值范围、太短的片段这些细节看不出来，容易做错。分组、校准是标准计算，agent 自己写。

应用只补了两处：`speech.align` 的 `lines`（一条字幕几行各当一句对齐，并给每行起止），以及确认 `edits.apply` 能写 `speakers`。

### 2.8 落地和后续

- **字幕的说话人规则同时改了**（2026-10-31，规格 06 §6.2 基线变更）：逐行读，“宁可丢不写错”，有标注但不确定的记 `speakersWithheld`，原文留在 `raw`。清洗过的字幕一条一个人。
- **一次完整清洗**（2026-10-31，孤独摇滚 12 集）：227 条两人条目中 210 条拆开，17 条因为有一行没找到而没拆；2882 条没标注的条目中，2129 条靠声纹得到说话人（校准到 97%）。

## 3. 没做、没定的

| 事项 | 现状 |
|---|---|
| 别的字幕风格 | 说话人流程只在《孤独摇滚》上打过分（ROADMAP L54） |
| 人工标准答案 | 没有。提议过人工标 150–200 句，没做；现在用字幕标注代替，而标了的行偏难 |
| “人听代表句命名” | 是用标注模拟的，比真人听略乐观 |
| 没标注的行 | 全季 3999 行猜出 81%，但这些行没有真值，准确率量不了 |

| 字幕里没写的插话 | 一条字幕时间内别人的“うん”“えっ”会污染声纹，没处理过 |

## 4. 想复现时

**素材：** 《孤独摇滚》S01 12 集 Netflix 日语 SRT，HyperACE v2（`bs_roformer_voc_hyperacev2.ckpt`）分离的人声。第三方版权内容，不进仓库。

**打分方法：**

- **切法：** 对齐把两行当两句，切点取两句之间的停顿。切分模型在字幕时间附近取 10 秒窗口，看局部说话人的活动概率。
- **拼接测试：** 两句已知不同人的台词拼起来，切在两句之间的静音里都算对，误差是到这段静音的距离。抢话测试没有静音，误差是到拼接点的距离。
- **跨集认人：** 1–3 集当参考，认 4–12 集。
- **流程打分：** 只算主要角色（整季标注至少 40 行）。没有标注时门槛和测试分开（1–6 集 / 7–12 集）；有标注时按条 5 折，门槛只在样本内部校准，不偷看被藏起来的标注。
- **解析字幕：** 不用应用的规则。`（名字）`单独占一行算下一行的标注；整行括号（音效）删掉；半角注音删掉；多人标注和 ♪ 行不参与认人。
