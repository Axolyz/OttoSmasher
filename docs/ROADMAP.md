## 1. 每个阶段都必须做到（完成定义）

这些规则散在 AGENTS、ARCHITECTURE、UI_PLAN、QUESTIONS 里，阶段验收前逐条自查，验收清单里写明自查结果。

**数据与业务**
- [ ] 业务逻辑只在 Core 命令里；界面不做业务判断（为阶段 11 脚本与将来的 agent 留路，ARCHITECTURE §15）。
- [ ] 所有用户资料修改走统一编辑通道（预览 → 原子应用 → 可撤销，对象带版本）；快捷编辑也产生编辑记录（R9）。
- [ ] 耗时或调用模型的操作是任务：提交时冻结业务输入与设备设置、结构化进度、可取消（结束整棵进程树）、可重试、取消不留半成品登记（规格 13 §13.1）。
- [ ] 时间换算只走 `domain.mapping`；每个时间值写明所属时钟（原片秒 / 资产局部秒 / 文件秒 / 采样显示坐标）。
- [ ] 不静默回退、不静默降级、不静默替换（P6）；未知不是零（P7）；资料变化只提示“资料已更新”，不自动刷新、重排、重选（P8）。
- [ ] 测量按资产共享，不跨资产借用；内容指纹已废弃，文件是否被替换看“文件快照”（Q D3）。
- [ ] 结构变更写新的迁移文件（不改旧迁移）；迁移前自动备份已由框架保证。
- [ ] 算法按规格的【基线算法】/【基线参数】逐项复现，规格里的数值例子写成单元测试；不顺手“优化”结果。

**界面**
- [ ] 动手前在原型里走一遍对应部分，做完并排截图比对，差异按 `docs/ui/PROTOTYPE_GUIDE.md` §2 处理并记进 STATUS 差异表。
- [ ] 只用 `app/renderer/components/` 里的组件；缺了先补进组件库并更新组件样张，不在页面里手写复选框、菜单、弹层、表格。
- [ ] 集合类界面遵守 UI_PLAN §6.1 统一规则（单击只看、勾选只靠复选框类手势、右键不改选择且菜单头写对象、Esc 分层）；波形遵守 §6.2；快捷键与焦点区遵守 §7。
- [ ] 所有可见文字走 `t()`，新页面进伪语言 e2e；`node tools/i18n-check.mjs` 通过；数字日期用统一格式（只翻译文字，Q21）。
- [ ] 采样名、台词、读音标 `lang="ja"`。
- [ ] 主色是 logo 蓝 `--accent`；性质四色：语音青绿、调谐琥珀、非调谐珊瑚、未分类灰；只用设计令牌，不写死颜色。
- [ ] 窗口最小约 850×600 可用；1920×1080、缩放 100/125/150% 布局可用（规格 15 §15.7）。
- [ ] 空状态、加载中、出错、文件缺失、超长名称、上千行列表都要有样子（原型没画，自己按设计语言做，验收时给所有者看）。

**验证与交付**
- [ ] 单元/合成测试优先；真实素材经 `OTTO_FIXTURES` 原地引用、小批运行，不复制、不进 Git、不上传；不全库跑模型。
- [ ] 能自动化的用 pytest / vitest / Playwright（驱动真实 Electron）证明；人工只验自动化证明不了的（听感、REAPER、拖到 Finder、Windows）。
- [ ] Windows 上没实测的一律标“未验收”。
- [ ] 每个子步骤验证后单独提交，只提交自己的改动；推送、合并、发布等所有者授权。
- [ ] 环境只用 `tools/uv`、`tools/npm`（不往用户目录写任何东西）。

## 2. 会话交接协议

**开工（每个新会话）**
1. 自动加载的 CLAUDE.md 指向这里。读 AGENTS.md → 本地 STATUS.md（当前阶段、“下一步”）→ 本文件 §1–§3 与当前阶段一节 → PROTOTYPE_GUIDE 中对应阶段的行。
2. `git status` 看有没有未提交的修改（可能是上一个会话或别的会话留下的；不要丢，也不要混进自己的提交）。
3. 读当前阶段列出的交接包规格章节与 docs/16 验收条目；读 QUESTIONS 里与本阶段相关的答复。
4. 查 §3 遗留事项登记表里“到期阶段 = 当前阶段”的条目，并入当前计划。

**收工（每个会话结束前，哪怕阶段没完）**
1. STATUS：当前子步骤做到哪、怎么验证的、下一步具体做什么、未提交的工作。
2. 本文件 §3：新产生的遗留事项、待所有者决定的事项登记进去（写明到期阶段）；已处理的划掉并注明提交号。
3. 所有者新给的答复写进 QUESTIONS（第五节按轮次记录）；影响界面的同步回写 UI_PLAN；影响架构的同步 ARCHITECTURE。
4. 不在子步骤做到一半时换会话。

**阶段收尾**
1. 按 §1 自查；按 PROTOTYPE_GUIDE §5 做并排比对。
2. 验收清单：对应 docs/16 的条目、怎么运行、该看什么（操作 → 应该看到什么）、自动化验证结果、与原型的差异、已知问题与未做、需要所有者决定的事。
3. 更新本文件下一阶段一节里“开工前要知道的”（把本阶段学到、下一阶段会用到的写进去）。

**续接提示词**（所有者开新会话时粘贴；比交接包里的版本多了本文件）

```text
继续开发 OttoSmasher 新版。按 docs/ROADMAP.md §2 的“开工”步骤：读 AGENTS.md、STATUS.md、docs/ROADMAP.md（§1–§3 与当前阶段一节）、
docs/ui/PROTOTYPE_GUIDE.md 对应行，再读当前阶段相关的交接包规格与 docs/16 验收条目。检查 git 状态和未提交的修改（不要丢掉，也不要混进自己的提交），
然后从 STATUS.md 的“下一步”继续。遵守 AGENTS.md 全部规则；规格不清先问我；会话结束和阶段结束都按 ROADMAP §2 收尾。
```
