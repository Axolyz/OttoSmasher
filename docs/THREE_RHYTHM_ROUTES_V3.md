# Demo 0.6：三条卡拍路线

选中一句已分析台词即可生成节奏参考，不需要先做节奏搜索。SOFA 为默认模型；其他模型和原始分析保留。

| 路线 | 占格依据 | 对应不足时 |
| --- | --- | --- |
| 纯 mora | 文本 mora 直接决定每个合并节奏单元占几格 | 明确不可用；可填写缺失格数 |
| mora 参考校准 | 实测起点间隔为主，可靠 mora 计数作软约束 | 缺失单元的 mora 项为零，不猜读音 |
| 原节奏量化（无 mora） | 实测间隔、持续时间及可伸缩间隙 | 短句也直接计算，不回退到 mora |

“自动长音补格”默认关闭，只改变纯 mora 路线。开启后，只有连续长元音证据才增加实际占格；文本 mora 数、起点数量与模型边界均不改动。开关状态也用于三路线的对照列。校准和无 mora 两条路线不依赖此开关。

## 倍率与试听

先推断一个整数节奏型，再按 ×1／×2／×4／×8（每拍格数）播放。每格分别是 1／0.5／0.25／0.125 拍，不生成更细格和三连音。一个单元可以占 3 格；它不因此增加起点。4/4 只规定小节线，不强迫填满整数小节。

新句默认选连续语音总时长最接近原句的倍率。切换算法保留当前倍率，方便对照；另行显示整体时长倍率、对应播放速度、局部形变量。三个算法的源节奏尺可能不同，同一个 ×4 不保证相同播放速度。可选该算法排序最前的倍率来比较接近原速的结果。

表格并列显示三条路线逐音占格。相同起点、尾音与外部变速映射会显示“相同”，不故意扰动结果制造候选。纯节拍、原声叠加、严格试听、WAV/TextGrid 和 REAPER 均继续使用所选 `plan_id`。

修改占格只锁定真正改过的单元，其他单元保持自动；人工格数同时约束三条路线。清空某个输入可恢复自动，整体恢复按钮清除所有人工格数。缺少 mora 对应时仍显示可填写的表格。

搜索锁点默认关闭。开启后查询是显式硬约束，可以改变自动占格；显示实际锁点后占格，并以“搜索锁点调整”标明，同时在方案保留 `inferred_slots`。人工格数无法同时满足时报告冲突。锁点不得落在所选网格之外，禁止起音区仍生效。检索原始分数不变。

## 无 mora 与校准算法

输入是已经合并的感知起点，不是逐 mora 起点。连续元音、附着鼻音和长音的现有合并与人工拆分规则不变。“无 mora”仅指时值分配：模型对齐和节奏分组仍可以使用字幕／音素。

1. 根据每对起点和末尾结束控制点测量间隔，扣除重叠的声学间隙，防止静音被计为长音。最后一个音参与同样的分配。
2. 从实测间隔及可用周期候选提出多种源时间尺；不从 mora 平均时长初始化，不要求台词有唯一 BPM。
3. 用有界有序动态规划联合选择整数格距。目标包括间隔比例误差、相邻拉伸突变、短语累计漂移，以及偏好简单整数模式的惩罚。每个起点保留，不能删除、复制或重排。
4. 特别短的间隔按实际时长降低权重（最低保留四分之一），减少单个极短模型标记主导整句节奏尺的问题。它仍必须占至少一格，局部大变形仍会显示；这不是自动修正模型边界。
5. 2／4 秒窗口的周期与相位有支持时，以小权重参与整数格距的转移代价。短句、周期不稳的片段照常按实测间隔分配。真实停顿后累计相位／漂移约束重新开始。
6. 校准模式在相同优化器中增加 mora 软约束，既可减格也可增格，不限制为原格数上下微调一格。无 mora 模式完全去掉该项及全部 mora 派生初始化。

这是有界候选搜索，不保证数学上的全局最优，更不是音乐审美评分。源时间尺范围和简单模式惩罚避免通过任意小时间尺与巨大整数“解释一切”。周期与音高频谱是不同的信号，当前周期分析使用起点强度序列。

停顿独立就近量化为休止格。短于半个源时间尺的间隙不额外占整格，例如一个长停顿仅有 0.4 ms 跨入下一起点间隔时，不会凭空多加一格。源弱声音和呼吸仍由渲染器保留并伸缩，不填零、不删片段。

## 版本与接口

方案版本为 `binary-reference-v3`。旧 `binary-reference-v2` 方案需重新生成；上游模型输出与原片不变。派生方案、试听和旧导出文件不删除。

`POST /api/cues/{id}/quantization-plans` 增加／更新：

- `strategy`: `mora` / `mora_guided` / `acoustic`。
- `auto_long_vowels`: 布尔，默认 `false`。
- 原有 `bpm`、`density`、`analysis_kind`、版本字段和可选查询锁点保持。

返回四倍率 `plans`、`algorithm_statuses`、逐单元三路线 `comparison_slots`、`same_as_strategies`、`algorithm_evidence`。证据包含源时间尺、是否使用周期、短间隔权重及目标函数诊断。这些是解释数据，不能替代试听判断。

`algorithm_statuses` 表示输入是否可生成该路线，具体倍率的锁点冲突另列在 `conflicts` 中。纯 mora 不可用时仍返回 `reference.slots` 供人工填写。移除的 `local_period` 请求会明确被拒绝，避免旧名称静默改义。

验证入口：`scripts/validate_three_routes.py`。它读取固定 200 句现有四模型分析，不重跑模型、不修改语料。结果写入 `outputs/validation/three-routes-v3.json`，记录代码及输入指纹、可用/失败状态、映射差异和真实渲染检查。
