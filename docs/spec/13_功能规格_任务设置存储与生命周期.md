# 13 功能规格：任务、设置、存储与生命周期

---

## 13.1 任务

### 13.1.1 哪些是任务

所有耗时或调用模型的操作都是后台任务，界面提交后立即返回：

| 任务 | 通道 |
|---|---|
| 分离（整轨/选区；人声/三轨，调用 PyMSS Studio） | 模型 |
| 语音分析（批量/单条/选区；文本前端 + 对齐 + 派生 + 必要时音高测量） | 模型 |
| 音高测量与音高检索索引准备 | 模型 |
| 拉平（单个/批量，每项一个任务或一个任务多项皆可） | 模型 |
| 单音声学指标准备 | 轻量 |
| 派生重建（量化、语音检索索引，例如改了大数字惩罚度） | 轻量 |
| 视频片段导出（可能较慢） | 轻量 |

拖出生成 WAV 是同步的短操作（有取消），不进任务列表。

### 13.1.2 生命周期

- **状态**：排队 → 运行中 → 成功 / 失败 / 已取消；进程意外退出的标为**已中断**（“工作进程已退出，可重试”）。
- **并发**：两条通道各自限流——模型任务默认 **1**、轻量任务默认 **2**（设置 1–4；“多开会叠加内存”）。
  排队任务不应各自常驻一个进程空转（旧版一任务一进程、轮询抢锁，过度复杂）。
- **提交时冻结**：业务输入（资产选区、文本、辞典快照、参数、模型身份）和设备设置都在提交时冻结；之后改设置不影响已提交的任务。
- **取消**：排队或运行中可取消；必须结束**整个进程树**（PyMSS Studio worker、对齐 worker、ffmpeg 等）——POSIX 用进程组，Windows 用作业对象或按进程树结束；
  只结束本任务的进程，不误伤其他任务；取消后的结果不登记，半成品不登记。
- **重试**：失败/已取消/已中断可重试 = 用相同业务参数新建一个任务（新 ID）；设备设置用**当前**设置（用户常常是改了设备才重试）。
- **退出应用**：有排队或运行中的任务时提示“退出将取消 N 个任务”；确认后取消全部任务（结束整个进程树）再退出，不留孤儿进程；
  两个平台行为一致（旧版 Windows 退出会连带杀任务、macOS 不会）。下次启动时，上次未完成的任务显示为“已中断”，可重试（18 A19）。
- **失败证据**：保留任务日志、错误摘要、相关输入与外部工具日志（如 Studio 的请求与 stderr），供排查；成功任务的私有中间文件可以清理。
- **日志保留**：日志、进度文件等有保留上限（旧版无限累积）。

### 13.1.3 进度与界面感知

- 进度结构化：阶段、已完成/总数、百分比、消息；PyMSS Studio 的进度事件（见 14 §14.6）要映射成同一结构并真正显示出来（旧版格式对不上，从不显示）。
- 前端只在任务状态或进度变化时更新（轮询摘要或推送皆可；摘要不能带大结果）；每个任务声明它影响的对象（原片、采样），
  面板按“对象 + 操作类型”判断是否需要刷新；新结果只提示，不自动插入或重排（P8）。

## 13.2 设置

- 存在工作区里；**只作用于之后的操作**（缩放类设置立即作用于已打开的波形）；修改走可撤销编辑通道。
- **默认处理的可配置项**（P13）：02 §2.4 每条默认处理都标了它的可配置项；这些项集中放在设置里，按“它影响哪一步”分组，
  每项旁边用一句话说明默认值会怎样生效（例如“字幕采样前后各多取 0.1 秒”）。
- 完整清单与默认值见 03 §3.7。要点：
  - 推理：ONNX 加速默认关；DirectML 设备号 0；
  - 字幕：采样前/后扩展 **0.1/0.1 秒**【所有者，2026-10-05】；音效整行、注释括号、说话人（提取/拆分/清理）规则；OP/ED 识别词；
  - 语音分析：对齐前/后容差 0.65/0.65 秒；大数字惩罚度 1×；停顿灵敏度 1、语段切分阈值 0.28 秒；
  - 语音分析 · 高级（默认折叠）：量化路线（默认“原节奏 · 无 mora”）、自动长音补格（关）、段间休止调整（关）（所有者：不常用，收起）；
  - PyMSS Studio：安装目录、数据目录、分离设备（自动）、默认人声模型、显示分离进度；
  - 通用：界面语言（当前只有简体中文，国际化预留，15 §15.7）；
  - 原片：首选语言（默认日语）；分离：声部名 → 轨道角色的别名表；拉平：各入口的默认处理范围与定音方式（03 §3.7）；
  - 任务并发：模型 1、轻量 2；
  - 波形：指数缩放曲线、阈值 5；
  - 默认导出目录：空（= 素材库的导出目录，12 §12.6）；导出文件名模板（默认 12 §12.1 的格式）；视频片段格式（默认 H.264 MP4 + AAC）；
  - 空闲时整理可重建缓存：开。
- 全局 BPM 是界面状态（顶栏），持久保存，不在设置弹窗里。
- 所有者当前工作区里的实际值（参考）：字幕采样前后扩展 0.1/0.1 秒（已定为出厂默认）；对齐容差 0.65/0.65；量化 原节奏 · 无 mora；惩罚度 1；
  默认人声模型 `becruily_deux`（但多数集实际用 `bs_roformer_voc_hyperacev2` 分离）；模型并发 2、轻量并发 4；分离设备 auto；ONNX 加速关。

## 13.3 存储

### 13.3.1 程序与工作区分离

- **程序目录**只读；**工作区**可写（数据库、素材库、模型、缓存、日志）。应用更新不覆盖工作区数据。
- 工作区里：素材库（用户可见，英文目录名，见 12 §12.6）、数据目录（数据库、测量、索引、缓存、日志）、模型目录（用户放置的模型权重，见 14）。
  工作区内各目录同样用英文命名。
- 路径全程支持中文、日文、空格、方括号；Windows 要处理长路径。

### 13.3.2 音频的存储形态

| 东西 | 形态 |
|---|---|
| 原片 | 留在原位置，**不复制不转码** |
| 采样 | 只是资产选区引用，没有自己的音频文件 |
| 生成的正式音轨（分离声部、拉平成品） | 共享整轨，**LAME VBR V0**（最高质量档）MP3，存在素材库里；所有者接受有损保存 |
| 外部回导成品 | 复制进素材库，**保持原格式**（无损）【所有者，2026-10-04】 |
| 导出 | 显式格式（PCM 24-bit WAV；视频片段） |
| 模型输入 | 按需解码；能直接读数组的模型直接读选区；必须读文件的模型用带“使用租约”的临时 PCM，用完可回收 |

- MP3 编码要求：采样率是 32/44.1/48 kHz 时保持，否则转 48 kHz；超过 2 声道拒绝；写入无缝播放所需的编码延迟信息（LAME/Xing 头），
  解码后长度要与原 PCM 一致（只允许 MP3 尾部填充，0–1152 帧），否则编码失败并保留原文件；记录编码清单（原内容指纹、帧数、采样率、修剪量）。
- 不宣称 MP3 与原 PCM 逐样本相等；测量结果可以沿用压缩前的（所有者接受），但新测量以实际文件为准。

### 13.3.3 缓存与清理

- **永不当缓存删**：原片；素材库里的正式音轨、导出、REAPER 文件；测量结果（对齐、音高帧、声学指标、音高索引）；数据库；模型与环境。
- **可清理**：播放与可视化缓存（波形峰值、缩略图、频谱）、临时解码音频、派生节奏缓存与**语音检索索引**（随时可由测量重建）、未被引用的处理中间产物。
  注意**音高检索索引**由 F0 测量组成，属于“永不当缓存删”的测量结果。
- **自动整理**（设置“空闲时整理可重建缓存”，默认开）：在**用户空闲 5 分钟以上**（按用户的实际操作计时，不是“没有请求”——界面轮询不能刷新空闲计时）、没有任务运行时，至多每小时一次：
  删除超过 **1 天**的可清理文件；若总量仍超过 **512 MiB 高水位**，从最旧的开始删到 **384 MiB 低水位**以下。
- 正在使用（持有租约）或 15 分钟内生成/修改的文件不删；清理不跟随符号链接；有任务运行时拒绝手动清理。
- **手动清理**：设置里「清理缓存与闲置结果」；同样的保护规则；可以删除未被引用的中间产物。
- “是否被引用”要有准确的口径：既不能把来源记录里的旧路径字符串当成引用（导致永远回收不了），也不能漏掉真正的引用。

### 13.3.4 存储预算

- 目标：约 4k 采样时，日常附带数据约 **4 GB**；不含原片、模型与环境、备份、开发验证副本。
- 设置里的存储面板按类别列出占用、可清理量、引用中/近期生成数量，以及按原片的持久音轨占用。

### 13.3.5 数据完整性

- 数据库操作在事务中进行；文件发布原子化（写临时文件再改名），并发读取者只能看到完整文件；JSON/清单原子写入；数据库连接用完即关。
- 新工作区要支持并发首次初始化。
- **将来的结构迁移**：只在空闲时运行；有日志、可恢复；迁移前做一致性备份；迁移后核对引用、时间映射、来源一致性再删除旧文件；失败可回滚。
  （旧版数据**不需要**迁移到新版；这条是对新版自身演进的要求。）
- 删除数据必须有用户授权（删除确认、清理按钮）；不做静默删除。

## 13.4 运行环境与模型状态

- 设置里「检测环境与模型」：显示运行库是否就位（只代表能加载，不代表推理通过）、每个模型文件是否就位（缺失时列出期望路径）、
  每个模型在当前设备设置下的**实测状态**（未实测 / 实测失败：原因 / 实测通过：加速节点执行数）。三者分开显示（P12）。
- 详细的模型清单、路径、校验见 14。

## 13.5 日志与诊断

- 工作区里保存：服务日志、每个任务的日志、桌面端事件（渲染进程崩溃、无响应）；错误提示里给出相应日志的位置。
- 对外部工具（PyMSS Studio、ffmpeg、Rubber Band）记录版本、命令/请求、设备、输入输出路径和失败摘要。
- 普通使用不写调试文件；调试开关只供开发。
