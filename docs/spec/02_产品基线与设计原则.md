# 02 产品基线与设计原则

> 这是整个交接包里**最需要守住**的一份。
> 所有者对旧版的评价是：实现是屎山、到处是 bug，但**主流程、业务逻辑取舍、页面职责，以及
> “保持处理流程可理解、可编辑，只对主流程做少量克制的例外处理，其余例外交给用户手动修”**
> 是他反复制作后打磨出来的产品基线。
>
> 2026-10-05 所有者又补充了一条：“**让软件每个动作的结果都是可以由用户只靠少部分信息就可以确定的（透明），
> 有默认处理也让用户明确知道功能会怎么生效，而且可以提供关于默认处理方式的用户可配置项**”（P13）。
>
> 新开发者**可以质疑**基线，但改变基线前必须按 §2.7 写清楚具体制作场景、现有问题、预期收益和影响，
> **由所有者确认后**才能改。基线、半基线、自由设计三个层次的划分见 §2.6。

---

## 2.1 产品定位与范围

**是什么**：本地运行的音 MAD 素材工作站。帮助用户在原片里**检索、试听、截取、分离、拉平、卡拍，
并把结果交给 DAW 和视频软件**，全程保留人工审核和来源追溯。

**语言**：当前只做**日语**采样。项目之后会支持**中文和英文**采样，各个流程与日语完全相同【所有者，2026-10-05】；
本轮不实现，但数据模型和分析管线要留好后路（04 §4.9、08 §8.9、14 §14.11）。

**界面语言**：当前界面是简体中文。之后要做**国际化**（界面语言可切换）【所有者，2026-10-05】；本轮只做中文，但界面文案、格式化、错误信息都要按可翻译的方式实现（15 §15.7）。
界面语言与采样语言是两回事：界面可以是英文，采样仍是日语。

**形态**：macOS（Apple Silicon）和 Windows x64 的桌面应用；单窗口工作站，主导航只有
「采样库」「原片」「工具与工作流」三页；可以显式另开窗口，但默认不多窗口。

**输入**：本地视频（主要是 MKV/MP4，HEVC 10-bit + FLAC 很常见）、音频文件、可选的外部字幕（SRT/ASS）。
**字幕不是前置条件**：没有字幕也能完整地导入、播放、分离、截取、拉平、导出。

**输出**：真实音频文件（拖出/导出 WAV）、REAPER 可编辑交接、视频片段（PV 用）、库内采样与标注。

**明确不做**：自动生成音 MAD、自动审美评分或“推荐最好听”、替代 DAW 或视频编辑、插件平台、
多用户/账户/云同步、上传在线服务、通用移调工具、浏览器版。完整清单见 §2.5。

## 2.2 端到端主流程（基线）

三条路径共用同一套概念（原片 → 声音资产 → 选区 → 采样），可以随时互相切换。

```
【路径 1：有字幕，整批准备（所有者最常用的台词路径）】
 原片页                                                         采样库
 ┌──────────────────────────────────────────────────────┐      ┌───────────────────────────────┐
 │ 添加原片(可多选一季)                                    │      │ 筛选 / 音块检索 / 音高检索       │
 │  → 分离音轨（PyMSS Studio，整片人声；可选三轨）          │      │  → 试听：左键原声 / 右键卡拍     │
 │  → 人声/音效与默认轨（指定默认人声轨、音效轨）           │ ───▶ │  → 详情加工：截取/拉平/分离/回导 │
 │  → 导入字幕标记（可分批）→ 从字幕识别 OP/ED             │      │  → 交接：拖出WAV/REAPER/视频片段 │
 │  → 从字幕导入台词语音 / 音效采样（勾选，默认不勾）       │      │ （个别采样也可在这里语音分析）    │
 │  → 语音分析（批量：对齐 + 音高，分析采样绑定的音轨）      │      │                               │
 └──────────────────────────────────────────────────────┘      └───────────────────────────────┘

【路径 2：无字幕 / 音效 / 特殊素材，手动截取】
 原片页：添加原片 → 连续播放（画面+波形+字幕上下文）→ 切参考音源（原混音/人声/音效声部）
        → 选区（拖选、I/O、逐帧、Shift 吸附）→ 截取 / 拉平 / 分离 / 回导 / 导出
        → （可选）在采样上补实际台词文本并分析

【路径 3：在采样库里制作】
 采样库：范围栏（分面、性质、文字、保存筛选器…）∩ 主标签表达式 → 列表试听
        → 详情：在采样波形上再选区 → 截取子采样 / 拉平 / PyMSS 处理 / 回导
        → 拖出 WAV（跟随最近一次成功试听的原声或卡拍版）/ REAPER 交接 / 导出视频片段
```

主流程中**每一步都是用户显式发起的**；任何一步都可以跳过（例如不分离直接在原混音上截取、
不导字幕直接手动截取、不做分析直接拉平整段）。

## 2.3 设计原则

每条原则写：规则、理由、例子、反例（新开发者最容易“好心”做错的方向）。

### P1 人做裁决；明确保存才登记

- **规则**：模型输出不是人工确认；处理结果（分离声部、拉平中间结果、检索命中、试听渲染）不是采样；
  只有用户明确保存才登记为采样。检索不运行模型，也不登记采样。
- **理由**：素材能不能用只能靠耳朵判断。自动登记会把库塞满低质量候选，用户反而找不到东西。
- **例子**：分离完成后结果只出现在参考音源列表和任务结果里，用户逐个试听后点「保存为采样」才入库。
  拉平是例外——它是用户对选区的明确加工动作，只登记最终成品一条。
- **反例**：搜索时顺手批量生成候选采样；导入字幕时自动给每句建采样；分离后自动把人声保存成采样。

### P2 主流程只做少量、克制、可预期的默认处理；其余例外交给用户手动修

- **规则**：只为**最常见的情况**提供一条简单、可解释的默认规则（见 §2.4），并保证每条默认规则出错时
  用户都有**手动修正的入口**。不为少见情况加入复杂的自动例外处理、启发式猜测或向导。
- **理由**：所有者反复制作后发现，自动处理越多，流程越难理解，越容易“只能跑主流程、跑不了灵活场景”；
  而例外情况千变万化，自动处理永远补不完。简单默认 + 手动可修，才能同时保住主流程的效率和灵活场景的可用性。
- **例子**：
  - 字幕说话人：台词行里所有最外层括号的内容都算说话人；字幕写法不同由用户改正则，或事先用大模型洗字幕；
    多人同时说话处理不好就认了（这类采样本来就很少用）。【所有者，2026-10-04】
  - 对齐只用 pydomino 一个模型；对不准时用户拖音素边界、改对齐文本或辞典后重跑，
    而不是换模型“抽奖”。【所有者，2026-10-04】
  - 拉平交界定音：所选一侧证据不足就报错，让用户自己换侧或改手动，不自动换侧。
- **反例**：为某个字幕组的写法写特判；对齐失败自动换模型重试；
  检测到多人说话就尝试切分时间；为 OP/ED 做模糊匹配并自动确认。

### P3 少必经步骤；一次完成；不加向导

- **规则**：每个功能一个入口；能一步完成的不拆成两步；高级参数折叠在 ⓘ、高级区或弹窗里；
  不做新手向导和强制流程。可选准备（字幕、分离、分析）不阻塞其他操作。
- **理由**：所有者逐条批注删掉过重复入口（例如两个“分三轨”入口、多余的“加载整片连续播放”按钮、
  “预览字幕 → 确认导入”两步）。
- **反例**：导入原片后强制走“设置字幕 → 选音轨 → 分离 → 分析”的向导；同一个操作在工具栏、菜单、
  右键里各放一个不同行为的版本。

### P4 统一概念、统一操作

- **规则**：所有声音操作都作用于同一个对象——**资产选区**（某条声音资产上的半开区间）。
  截取（保存）、拉平、导出在原片页、采样详情、检索命中三处是**同一套**操作、同一套弹窗；分离、回导、对齐在原片页和采样详情两处同样如此；
  右键菜单与按钮同源；批量动作在顶部按钮和右键菜单共用。
- **理由**：用户在不同页面切换时不需要学习不同的规则；灵活场景（从命中直接拉平、从原片直接分离选区）
  天然可用，而不是只有主流程能跑。
- **反例**：原片页的截取和采样页的截取用两套逻辑；拉平只能从采样页发起。

### P5 真实音源与来源追溯

- **规则**：播放、试听、处理、分析、导出都使用**用户当前明确选定的**声音资产和区间（默认就是采样绑定的资产；
  用户可以在详情里显式切换音源再加工）。资产缺失或文件变化时报错，**绝不悄悄换成原混音或别的轨**。每个处理产物记录它来自哪个资产的哪段区间、经过什么操作和参数。
  处理后的声音不借用来源的测量结果（例如拉平后的音高不能用原句的音高冒充）。
- **理由**：用户必须确切知道自己听到/导出的是哪个版本；PV 画面要能对上原片时间。
- **反例**：分离轨找不到就播原混音；导出“当前采样”时用了另一条默认轨。

### P6 不静默回退、不静默降级、不静默替换

- **规则**：显式选了 GPU 就不悄悄退回 CPU；分离模型缺失就报错让用户去 PyMSS Studio 下载，不换模型；
  新分析失败不让旧结果顶替成“当前结果”（旧结果保留在历史里）；交界证据不足不换侧；
  原生播放不可用就报错，不退回其他播放方式。
- **理由**：静默替换会让用户误判质量来源，事后也无法复现。
- **反例**：`try: 用 CoreML except: 用 CPU`；分离失败时把原混音当“人声”。

### P7 未知不是零

- **规则**：缺失的测量（音高、能量、起音强度、持续时间、说话人……）是“未知”。带条件的筛选和检索中，
  未知一律**不命中**，不当作 0，也不自动放宽条件；界面上显示“未知”和缺失计数。
- **反例**：没有音高的音块被当作 0 Hz 参与比较；`强度 ≥ 0` 的条件让强度未知的音块也通过。

### P8 显式运行、固定结果、界面稳定

- **规则**：检索只在用户点击时运行。每次检索形成一个**固定结果**（成员、顺序、命中、范围、条件都持久保存，
  重启后恢复时不重搜、不播放）。后台任务完成、索引更新时**只给提示**（如「资料已更新 · 刷新浏览列表」），
  不自动刷新、插入、重排、重选；旧请求的响应不得覆盖用户的新选择。
- **理由**：用户在逐条审听结果，任何自动跳动都会打断判断、丢失位置。
- **反例**：索引准备完自动重跑上次检索；处理完成后自动选中新采样并滚动列表（例外：用户主动截取/回导后
  打开新子采样是预期行为）。

### P9 非破坏、可撤销、不追改

- **规则**：原片文件永不移动、转码、删除；声音资产创建后不可变；删除采样不删除共享资产、字幕、分析、原片；
  资料编辑可预览、原子应用、可撤销；**规则或默认值的变化只作用于之后的操作**，不追改已有记录。
- **反例**：改了字幕正则后自动重新分类所有旧标记；改了默认人声轨后把已有采样换到新轨上。

### P10 规则可配置，不做特判适配

- **规则**：字幕写法、说话人标注方式、音效行判定等因来源而异的东西，由**用户可编辑的规则（正则）**适配，
  提供默认值和试算框；程序内不写针对某个字幕组、某部作品的特殊逻辑。规则覆盖不到的，用户可以改规则、
  在外部（包括用大模型）预先清洗字幕，或事后手动编辑。【所有者，2026-10-04】
- **理由**：“字幕的版本和写法非常多，我们适配不过来；手动适配是用户的事情，不是我们的事情。”

### P11 增强都是可选的，缺了要说明而不是坏掉

- **规则**：字幕、分离、分析、索引都是可选增强。缺少它们时：基本的播放、截取、整段拉平、导出照常可用；
  依赖它们的功能明确提示“需要先准备什么”，提供准备入口，而不是报错崩溃或静默隐藏。
- **例子**：无字幕采样的「音素与分析」页显示缺失原因和「提供台词并分析」入口；音高索引覆盖为 0 时显示准备入口。

### P12 如实呈现

- **规则**：区分“执行成功”和“质量好”、“加速后端可用”和“模型已实测通过”、“自动选择”和“用户指定”、
  “字幕提供”和“人工确认”。计数准确；节奏映射图用同比例时间轴；近似检索要标明可能漏检。
- **反例**：分离任务成功就显示“已验证”；provider 列表里有 CoreML 就显示“CoreML 可用”。

### P13 透明：结果可预期，默认处理看得见、可配置【所有者，2026-10-05】

- **规则**：
  - 每个动作的结果，用户只凭**少量信息**（界面上能看到的选区、音源、几个参数）就能预先确定；不依赖隐藏状态、历史记录或“智能判断”。
  - 每条默认处理（§2.4）都要让用户**明确知道它会怎么生效**：在发起动作的地方用一句话写出将要发生什么
    （例如“将创建 34 个采样，每个比字幕前后各多 0.1 秒，绑定默认人声轨「hyperacev2 · vocals」”），而不是事后才发现。
  - 默认处理的关键参数和开关作为**用户可配置项**放进设置（§2.4 的“可配置项”列），旁边说明默认值如何生效。
- **边界**：可配置项只调整**默认规则的参数或开关**，不引入新的自动例外分支；配置变化同样只作用于之后的操作（P9）。
  配置项要克制——只给真正会因素材或习惯而不同的地方；算法内部常数（09–11 的基线参数）不暴露成设置。
- **理由**：P2 让默认处理少而简单，P13 让这些默认处理对用户透明、能按自己的素材调整，二者合起来才是
  “可理解、可编辑”。
- **例子**：字幕采样的扩展量写在导入弹窗里并可在设置改；OP/ED 的开始/结束标记可在设置改；导出文件名模板可配置并给出预览。
- **反例**：根据素材“自动判断”用哪种规则；把默认值藏在代码里、只有出错时才知道；为每个算法常数都做一个设置项。

## 2.4 主流程内置的默认处理（克制例外处理清单）

这是**全部**被允许的自动/默认行为。新增任何一条自动处理都属于基线变更（§2.7）。
“可配置项”列是 P13 要求的用户可配置项（设置里集中放置，旁边说明默认值如何生效）；标〔新〕的是 2026-10-05 按 P13 新增的配置，
标“—”的没有配置项（属于算法基线或无需配置），出错时靠最后一列的手动入口修。

| # | 默认处理 | 作用于 | 刻意不做 | 可配置项 | 出错时用户怎么改 |
|---|---|---|---|---|---|
| 1 | 字幕行分类：整行只有括号 → 音效；括号外有文字 → 台词（可编辑正则） | 字幕标记导入 | 改规则不追改旧记录 | 音效整行正则（含试算框） | 改正则、预清洗字幕、编辑标注 |
| 2 | 自动对齐文本移除行内所有最外层括号（含嵌套读音） | 对齐文本 | 不判断哪个括号该保留 | 注释括号正则 | 编辑对齐文本、用户辞典 |
| 3 | 说话人 = 台词行内所有最外层括号内容（可编辑正则）；一人记“角色”，多人记“参与者”并加 `speaker-status:多人未分段` | 字幕标记导入 | 不推断多人各自时间；不内置拆名/去读音特判 | 说话人提取/拆分/清理正则 | 改正则、预清洗、编辑区段标签 |
| 4 | OP/ED：字幕里独立的 `♪～`/`～♪` 成对；两对依次为 OP/ED，一对按前后半片判断 | 用户点「从字幕识别 OP/ED」 | 孤立/重复/超过两对只报告；不模糊匹配；没有参考帧扫描【所有者，2026-10-05 去掉】 | 开始/结束标记词〔新〕 | 结果里逐对确认、手动标记、删除 |
