# 01 音 MAD 制作背景与方法论

> 读者：没做过音 MAD、或只知道术语的新开发者。
> 目的：让你知道**这个工具在制作链条里替人省掉哪一段劳动**、所有者**实际怎么用它**、
> 以及**为什么流程被组织成现在这样**。后面所有规格都以这里的制作场景为依据。
>
> 证据等级：标【所有者】的是所有者本人在 2026-10-03/04 访谈或历史需求里明确说过的；
> 标【推断】的是根据功能和使用记录推出来的，若与所有者说法冲突以所有者为准。

---

## 1.1 音 MAD 是什么

音 MAD（日：音 MAD / 音ＭＡＤ，中文圈也常归入“鬼畜”）是一种同人视频：把动画、游戏、影视里的
**台词、喊声、音效**切成很短的素材，经过**移调、拉平、变速、卡拍**之后，在 DAW 里编排成一首完整的乐曲，
再把每个声音对应的**原片画面**按同样的时间排布成视频（PV）。

几个要点：

- **素材来自原片**。乐器、鼓组、人声旋律、说唱段全部（或大部分）由原片里的声音构成。
- **制作的大头是“找素材”**。一首歌可能需要几百个合适的片段：节奏合适的台词、音高稳的长音、
  脆的撞击声、能拼出歌词的音节……要在几十集里翻找、试听、比较。
- **好不好用只能靠耳朵判断**。语气、情绪、音色、能不能接上拍子，都没有可靠的自动评分。
- **声音和画面绑定**。观众看到的是“角色说出/唱出这个音”的画面，所以每个声音素材都要能追溯回原片的
  准确时间和画面。

**这个工具不做的事**：不自动生成音 MAD，不替代 DAW（编排、混音在 REAPER 里），不替代视频编辑软件（PV 在 AE 等软件里剪）。

## 1.2 工具在制作链条中的位置

```
 选曲/扒谱          素材准备（本工具）                        编排混音            PV 剪辑
(外部，BPM/旋律) → 导入原片 → 准备音轨/字幕 → 找/听/切/修 → 交接 → REAPER(DAW) → AE 等视频软件
                    │                         │            │
                    └── 原片为根：任何素材都能回到原片看上下文和画面 ──┘
```

本工具负责中间这一段：**导入原片 → 准备（分离、字幕标记、分析）→ 检索 → 试听判断 → 截取与加工
（拉平、卡拍、分离、回导）→ 交接（拖出 WAV、REAPER 交接、导出视频片段）**，并且全程保留来源追溯。

## 1.3 所有者与使用方式

- 主要开发/使用机器是 Apple Silicon Mac，也要求 Windows x64 可用（1920×1080）。DAW 是 REAPER。【所有者】
- 一次制作的节奏【所有者，2026-10-04】：
  - **有字幕的番剧**：以“整批准备”为主——导入一季原片，整轨分离人声，导入字幕标记，批量建台词采样，
    批量做语音分析，然后主要在采样库里检索、试听。
  - **没有字幕的素材**：只能“边看边截”，在原片页看画面和波形手动截取。
  - **音效和特殊素材**（撞击、呼吸、尖叫、乐器声等）：基本都在原片页手动截。
- 四类制作都常用：Rap/念白卡拍、调音单音（拉平）、人力/拼词唱词、鼓组/音效；
  并且**任意采样对应的画面都要能导出**，供视频软件做 PV。【所有者，2026-10-04】
- 交接方式：拖出 WAV 和 REAPER 交接（未烘焙原声 + 可编辑拉伸标记）**都常用**。【所有者】
- 实际使用证据（旧工作区）：
  - 拉平做过 72 次，对象多是喊叫和拖长音（如「ウワーッ」「歳納京子！」），目标音在 G3–A♯5，
    相对原音高的偏移都在 ±0.5 半音内——即“去掉起伏、吸附最近半音”，不是大幅移调。
  - 常用查询【所有者原始需求】：“`BPM 180 / x-xx / 到句末 / 无音块限制`，音块常用时长与音高”。
    （x-xx 的读法是交接人的【推断】：x 表示有起音的格，- 表示空格。）
  - 会给角色标签筛选、给固定结果加星标、做 `0.20 A4` 这类单音高查询。
  - 用户辞典里登记过 `歳納 → トシノウ`（人名读音被 G2P 读错时的修正）。

## 1.4 代表性制作场景（逐步）

每个场景写四件事：**目标**、**在工具里怎么做**、**哪些判断必须由人做**、**这样设计的理由**。
它们是后续页面职责与功能规格的依据；新开发者设计任何流程时都应能回答“它服务于哪个场景的哪一步”。

### 场景 A：Rap / 念白卡拍（性质：语音）

**目标**：歌曲某段需要角色“说”一句话卡在拍子上。理想素材是**自然语速下音节节奏本身就接近目标节奏型**的台词，
这样只需整体变速（甚至不变速）就能卡上拍，语气和情绪保持自然。

**在工具里怎么做**

1. 准备（一次性，有字幕时整批做）：导入原片 → 用 PyMSS Studio 整轨分离人声，设为该原片的默认人声轨 →
   导入字幕标记 → 从字幕批量建台词采样 → 批量语音分析（文本前端 + pydomino 对齐 + 音高测量）。
2. 在顶栏填目标 BPM（如 180）。
3. 采样库切到「语音 · 音块检索」，在钢琴卷帘上画目标节奏型（如 x-xx），可加首尾条件（如“到句末”）
   和逐音条件（元音、音高、时值……），选策略：**必须满足节奏**（严格）或**按节奏相似度排序**。
4. 点「查找」得到一个固定结果标签。逐条试听：**左键听原声，右键听卡拍版**。
5. 合适的：保存命中为采样；或直接 Option/Alt 拖出卡拍 WAV 到 REAPER；或「复制 REAPER 交接」，
   在 REAPER 里粘贴得到未烘焙的原声 + 拉伸标记，继续手工微调。

**必须由人判断**：语气、情绪、咬字清晰度、卡拍后是否自然。严格命中 ≠ 好听。

**设计理由**

- **台词没有唯一 BPM**：同一句话在不同网格密度（每拍 2^k 格）下都可能成立，所以只在检索时按目标 BPM
  选出离原速最近的两个候选（“近快”= 播放速度 ≥1 的最慢密度，“近慢”= 再慢一档），按综合分取优。
- **大幅变速伤音色和语气**：排序时用“原速偏好”惩罚偏离 1× 的程度（对加速和减速对称）；可选硬性倍速范围。
- **检索与卡拍是两件事**：检索衡量“原节奏与目标节奏的适配度”；卡拍是独立的后处理
  （保护每个起音附近的原声，只拉伸起音之间的部分并保持音高）。
- **局部细修交给 DAW**：工具不做局部自动拉伸修正；需要精修时用 REAPER 交接里的可编辑拉伸标记。

### 场景 B：调音单音 / 音合わせ（性质：调谐单音）

**目标**：旋律声部要让角色“唱”某个音。做法是取一个音节（多为元音长音、喊叫、拖长音），
先**拉平**——去掉说话时自然的音高起伏、保留音色/辅音/时长，得到稳定单一音高的“调谐单音”，
再在 DAW 里按旋律移调使用。原句不拉平直接移调会有明显“跑调感”。

**在工具里怎么做**

1. 找素材：独立音高检索（如在查询画布上放一个 0.40 秒的 A4 音高块，找自然音高已接近目标的片段，减少移调失真）；
   或语音检索按元音、音高稳定度、时值找长元音；或在**采样详情**波形上看叠加的音高（F0）线找平稳段（原片页波形不画 F0）。
2. 在波形上选区（Shift 吸附音素边界）。
3. 打开「拉平」弹窗：
   - 处理范围：**整段** / **从首个元音起**（保留开头辅音的自然起音）/ **内部拉平**（首尾保留原样，便于衔接）；
   - 目标音高：**段内自动**（可靠帧的置信加权中位数，吸附最近半音，移调最小）/
     **交界自动**（以左侧或右侧边界向内 100 ms 的音高为准，让拉平段与保留段衔接自然）/ **手动指定音名**。
4. 成品自动登记为「调谐单音」采样，带 `pitch:音名` 标签；拖出到 REAPER。

**必须由人判断**：音色是否适合、拉平后是否有伪音、选哪一侧作交界参考。

**设计理由**

- **只拉平，不做通用变调器**【所有者】：移调在 DAW 里做；工具只负责“去起伏”。允许显式指定目标音名，但默认吸附最近半音。
- **证据不足就报错，不自动换侧/换方法**：交界一侧没有足够可靠的音高时提示用户换侧或改用段内/手动，绝不悄悄换。
- **名称不加音名后缀**：音高用标签表达，名称保持台词内容。

### 场景 C：人力 / 拼词唱词（性质：语音 → 常再拉平）

**目标**：用角色台词里的音节拼出歌词，让角色“唱”出一句词（人力 VOCALOID 式）。需要按音节找素材：
特定辅音 + 元音（如「か」= k + a）、合适的音高与时值，常要连续两三个音节一起找。【所有者确认此场景常用；具体步骤为推断】

**在工具里怎么做**

1. 「语音 · 音块检索」里用逐音条件：前导辅音序列、首元音、目标音高（音名/八度/音分容差）、
   音高稳定度、原声时值等；多个**相邻、有序**的音块可一次检索（如连续的「か」「な」）。
2. 命中后定位到采样，在波形上 Shift 吸附音素边界截取，必要时拉平，再到 DAW 拼接。

**设计理由**

- 音素、mora（文字拍）、音块（听感上的一个起音）是**不同概念**，检索按音块、截取按音素边界。
- 只匹配**相邻有序**的音块，中间夹着不合格的音块就不算命中；**测量缺失就不算命中**（未知 ≠ 0）。
- 对齐精度直接决定可用性，所以**人工修正音素边界**必须顺手（见 08）。

### 场景 D：鼓组 / 音效（性质：非调谐单音）

**目标**：用剧中的撞击、脚步、关门、拍手、尖叫等短促声音充当打击乐（底鼓/军鼓/镲……）。
这类素材往往需要**保留背景或在音效轨里找**，人声分离反而有害。【所有者：基本只能在原片页手动截】

**在工具里怎么做**

1. 原片页把「参考音源」切到音效类轨道（三轨分离的音效声部，或人声模型输出的伴奏/残差声部），
   看画面 + 波形定位撞击 → 截取。在音效角色轨上截取时，性质自动预填为「非调谐单音」（可改）。
2. 有字幕时，括号音效行（如「（殴る音）」）可以一次批量登记为音效采样（时间是粗边界，需要人听着修）。
3. 采样库「单音 · 瞬态」模式按起音时间、衰减时间、峰均比、频段占比等指标筛选。

**设计理由**：音效不继承说话人标签；性质只按明确的轨道角色预填，冲突或未知就是「未分类」，不靠文件名或音高猜。

### 场景 E：PV 画面（任意采样）

**目标**：视频里每个声音都配上它在原片里的画面（口型、动作），在 AE 等软件里按音频排布。
【所有者，2026-10-04】**任意采样对应的画面都要能导出成实际视频片段**，供视频软件直接使用。

**在工具里怎么做**

- 每个采样都有“画面”：默认是原片视频的同步画面（按采样到原片的时间映射取帧）；也可以绑定静态图片或
  独立循环动画（用于没有画面的素材）。
- 导出视频片段时：原声版按原速取画面；**卡拍版两种都提供**——画面按同一条时间映射变速（音画同步，可直接用），
  或只导原速画面（变速在视频软件里自己做）。

**设计理由**：音频是唯一主时钟，画面跟随；声音素材必须能追溯到原片准确时间，否则 PV 对不上口型。

### 场景 F：无字幕原片的手动截取

1. 导入原片（不需要字幕）→ 原片页连续播放整集（画面 + 波形）。
2. 找到片段 → 拖选区（可按 I/O 设点、方向键逐帧、Shift+方向键按 1 ms 微调）→ 截取 / 拉平 / 分离 / 导出。
3. 需要节奏相关功能时，对该采样手动提供实际朗读的台词文本，再做语音分析。
   音高检索、整段拉平、拖出、分离都**不需要**文字。

### 场景 G：外部处理回导 / 独立音频导入

- **回导**：在 DAW 或其他工具里对某个选区做了处理（降噪、手修、混响……），再导回库里挂到原位置：
  **只看选区起点**，终点 = 起点 + 文件时长，必须落在当前声音资产范围内；沿用原时间映射，不补静音、不裁切、
  不变速、不推断成品内部的剪辑。回导文件**复制进素材库并保持原格式**【所有者，2026-10-04】。
- **独立导入**：不来自原片的外部音频可以直接导入为采样（性质导入时选择，不靠文件名推断）。

## 1.5 方法论要点：为什么流程被组织成这样

1. **找素材最耗时，工具的价值是“缩小范围 + 快速试听 + 不丢上下文”**。
   衡量标准是“找到可用素材需要多少时间和试听次数”，不是某个自动评分。【所有者原始需求】
2. **人耳是最终裁判**。模型（分离、对齐、音高）只用来缩小范围和加工；模型输出不是人工确认，
   处理结果也不自动成为采样——**明确保存才登记**。
3. **原片为根，来源可追溯**。任何采样都能回到原片看画面、看前后台词；知道自己用的是哪条音轨、经过了哪些处理。
   这让“重做”成为可能，也让 PV 画面能对上。
4. **准备一次，全季复用**。有字幕时一次性整轨分离人声、导入标记、批量分析；之后的检索不再跑模型，
   搜索结果几秒内返回。
5. **采样只是“对某条音轨某段区间的引用”**，截取不复制音频；需要真实文件时（拖出、导出）才生成。
   所以截取可以随手做、随手删，不会把磁盘塞满。
6. **两条检索路线对应两种需求**：节奏路线（音块检索）服务说唱/人力，音高路线（音高检索）服务旋律/调音。
   单音的音色/瞬态筛选服务调音素材和鼓组。
7. **主流程只做少量、可预期的默认处理，其余例外交给人手动修**（这是所有者最强调的取舍，详见 02）。
   例如：字幕括号按一条可编辑的正则处理，写法不同就改正则或事先清洗字幕，程序里不做特判；
   对齐错了就拖边界或改文本重跑，而不是换模型“抽奖”。
8. **默认值服务最常见的情况，且改默认值不追改已有记录**。如字幕采样前后各扩 0.1 秒、对齐容差各 0.65 秒、
   拉平吸附最近半音、交界取左侧。
   默认处理还要**透明、可配置**【所有者，2026-10-05】：用户只凭少量信息就能预先知道一个动作的结果；默认处理在发起处写明会怎么生效，
   关键参数可以在设置里改（02 P13）。
9. **结果是固定的快照**。每次检索形成固定结果，逐条审听时不会因为后台任务完成而重排、刷新或跳走。
10. **先圈范围，再灵活检索**【所有者，2026-10-05】。很多时候要先把范围限定在某部剧或某个角色的采样上，再在里面反复换检索条件。
   所以范围先在范围栏上筛好（作品、人物等分面和保存筛选器；旧版是保存筛选器和单标签范围），主标签表达式只写这次真正要找的东西，不必常驻挂着两三个标签（07 §7.3）。
11. **语言不是流程的一部分**。现在只做日语采样；之后会支持中文和英文采样，字幕 → 采样 → 分析 → 检索/卡拍 → 拉平/导出的流程完全相同，
   只有文本前端、对齐模型这类“语言配置”不同（08 §8.9）。

## 1.6 制作术语表（含易混点）

| 术语 | 含义 | 易混点 |
|---|---|---|
| 原片 | 导入的原始视频或音频文件（一集番剧、一段视频、一首歌……），留在原位置，不复制不转码 | 不是“采样”；没有字幕也是完整的原片 |
| 声音资产 | 属于某个原片的一段可播放声音：原片自带音轨、分离出的声部、拉平成品、回导成品…… | 资产不可变；处理总是产生新资产 |
| 采样 | 用户明确保存的“某个声音资产上的一段区间” + 名称、性质、标签等 | 截取不复制音频；导出文件不是采样 |
| 性质 | 采样的用途分类：**语音**（台词，用于说唱/人力）、**调谐单音**（有稳定音高，用于旋律）、**非调谐单音**（打击/音效）、**未分类** | 是筛选属性，不是文件夹；不从父采样继承 |
| 人声 / 音效（轨道角色） | 原片里被指定为“对白”或“音效”用途的整轨；每个角色可指定一条**默认轨**，供之后的字幕采样使用 | “角色”还指剧中人物，两者不同 |
| 字幕标记 | 导入的字幕行，只是时间轴上的标记，**不是采样** | 字幕时间约有 ±0.5 秒误差，不能当测量边界 |
| 说话人 / 参与者 | 字幕括号里给出的人物名，投影成区段标签；一行一人记“角色”，多人记“参与者”且不推断各自时间 | 字幕写法千差万别，靠可编辑正则适配 |
| 区段标签 | 绑定在原片/某组音轨/某条资产的时间区间上的标签，采样按时间交叠动态继承 | 端点相接不算交叠 |
| 音素 | 对齐模型输出的最小发音单位（a、k、N、cl……）及其时间 | 只能改时间，不能增删改标签 |
| mora | 日语文字拍（片假名一拍），来自文本，不是时间测量 | 不能把 mora 均分成伪时间 |
| 音块（节奏单元） | 听感上的“一个起音”：连续元音（间隔 ≤35 ms）加其后附着的 N 合成一块；辅音、停顿会打断 | 不是 mora，也不是音素；可人工拆开 |
| 音块（查询） | 检索时画在节奏卷帘上的块：左沿要求一个起音，块内不允许出现别的起音 | 块长不是发声时长；“块内无新起音”不等于静音 |
| 占格 | 一个音块从起音到下一个起音占多少个整数网格 | 可人工锁定 |
| BPM / 网格密度 | 目标曲速；每拍 2^k 格（“二进制”指 2 的幂次细分，没有三连音） | 台词没有唯一 BPM |
| 卡拍 | 把每个音块起音放到 BPM 网格上：起音附近原声逐样本保留，中间部分保持音高地伸缩 | 严格卡拍保证“标记落位”，不保证标记本身准确 |
| 原速卡拍 | 没填 BPM 时的卡拍：保持 1× 语音速度，只做量化对齐 | 只用于试听 |
| 近快 / 近慢 | 同一节奏骨架下，播放速度 ≥1 的最慢密度 / 再慢一档；检索只比较这两个 | 相对的是原速，不是相对查询 |
| 原速偏好 | 排序代价 = 权重 × \|log2(播放速度)\|，0–1，界面默认 0.1 | 对加速与减速对称惩罚 |
| 大数字惩罚 | 推断占格时惩罚过大的格数，避免用极细网格“解释一切”；0–3 倍，默认 1 倍 = 0.045 | 只作用于“原节奏 · 无 mora”路线 |
| 拉平 | 把一段声音的音高轨迹压成恒定目标音高，保留音色、辅音、时长 | 不是移调工具 |
| 首元音起拉平 | 从第一个有效元音（含拨音 N）处理到选区末尾，之前的辅音原样保留 | 没有匹配的对齐结果就拒绝 |
| 交界定音 | 以选区左/右边界向内 100 ms 的可靠音高为目标 | 证据不足不换侧 |
| 音高波动范围 | 可靠帧音高的 P90−P10（中间 80% 跨度），单位音分，100 音分 = 1 半音 | — |
| OP/ED | 每集重复的片头/片尾曲区间：只排除自动登记和批量分析，不禁止手动播放、截取、分离 | — |
| 拖出 | 按住 Option（macOS）/ Alt（Windows）左键拖动，把当前声音生成真实 WAV 拖进 DAW | 越过拖动阈值才生成，不预渲染 |
| REAPER 交接 | 复制到剪贴板的 REAPER 条目：未烘焙原声 + 卡拍拉伸标记，粘贴后可在 REAPER 里继续改 | 和拖出“卡拍 WAV”（已烘焙）是两件事 |
