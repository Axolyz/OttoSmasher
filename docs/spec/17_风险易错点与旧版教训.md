# 17 风险、易错点与旧版教训

> 旧版在三周左右的高速迭代里反复踩过同几类坑。新版不需要兼容旧版，但**同样的坑会再出现**。
> 这里按“bug 类别 → 好心办坏事 → 算法细节 → 旧版具体问题 → 验证纪律”列出。
> 注意：算法与参数是**基线**（所有者 2026-10-05），本文件列的是“实现时容易做错的地方”，不是“可以顺手改进的地方”；想改的先写成提议，等所有者确认。

---

## 17.1 反复出现的 bug 类别（设计时就要防）

1. **时间坐标混淆**：原片秒、资产局部秒、文件秒、采样显示坐标、播放器源时间、采样帧——旧版多次把共享整轨当成已裁切的短音频、重复叠加偏移、
   把查询画布尾部的静音带进试听。→ 每个时间值都要明确它属于哪个时钟；换算只走映射一处。
2. **静默替换/回退**：缺分离轨就播混音、GPU 失败退回 CPU、对齐失败换模型、新失败让旧成功“顶上”、原生播放失败退回网页播放、挂外部声部时原音轨漏音。
3. **旧响应覆盖新选择**：快速切换采样/音源时，慢的旧请求结果覆盖了新的；首次选择要点两次才加载。→ 请求带代次，过期结果丢弃。
4. **后台任务引发全局刷新、重排、自动重搜**；任务轮询过重（一次 10 MB）。→ 只广播变化、按对象失效、只提示不刷新。
5. **迁移遗漏和路径陈旧**：搬家时漏了拉平成品的测量侧车（用户发现“调谐单音音高消失”）；来源记录指向已删除的临时文件。
6. **跨资产借用测量**：处理后的声音借用来源的音高；切换音源后显示原音源的音素。
7. **方案/分析身份过期**：改了分组后，按编号保存的拆点/占格错位；改 BPM 后命中还挂着旧方案。→ 派生物都带上游版本，过期就拒绝并重算。
8. **把未知当零、先过滤后拼接**（相邻检索变成跳着拼）。
9. **静音误判**：把模型空白、无音高、低能量、促音闭塞当静音，导致重复计时或删掉弱辅音和呼吸。
10. **对齐伪影**：发射峰当边界导致尾音被裁、同一元音中间出现伪空档、零长度词、小于 20 ms 的音素、分词吞掉「ー」。
11. **字幕文本清洗**：嵌套括号注释漏进对齐文本（旧版到最后一个提交才修好）、名字里的读音括号、样式标记残留、符号被读出来。
12. **选择与计数**：浏览焦点被当成批量选择；标签影响数重复计数；导入候选不能跨页选择；工具栏显示的是本页数而非总数。
13. **重复入口/残留入口**：同一功能多个入口、删掉的功能还留着按钮。
14. **原生播放器生命周期与层级**：字幕被遮挡、原生视图盖住弹窗、暂停时逐帧 seek 引发读盘风暴、清理回调导致白屏、挂波形时播放头被重置、切页后还在出声。
15. **可视化失真**：两条各自归一化铺满的映射图（1.576× 变速看不出压缩）；对峰值数据做 FFT 冒充频谱。
16. **新旧版本错配**：后端服务没随代码更新，用新前端配旧后端验证。
17. **性能**：检索曾要 5 分钟；逐句起进程（352 句约 224 分钟）；每次选择都全库计算标签。
18. **夸大结论**：把“运行成功”“provider 列表里有”“零误差”“清单字节数”当成质量、实测或真实释放量。
19. **跨平台**：中文路径、子进程编码、DLL 重定位、CoreML MLProgram 编译失败、Windows 进程探活、符号链接权限、长路径。
20. **资源泄漏**：数据库连接累积；并发生成同一文件时读到半成品；内部技术对象（原片浏览用的隐藏采样）泄漏进用户视图；角色轨列出逐句资产。

## 17.2 “好心办坏事”清单（基线明确不要）

1. 先把算法做漂亮，迟迟不交付基本闭环（导入 → 播放 → 截取 → 试听 → 拖出）。上一轮重写就犯过这个错。
2. 加回已删除的东西：多窗口、文件夹/集合/版本槽位/偏好版本、候选审核状态机、插件平台、声音发现、角色聚类、浏览器版、CLI、双版本。
3. 好心回退（混音、CPU、旧结果、备用模型）和好心修正（尾音裁短、空格当停顿、能量补音、证据不足换侧、推断多人时段、自动选更响的轨、OP/ED 模糊匹配后自动确认）。
4. 为某种字幕写法写特判（P10：用户改正则或预清洗字幕）。
5. 好心刷新、重搜、重排、自动选中、预渲染拖出文件、检索时顺手跑模型或建采样。
6. 字幕导入走两个极端：恢复强制预览关卡，或者导入时直接给每句建采样；用导入历史/删除记录阻拦用户的显式重建。
7. 术语误读：两种“音块”（源节奏单元 vs 查询块）；“块内无新起音” ≠ 静音；块长 ≠ 发声时长；“首尾”指节奏起音；mora 不是时间戳；
   “二进制”是 2 的幂；时长比与播放速度互为倒数（混用会把上下限弄反）；近快/近慢相对原速；“无 mora”不等于不用音素；
   音块合并与 G2P 的“重复元音不合并”是两层；“角色”有轨道角色和剧中人物两种意思。
8. 把拉平做成移调器，或自动给名称加音名。默认吸附最近半音（不是“严格保持原音高”）。
9. 把严格命中/零误差当成好听。卡拍只保证当前标记落位。
10. 把测量结果、整集分离、正式音轨当缓存删；以为存储预算包含原片。
11. 给重新定位加内容校验或移动文件；以为删除登记会删除磁盘文件。
12. 照旧版去掉常驻复选框（最终版本恢复了常驻复选框，但浏览焦点仍不算选择）。
13. 把 OP/ED 当成“禁止区”，禁止在里面手动取样。
14. 把“不维持兼容层”理解成可以不可恢复地迁移（新版自身的迁移仍须可恢复、可核对）。
15. 自动下载模型、替 Studio 装依赖、上传在线服务。
16. 在选区变化时预渲染拖出文件、加拖拽把手；REAPER 交接用烘焙后的 WAV 代替；回导要求等长。

## 17.3 容易做错的算法与接入细节

> 下表的数值都属于基线（照旧版复现，含所有者 2026-10-05 确认的几处修改：19 的 G1–G4、K1–K3），不是“参考值”。

| # | 细节 | 为什么重要 |
|---|---|---|
| 1 | 音块只合并间隔在 [−1, 35] ms 的连续元音，N 只向后附着，所有非元音标签都打断 | 单元一错，量化、检索、卡拍全偏 |
| 2 | 时值 = 起音间隔 − 停顿（至少 5 ms），末块终点规则特殊 | 直接决定占格 |
| 3 | 停顿只看能量（85 百分位 × 0.25 × 灵敏度，≥120 ms，两侧内缩 20 ms，排除促音） | 不能把模型空白或无 F0 当静音 |
| 4 | 大数字惩罚只作用于原节奏路线；mora 参考校准固定 0.045；漂移项除以 √步数；**停顿段**变化或前一块有休止时重置累计 | 参数套错三条路线结果混淆 |
| 5 | 近快/近慢按真实映射算出的语速判定，密度可以是任意 2^k，“必须满足节奏”路径也一样（旧版那条路径只收 1/2/4/8，是缺陷，K1） | 起音保护会改变实际速度 |
| 6 | 原速偏好用 log2，对称；同分取近快；不要把速度惩罚算两次 | 排序翻转 |
| 7 | 最大间隔 = 下一元音锚点 − 上一块结束 | 前导辅音可能吞掉静音 |
| 8 | 未知不等于零：强度、持续、音高、角色、覆盖率缺失都不命中，强度 ≥0 也不例外 | 硬性要求 |
| 9 | 只给音级用圆周距离，给八度用绝对距离（C4 = 60） | 差一个八度会错判 |
| 10 | 音高检索的覆盖率分母含不可靠帧；缺口按整个查询窗算；可靠门槛 0.5 不可调 | 命中集合 |
| 11 | 音高检索只合并“允许起点”区间，不合并声音区间 | 否则拼出跨采样命中 |
| 12 | 拉平目标 = 置信加权中位数 → floor(x + 0.5)；交界向内 100 ms；证据不足不换侧；手动值是音名或带单位的 Hz | 错一个半音就毁掉成品 |
| 13 | 拉平只在区间内有声帧替换 F0，无声帧置 0；3 ms 波形淡化与 F0 过渡是两回事；区间外样本原样复制；时长必须不变 | 可追溯性的前提 |
| 14 | G2P 逐码位替换保持字符位置；mora 映射三方计数相等才成立 | 词与 mora 定位依赖它 |
| 15 | 重跑的采纳顺序：取消检查 → 输入一致性 → 当前头版本 → 人工版本保护 | 违反任一条就会覆盖旧结果或人工版本 |
| 16 | Studio：独立子进程、剥离 PYTHONPATH/PYTHONHOME、强制不下载、stdout 按 UTF-8 解码、任何 error 事件都算失败 | Windows 编码与“部分失败仍退出 0” |
| 17 | Studio 声部名大小写不一（`Vocals` 与 `vocals`）：保留原样，能力判断时比较小写 | 声部识别 |
| 18 | 分离/拉平/编码后都要核对长度并传递映射；采样率可能变化，按时长和帧数分别校验；禁止补静音或裁切 | 时间对不上 |
| 19 | MP3 依赖 LAME/Xing 头做无缝解码；随机读要预滚；拒绝 >2 声道；非常规采样率转 48 kHz；编码失败保留原文件 | 导出首样本错位 |
| 20 | 缓存“是否被引用”的口径要准：来源记录里的旧路径不算引用；正在使用的临时 PCM 要有租约；空闲判断不能被界面轮询刷新 | 旧版自动清理几乎从不触发，长任务的输入却可能被删 |
| 21 | 进程树取消跨平台（POSIX 进程组 / Windows 作业对象）；不要用 `kill(pid, 0)` 在 Windows 探活 | 误杀或漏杀 |
| 22 | “停顿段”（任一停顿切分）和“语段”（≥0.28 秒停顿切分）是两个概念：检索邻接、首尾判断、相对音高/响度、占格累计重置用停顿段；检索范围、按语段量化、段间休止用语段 | 旧版两者都叫“连续语段”，混用会让检索默认跨过短停顿 |
| 23 | 帧口径：语音检索的音高类条件（含走势、停顿段内相对音高）、覆盖、波动、拉平定音都用可靠帧（≥0.5）；宽口径的有声帧（>0.05 且有能量）只用于拉平重合成的有声掩码和显示 | 混用会改变检索结果或拉平音质 |
| 24 | 对齐只送本句；目标 = 采样选区、窗口 = 目标 ± 容差，所有入口一致；输入未变就跳过 | 与参考输出对比时窗口要一致 |
| 25 | 前导辅音从块首向前取，遇停顿、AP、spn、N、促音 cl、元音停止（cl 不计入） | 辅音条件的命中集合 |

## 17.4 旧版具体问题（新版不要复制）

按领域摘要（细节散见各规格的“旧版是 bug”注释）：

- **原片页**：截取/分离/拉平不同级、波形无右键菜单；切换音源把选区重置为整片；画面焦点下快捷键被处理两次；导出选区时偷偷建采样；
  “导出选区视频”其实导出 JSON；截取弹窗缺“未分类”；纯音频原片显示空白画面；三轨分离后参考音源列表不刷新；批量导入字幕标记时一部没字幕全体失败。
- **采样库**：批量拉平结果进入看不见的待审核批次；快捷编辑绕过撤销；存在屏蔽层与按采样显示的“派生继承”开关（实际改的是全局规则）；
  卡拍导出要求先打开节奏页；右键空白处沿用上一次的行；↑/↓ 选到已删除行；标红数字框误拦无关请求；缩略图不随画面绑定更新；持久化页码被清零。
- **字幕**：新导入与迁移数据用了两套不同的说话人规则——问题是**两套规则并存**。（“句中读音被当成说话人”在新默认规则下是所有者接受的代价，D11，不要加特判。）
  字幕采样的扩展部分让采样继承了相邻句的说话人（327 条中 6 条）；样式标记残留在对齐文本里；命名用原文（带说话人括号和读音）。
- **对齐**：多处默认模型与设置不一致；单条重跑与批量的派生结果不一致（少了覆盖估计和起音强度）；HubertFA 的促音被当成休止（新版已不用 HubertFA）。
- **检索**：严格证据的“平均偏差”显示的其实是代价（字段名写错，已定修正 A27）；必须满足节奏模式会静默丢掉某些密度的候选；命中试听总用近快，与排序证据可能不一致——
  三条都已定修正（19 K1–K3）；声学指标的音高类对没有对齐的采样恒为未知（已定修正，A16）。
- **拉平**：手动目标提示写 Hz、后端当 MIDI；拉平文件名里漏进了程序内部数据。
- **Studio 与任务**：Studio 进度格式对不上从不显示；CUDA 设备号没传；三轨路径忽略设备设置；硬编码默认人声模型导致“补齐分析”不用用户设置；
  中断的任务界面不能重试；任务列表显示内部英文名；Windows 退出会杀任务而 macOS 不会；`os.kill(pid, 0)` 在 Windows 上不是探活。
- **存储**：清理说明文字与实际策略不一致；自动清理几乎不触发；生成的 WAV 母带回收不掉；长分离任务的输入 PCM 可能被并发清理删掉；
  用户可见目录里残留大量零字节锁文件；日志/探测文件无限累积。
- **删除与身份**：原片删除在旧版后期的数据模型下必然失败（资产被设计成不可删除）；重新定位后 OP/ED 区间失效（指纹含路径）；四种不同的“指纹”定义；
  ID 由路径/内容派生导致重新定位后要反查最初路径。
- **错误呈现**：原生错误事件没有任何监听者，拖出失败等被静默吞掉。

## 17.5 验证纪律（所有者的工作规则）

- 优先用单元测试、接口测试和构建检查验证行为；界面自动化/人工点击只补充自动化证明不了的问题。**不要在用户正在使用的应用上操作。**
- 用真实素材小批验证（fixtures），补充合成测试；**不全库重跑模型**，不每次重复完整的 REAPER 验收。
- 界面改动只验证受影响的一个代表流程；布局改动才补目标缩放；原生播放改动才补对应硬件检查。
- 一轮足够的验证通过后就停止重复点击；所有者说停止点击时立即停止——**点击次数多不等于更可信**。
- 没有实测证据，不宣称功能可用或音质领先；“运行成功”“provider 可用”不是质量结论；Windows DirectML、Windows 拖放/粘贴在实测前标为未验收。
- 只验收桌面原生版。
- 删除或迁移用户数据必须有对应授权。
