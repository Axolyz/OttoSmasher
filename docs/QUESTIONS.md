## 一、需要所有者决定的事（影响阶段 1–2）

| # | 问题 | 我的建议 |
|---|---|---|
| Q1 | **Windows x64 怎么验收？** 阶段 1 起就要在 Windows 上构建 pydomino 的 C++ 扩展、跑测试。可选：(a) 你有 Windows 实机，阶段里按清单人工验；(b) 用 GitHub Actions 的 Windows runner 做构建与冒烟（需要建远程仓库并推送，必须你授权）；(c) 本机虚拟机 | (b) 做构建与自动化测试 + (a) 做原生播放、拖放、REAPER 粘贴、DirectML 的实机验收。在你授权推送前，Windows 一律标“未验收” |
| Q2 | **libmpv 动态库从哪来？** 播放仍用 libmpv（HEVC Main10 + FLAC、引擎侧截停），由一个小的 C++ 原生扩展把画面画进页面画布（ARCHITECTURE §10.1）。本机没有 libmpv；`brew install mpv` 是全局安装，源码编译也要一串 Homebrew 依赖 | 阶段 1 开始时我先调研并列出 macOS arm64 与 Windows x64 的预编译 libmpv 来源（具体 URL、版本、大小、SHA-256），**等你同意后**再下载到 `third_party/`（gitignored） |
| Q3 | **发布版的工作区默认放哪？** 规格只说“程序与工作区分离” | 默认 `~/Documents/OttoSmasher Workspace/`（Windows：`%USERPROFILE%\Documents\OttoSmasher Workspace\`）；设置里可换；首次启动直接用默认值（不做向导），顶栏 ⋯ 可打开 |
| Q4 | **采样独立化的入口与格式**（规格 04 §4.8 是刚需，但只写了“删除前可选择独立化”）：① 要不要在采样上提供单独的「独立化…」操作（不删原片也能先独立化）？② 物化的声音用什么格式？③ 画面片段用什么编码？ | ① 提供（采样右键 / 批量 / 删除原片弹窗三个入口，同一个操作）；② **FLAC 无损切片**——这样采样绑定（资产 + 区间）不变、测量和固定结果继续有效（ARCHITECTURE §4.9 的“存储迁移”做法），代价是比 MP3 大约 3–4 倍；③ H.264 CRF 18、分辨率与帧率跟随原片 |
| Q5 | **范围栏上能不能放“表达式”条件块？** 规格 07 §7.3 的保存筛选器条件里有“标签表达式”，但「把当前范围存为筛选器」又明确“不含主表达式”——那筛选器里的表达式从哪来？19 §19.2 的例子里范围栏有“表达式：…”块 | 范围栏「+条件 → 范围表达式」可以加一个独立的表达式条件块（与主表达式分开、取交集）；存为筛选器时它会被存进去，主表达式不会 |
| Q6 | **拉平弹窗里改“处理范围”时，定音方式要不要跟着变？** 规格 11 §11.2 的表格按“范围”写默认定音（整段/仅元音 → 段内自动；首元音起/内部 → 交界左），02 §2.4 #15 与设置按“入口”写默认 | 不联动：打开时按入口默认（设置可改），之后用户改范围不自动改定音（P13：结果只由看得见的选项决定）。如果你更习惯联动，告诉我 |
| Q7 | **详情里切换了音源再点“语音分析”，分析的是谁？** 规格 08 §8.4 说分析“采样实际绑定的资产”，又说“详情里可以先显式切换音源” | “语音分析”永远分析采样绑定的资产；在切换后的音源上分析要用「标注与对齐 → 对齐当前选区」（结果归属“资产 + 文本区段”，原片页音素层可见；要让检索/卡拍用上它，需在该音源上截取为新采样）。切换音源后「语音分析」按钮旁提示这一点 |
| Q8 | **没有任何画面的采样导出视频片段**（纯音频原片、没有画面绑定）怎么办？规格 12 §12.5 要求“任意采样都能导出画面” | 报“此采样没有画面，可先绑定静态图片或循环动画”并就地给出「画面绑定…」入口；不自动生成黑屏视频（P6） |
| Q9 | **独立导入的音频**在原片列表里“以来源类型‘独立音频’区分”（规格 06 §6.6）——它是内部种类，还是会产生 `type:独立音频` 继承标签？ | 内部种类（`kind=standalone_audio`，列表上显示徽标），**不**产生 `type:` 标签；用户仍可自己填来源类型 |
| Q10 | **批量拉平是“每项一个任务”还是“一个批量任务”？** 规格 11 §11.6 写“每项一个任务”，13 §13.1.1 写“每项一个任务或一个任务多项皆可”，03 §3.1.3 又要求“批量拉平 → 结果表” | 一个批量任务（一个进程，逐项独立执行与登记），任务抽屉里一行，展开是逐项结果表，可只重跑失败项——与批量语音分析一致，也避免几十个任务行刷屏 |
| Q11 | **⌘Z / Ctrl+Z 绑定“撤销最近资料修改”**（焦点不在输入框时）可以吗？旧版只有命令面板入口 | 可以，但每次撤销都在提示条写明撤销了什么；输入框获得焦点时 ⌘Z 只做文字撤销。如果担心误触，改为只保留顶栏 ↶ 与提示条按钮 |
| Q12 | **素材库导出目录按日期分子目录**（`Library/Exports/2026-10-05/`）可以吗？目录名必须是英文，所以按原片分只能用 `src-<id8>` 这种不直观的名字 | 导出与 REAPER 按日期；库内正式音轨按原片（`Library/Tracks/src-<id8>/`，应用里每个原片有“打开库目录”） |
| Q13 | **收件箱归类后焦点自动跳到下一条未归类**（界面方案 v2 §2.2）可以吗？规格只说“归类后该行就地显示、不立即消失” | 跳：分拣是连续动作，而且只在你按归类键/按钮时发生（不是后台自动选中，P8 不受影响）。不喜欢就改成留在原行 |
| Q14 | **列表默认不显示画面缩略图**（v2 把画面移到舞台头部，⋯ 里可打开“列表显示画面”）可以吗？旧版列表每行都有缩略图 | 默认不显示，让列表更安静、一屏更多条；你若靠缩略图认场景，就改成默认显示 |

## 二、规格内部的矛盾（我按右列执行，请确认）

| # | 矛盾 | 我的处理 |
|---|---|---|
| C1 | 18 D39 写“修正 K1（必须满足节奏**只收 1/2/4/8** 密度）、K3（命中卡拍试听**固定近快**）”——这描述的是旧版缺陷本身；09 §9.6.4 / §9.7、19 K1/K3、18 §18.2、16 R14.16 / S3.2 都写的是修正后的行为 | 按 09：必须满足节奏接受任意 2^k 密度；命中的卡拍试听用该命中证据所选的方案；列表行默认卡拍仍用近快 |
| C2 | 分离结果保存为采样的默认性质：05 §5.5.2 写“性质默认未分类”；04 §4.2.7、06 §6.8、19 F2、16 R2.6 写“按声部资产的角色预填（人声声部 → 语音）” | 按 F2（角色预填） |
| C3 | 检索命中保存的默认性质：09 §9.7 写“默认性质‘语音’”；04 §4.2.7、06 §6.8、03 §3.4.4 写“按命中所在资产的角色预填” | 按角色预填；音高命中（10 §10.2.6 “性质由用户选”）同样按角色预填、可改 |
| C4 | 导出文件名的“原片段”：12 §12.1 写“原片名（≤60 字节）+ `__` + 原片 ID 前 8 位，**整段 ≤45 字节**”，两个上限不可能同时满足 | 整段 ≤45 字节优先：原片名按 UTF-8 截到 35 字节（不截断多字节字符）+ `__` + 8 位 ID |
| C5 | 测量共享的前提是“同一份文件内容”（04 §4.2.8、不变量 13），但 13 §13.3.2 又允许 MP3 正式音轨“沿用压缩前的测量” | 按 13 §13.3.2（所有者已接受）：分离/拉平成品在编码前测得的 F0 挂到该 MP3 资产上，并在测量记录里标“测于编码前 PCM”；之后新的测量以实际文件为准 |

## 三、规格没写清、我先这样定的（不影响基线；有异议再改）

| # | 事项 | 我的做法 |
|---|---|---|
| D1 | 原片音轨模式的音高检索（10 §10.2.3）与新范围栏的关系 | 分面条件（作品、人物等标签）按“查询窗与标注正长度交叠”求值；性质、星标、属性条件这类采样专用条件在该模式下拒绝并说明 |
| D2 | “独立化”后的采样能否再被截取、拉平 | 能：它仍是同一资产上的区间；物化切片覆盖的范围内一切照常，超出切片的范围报“原片媒体已释放” |
| D3 | 内容指纹算法（04 §4.2.1 “算法自定”） | 原片：大小 + 头/中/尾各 1 MiB 的 SHA-256 + 流签名；库内生成文件：全量 SHA-256 |
| D4 | 列表“最近一次成功试听的版本”跨窗口是否共享 | 同一 UI 进程内共享（另开的窗口也是同一进程），不跨重启 |

| D6 | 复制模型时 `tsqyomi/` 目录里多出一个旧版的 `preparation.json`（不在规格 14 §14.1 的清单里） | 不读、不用；新版只认规格列出的文件与 SHA-256 |
