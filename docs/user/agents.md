# 让 agent 操作 OttoSmasher

能在你电脑上运行命令的 agent（Claude Code、Codex 等）可以通过命令行 `otto` 操作 OttoSmasher。它调用的是界面用的同一组功能，所以它做的事你都能在应用里看到。

应用负责确定的事：存资料、分离、分析、检索、卡拍和导出。需要判断的事交给 agent，比如清理写法乱的字幕、挑出说某类内容的台词、没有字幕时找 OP / ED。

## 接上 agent

1. 打开一次 OttoSmasher。发布版启动时会把 `otto` 装成命令（`~/.local/bin/otto`；Windows 在 `WindowsApps`）。
2. 打开设置 → 命令行与 agent，点「复制给 agent 的开场白」。
3. 把开场白发给 agent，后面接上你的任务。

终端里找不到 `otto` 时，把 `~/.local/bin` 加进 PATH，或者用设置里写的完整路径。

可选：想让 agent 不用你提醒也知道这个工具，请它把 [skills/ottosmasher/SKILL.md](../../skills/ottosmasher/SKILL.md) 按它自己工具的方式装到当前项目。不要装成全局，免得别的项目里也带着它。

示例：

```
（先贴设置里复制的开场白）
任务：~/Movies/otomad素材/某番 里是新下的几集和字幕。登记文件夹，整集分离（用 HyperACE v2），对着人声把字幕洗干净（改文件之前把计划给我看），
导入字幕，把说到游戏的台词都建成语音采样、分析、打上 topic:game，
然后在这些采样里找“前两拍各一个音、第二个音长”的节奏，把命中导出到 ~/Desktop/game-hits。做完告诉我建了哪些采样、哪些拿不准。
```

## 改 agent 的做法和约定

工作区的 `Agent/` 文件夹里有两样东西，你都可以直接改：

| 文件 | 内容 | 什么时候生效 |
|---|---|---|
| `Agent/playbook.md` | 你的约定，比如“总是整集分离”“导出放到桌面某文件夹” | agent 每次开工都看 |
| `Agent/skills/<名字>/SKILL.md` | 做法，比如怎么洗字幕、怎么对轴 | agent 做这类任务时才看 |

运行 `otto setup playbook` 可以生成带示例的约定模板。让 agent“记下这个做法”，它也会写进这里。

打开文件夹：设置 → 命令行与 agent →「打开文件夹」。第一次打开这个设置页，或者第一次有 agent 开工时，内置的做法会放进这个文件夹。

内置的做法有：

| 名字 | 做什么 |
|---|---|
| `cleaning-subtitles` | 洗字幕、标说话人、核对跨版本的时间轴 |
| `separating-audio` | 决定整集分离还是局部分离 |
| `retiming-lines` | 修正台词边界 |
| `finding-op-ed` | 没有字幕时找片头片尾 |
| `grouping-speakers` | 用声纹按说话人分组（实验性；需要 uv 和 ffmpeg，第一次会下载几百 MB） |
| `picking-lines` | 从几千句台词里按意思挑选 |

你也可以新建文件夹，加自己的做法。格式是 [Agent Skills](https://agentskills.io/specification)：一个文件夹，里面一个 `SKILL.md`，开头写 `name` 和 `description`。

应用更新时的处理：

| 情况 | 结果 |
|---|---|
| 你没改过这个文件 | 自动换成新版本 |
| 你改过，内置版本也出了新版本 | 你的文件不动，新版本放在旁边的 `.new` 文件里，可以让 agent 帮你合并，处理完删掉 `.new` |
| 你删掉了这个文件 | 不会补回来 |

如果你改过的做法用到了新版本已经没有的命令，运行 `otto setup skills` 能查出来。

## 接上音频工具

很多 agent 听不到声音。除了登记文件、导出指定采样这类按固定步骤做的事，agent 做需要判断的任务都要先接上音频工具，比如编排音 MAD rap、挑音色、挑台词、洗字幕。

运行 `otto setup audio --for claude-code|codex|other`，它会给出接上 [audio-mcp](https://pypi.org/project/audio-mcp/) 的命令或配置。接上后，agent 能看频谱图、量响度、做带时间的转写。

这需要先装好 `uv`。第一次使用会下载程序和 Whisper 模型，约 1.6 GB。它只用 CPU，所以长音频转写较慢。

## 等长任务

整集分离要十几到几十分钟。能在后台等的 agent 会后台等，不耗 token。不能的 agent 会告诉你先停在这里，跑完后你说一句“继续”就行。

## 你会看到什么

顶栏 ↶ 左边的「操作历史」按钮列出所有资料修改，写明是你还是哪个 agent 会话做的。agent 连着时，按钮上会亮一个小圆点。

agent 要做撤销不了的操作时，应用会弹出确认框，写明是哪个会话、要做什么、影响多大。这些操作包括删除原素材或采样、给作品文件夹改名、清理存储、独立化后删原素材。

- 你点「允许」才会执行。
- 2 分钟没人回答就不执行，请求会留在「操作历史」的“错过的确认请求”里，按钮上亮红点。
- 放行时如果资料变了，应用不会执行，而是带着新的影响再问你一次。
- 不想每次都确认：打开设置 → 命令行与 agent →「撤销不了的操作也不用确认」。这一项只有你能改。

## 撤回 agent 的修改

agent 的每个修改都记着会话名。在「操作历史」里可以撤销某一条，也可以按会话筛选后点「撤回这个会话…」。如果某条之后被你或别的会话又改过，撤回会停在那里并告诉你。

新建的采样、分离出的音轨和导出的文件撤回不了。要删 agent 建的采样，用删除，它会让你确认。

## 数据去向

agent 用云端模型时，它读到的台词和音频可能会离开你的电脑。应用控制不了 agent，要不要这样用由你决定。

## 命令分两层

- 业务命令操作资料库：原素材、采样、编辑和撤销。
- 原始能力只做计算：日语对齐、读音分析、测音高、按应用规则读字幕文件。声音可以是库外的任意文件，也不会改你的资料。
