# 独立音高检索

本文件描述当前索引与查询实现及验收限制。任务进度以 `../STATUS.md` 为准。音高查询不读取 FA、音素或 mora，不运行模型，不登记采样。

## 数据与坐标

`pitch_tracks` 记录不可变索引代次的目录、内容签名、帧数及实际文件描述；`pitch_sample_ranges` 是可重建的采样覆盖缓存。文件时间是原文件解码后的音频流时间；采样的 `start/end` 映射到这个时间轴。相同内容 SHA-256、音频流、FCPE 权重版本与索引算法版本共享索引；标签、名称与采样关系不进入声学内容身份。

每个声音内容对应一个二进制分片目录：

- `native.npy`：float32，N×3，10 ms 网格的 F0 Hz、confidence、线性能量。
- `summary.npy`：float32，ceil(N/5)×3，每 50 ms 的可靠帧 MIDI 均值、可靠覆盖率和平均能量。
- `manifest.json`：输入内容、文件大小/mtime、模型签名、帧数与索引签名。

文件采用 NumPy mmap 读取，不用 JSON 承载逐帧数组。当前分片单位是独立声音内容，不是固定分钟数；超长单文件仍需独立验证内存。准备任务每次只初始化一个 FCPE，60 秒一段、两侧各 1 秒上下文，恢复连续原生网格。每次发布新目录，避免覆盖正在被查询进程映射的文件。

## 文本和严格条件

```text
0.40 A4
0.30 C5..D5
```

1–16 行，每行至少 100 ms，总长不超过 10 秒。时长四舍五入到 10 ms，API 返回规范化值，界面按实际值预览。音符解析支持升降号和八度。首版不支持自由曲线、局部变速或 DTW。

默认参数：`tolerance_cents=50`、`coverage=0.8`、`max_gap=0.12`。confidence ≥ 0.5 且 F0>0 的有限帧才可靠；门槛不可通过查询调低。每行分别满足带内覆盖率；整个查询的连续不可靠帧不得超过缺口阈值，不能在行边界把长缺口拆短。缺失不是 0 Hz。可选 `stability_cents` 限制可靠 MIDI 的 P90−P10，`energy_min/energy_max` 限制每行平均线性能量。未知字段拒绝，不静默忽略。

默认范围是已保存采样。当前文件夹、来源、选中项及统一布尔标签表达式先筛选候选采样。合格起点区间为每条独立采样的 `[ceil(start/10ms), floor(end/10ms)−查询帧数]`；只合并这些**允许起点**，不合并声音区间，因此相邻采样不能拼接出一个长命中。

## 查询过程与近似边界

1. 在 50 ms 起点网格，以摘要前缀和向量化计算每行覆盖率。粗筛音高带比用户容差额外宽 100 cents，覆盖率低 0.15，减少网格偏移带来的漏检。
2. 每个声音内容的合格 50 ms 连续起点组成候选组。按粗筛分数选各组代表，先分配不同组，再轮询组内候补；最多 2,000 个粗筛候选。一个长音不独占精排预算。
3. 在每个候选 ±50 ms 的原生 10 ms 起点精排，去重重复起点；每组只保留满足严格条件的最佳窗口。每批最多 256 个窗口，使用与标量校验相同的可靠性、覆盖、缺口、能量与稳定度条件。
4. 精排使用用户原始阈值。最终按平均音高范围偏差排序，最多 100 个唯一内容/区间，附所有能完整包含命中的合格采样 ID。

所有查询明确标注近似。漏检来源包括 50 ms 网格、摘要均值掩盖短变化、粗筛阈值、2,000 候选上限和 F0 本身的误差。宽松粗筛不能成为正式命中条件。连续起点组只保留一个最佳窗，可能漏掉组内另一个合格窗口，或漏掉只包含其他组内窗口的重叠采样。两个被不合格起点隔开的区域仍保留为独立命中。

## 失效与失败

- 改变采样绑定或删除采样会删除覆盖缓存，保留共享索引。
- 查询重新检查实际文件大小/mtime、算法版本、配置中的模型 SHA-256、manifest 和帧数；过期项不参与检索，并计入覆盖报告。索引任务验证实际文件 SHA-256；查询不重复读完整媒体算哈希。
- 源文件缺失、索引代次缺失或不一致须报告，不能换成混音。试听命中再次检查索引身份。
- 修改标签/文件夹即时改变范围筛选，不重新跑 FCPE。修改 FA 不使 F0 失效。处理后声音有新内容身份，必须单独准备索引。
- 文件被外部程序修改且刻意保留相同大小与 mtime 不在廉价查询检查的保证范围内；明确重建索引会进行内容校验。

## 数据库与 HTTP 基准

`scripts/benchmark_pitch_catalog.py` 在独立工作区创建十万条真实 SQLite 采样记录、50 个资产、6,000 条时间标签和人工标签；索引仍是上述 50 小时**合成 F0**。通过 FastAPI TestClient 调用正式 HTTP 路由，包含范围筛选、动态标签、检索、关联与 JSON 序列化。六组各运行六次，首轮之外的五次统计热 p95。

```sh
PYTHONPATH=src .runtime/envs/core/bin/python scripts/benchmark_pitch_catalog.py \
  --workspace .runtime/pitch-http-benchmark --indices .runtime/pitch-benchmark --prepare
PYTHONPATH=src .runtime/envs/core/bin/python scripts/benchmark_pitch_catalog.py \
  --workspace .runtime/pitch-http-benchmark --indices .runtime/pitch-benchmark --case tags --repeat 6
```

可选 case：`single/multi/none/common/tags/overlap`。每组用新进程，`overlap` 必须最后运行：它把这个专用基准库的采样和覆盖范围改成几乎整轨，以检验大量重叠。脚本拒绝覆盖已有工作区。不要针对用户工作区执行准备。

## 已接入口与实音频验证

采样及 `sources` 模式共用精排。来源模式可以用 `asset_ids`、`roles`、`scope.source_id`、来源文字与布尔标签过滤，显式索引准备同样尊重这些条件；区段标签按查询窗正长度交叠计算。`boundaries.start_tolerance/end_tolerance` 为 0–5 秒，基于独立文字标注，无资料明确计作未知，绝不以音素猜测。每个结果只关联满足该范围条件的采样或资产。

GUI 可试听命中、定位采样，或明确保存命中为新采样。`pitch-hit/selection` 先核对文件身份和完整包含关系，再转为资产局部坐标；保存统一走 `selection/save`，查询本身不登记资料。

真实短句在独立索引任务后，来源模式检索返回 98 个有效窗口，命中保存成功；处理后音频使用独立内容身份。真实素材的大规模准确率和不同机器的桌面启动性能仍需要实际数据验收。


## 固定结果与独立版展示

`search_sessions` 保存查询、范围及索引版本；`search_session_rows` 保存固定成员、命中和采样绑定版本，不复制完整测量。主列表按采样/来源音轨分行，多命中共用展开、试听及定位。关闭标签只删除结果集合。分页读取每页最多100行，恢复不执行查询、不自动播放；资料名可更新，失效成员保留位置并禁止旧命中操作。

索引覆盖预检与准备任务独立。查询计时包括范围筛选、关联和分组，界面另计从点击至结果呈现；两者不能与纯内核时间混用。当前结果按声音/区间去重后最多100个窗口，最多100个展示对象；声音重叠复用计算并逐采样核验完整包含。
