## 1. 产品定位与分工

- **三层各管一件事**：
  - **原素材与文本层**记事实：哪里说了什么、谁说的、OP/ED 在哪。只记，不做取舍。
  - **采样**是从原素材上切下来、能直接用的单位：边界确定，能试听、拖出、导出、交接、卡拍、拉平，三大搜索与筛选都只对它。**建成采样只表示“能用”，不表示“有价值”**；可以逐句手工截取，也可以整集台词一次全建。
  - **星标、标签、筛选器**记取舍：可改、可以有好几个维度。
  （2026-10-31「采样的定位」；取代 2026-10-09 的“采样 = 哪段有价值”）
- **上下文优先**：判断类、算法本身不稳的事（说话人聚类、不规范字幕里找 OP、字幕清洗、抠图等）不进应用；应用提供原子能力（读资料、拿音频与画面、带来源可撤回地写回），判断交给人或 agent。稳定确定的流程照旧在应用里，不用 agent 也完整可用。（2026-10-24 阶段 A 验收反馈第 10 条）
- **应用不管预处理**：不读视频里内挂的字幕流、不做提取 / 调轴 / 清洗；这些由用户或 agent 在文件上做。（2026-10-25，同上第 12 条）
- **术语**：界面上叫“原素材”（不叫原片）、“素材标识”（集数 / 编号 / 名称，推断不到时用文件名）、“详情区”（不叫舞台）。代码与内部名（source、stage）不改。（2026-10-10「术语、快速开始、README 亮点」）

## 2. 原素材与导入

- **原素材只有一种**。原素材页「＋」/ 拖入与采样库「导入」/ 拖入共用一个导入框，差别只在「直接建立全长采样」默认勾不勾（采样库勾、原素材页不勾）。同一文件再导入不重复登记。（2026-10-07「阶段 3 验收反馈」）
- **原素材文件夹**：第一层子文件夹 = 作品；启动时与「重新扫描」时自动登记、认移动和改名；文件夹里的原素材作品只跟文件夹走，改名用「作品设置…」（改磁盘文件夹名，失败回滚，不进撤销，与已有作品同名就拒绝）。原素材原地引用，不复制、不转码。（同上）
- **作品 / 素材标识推断**：有序正则列表，第一条匹配生效，命名组 `work` / `episode`；推断不到时作品留空、素材标识用文件名。（Q22；2026-10-10 术语）
- **一个原素材只有一个原始音轨**：多配音、多语言就拆成多个原素材导入，不引入“族”这类概念。（2026-10-12「音素回到原素材时间线」第 8 条）
- **同名画面自动绑定**；导入文件夹时音频与视频都导入，与某个音频同名的视频 / 图片是它的画面。（Q20、2026-10-07）
- **文件是否被替换看“文件快照”**（大小 + 修改时间 + 流签名），内容指纹废弃。（D3）
- **删除原素材**：可勾选要独立化的采样；原素材记录变成“媒体已释放”，留在作品组里，段与测量保留；磁盘文件不动。删除原素材撤销不了，要确认。（2026-10-09 阶段 8 / 9 细节第 16 条）

## 3. 文本层与字幕

- **原素材上的四类对象**：文本层的段（说了什么，给分析）、音效提示（给人工拣选）、区段标签（时间上的属性）、OP/ED。段用原素材时间、作用于整个原素材，字幕来的与手输的同级；字幕里本来重叠的段允许存在、不自动处理（读到的采样报“不可用 + 原因”，用户自己缩判定区间）。没有“歌词”概念。（2026-10-09「原片上的四类对象」）
- **字幕关联**：与媒体同名的 `.srt` 优先，其次 `.ass`；再其次同名加后缀、字幕子文件夹。只关联，导入是另一个显式操作。（规格 06；2026-10-07）
- **字幕导入 = 一次显式操作，四类一起进**（段、音效提示、说话人、OP/ED），整次原子、可撤销；文本层不分版本。再导入时逐行比：不交叠 → 新增；区间与文字都相同 → 无变化（**不更新说话人和原文**）；只碰到未受保护的旧段 → 按全局选项替换（默认）或保留；碰到受保护的 → 跳过，可逐行强制替换（二次确认）。受保护 = 段被改过（文本、边界、拆分合并、手输）或有人工音素版本。（2026-10-09 同上；2026-10-31「删除导入的字幕标记」）
- **删除导入的字幕标记**：原素材右键 / 多选「删除导入的字幕标记…」，一次删掉字幕来的段、音效提示、规则标的 OP/ED（可撤销）；手输段不删，受保护的默认留下。要按新字幕从头来就先删再导入。（2026-10-31「删除导入的字幕标记」）
- **说话人只认一种写法，逐行读、宁可丢不写错**：台词行**行首**的括号是这一行的说话人（`、` 分隔 = 几个人同时说）；台词中间的括号只从台词里去掉、从不当人名；只有括号的一行是音效，但下一行是没标注的台词时两样都不认；没标注的行 = 不知道、从不跟上一行；一条里每个台词行都标了才记说话人，有一行没标就不记并标 `speakersWithheld`。剩下约 1% 的误认（行首括号其实是音效描述）接受。洗好的字幕写法：一条一个人、每个台词行都标。（2026-10-31「字幕说话人只认一种写法」）
- **段的 `speakers`** 是确定读出的那部分，空 = 不知道；完整的标注在段的 `raw`（原字幕这一条的原文，编辑、拆分后保留，合并后是各段原文连起来）。只改说话人不算受保护，另记“说话人改过”，只让「按当前规则重新生成说话人」跳过它。（同上；2026-10-09 追问答复）
- **编辑段**：改文字或边界后，旧分析立即停用，用户手动重跑；「改段后自动在后台重跑」开关默认关。拆分、合并 = 删旧段建新段。手输段与已有段重叠时让用户选替换、切开或取消。（2026-10-09 追问答复）
- **标点**：停顿 = `、。，．,.！？!?…‥―—` 与空白；其余标点、符号直接忽略；`～〜~` 是长音。（2026-10-12「使用反馈」第 2 条）

## 4. 语音分析与音素

- **音素属于原素材时间线**：一句台词只有一份当前音素（最近一次分析或人工修过的那份），修一次处处生效；只有回导成品（及从它加工出来的）另有一份。只在盖住整句、含人声的轨上测；明确选的轨不含人声或盖不住整句就写原因、不偷偷换轨。（2026-10-12「音素回到原素材时间线」）
- **音轨角色在加工时复制一次**：拉平成品继承输入音轨当时的角色，之后改输入音轨不同步，免得覆盖在成品上手动改的角色。（2026-11-04，ROADMAP L45 关闭）
- **含人声** = 开着“人声”角色，或一个角色都没开、又不是从分离声部来的；不含人声的轨不读音素、不能分析。（同上）
- **原素材页可以直接分析段**（默认人声轨或当前查看的轨），不需要先建采样。（2026-10-08「分析挂在句上」、2026-10-09）
- **采样只读取分析**：读与判定区间正长度交叠的所有段；被采样范围裁掉一部分的音素标 ◐；读到的多段音素重叠时节奏“不可用 + 原因”，不自动裁决。（2026-10-09「原片上的四类对象」D 节）
- **对齐窗口** = 段区间 ± 对齐容差，默认前后各 **0.2 秒**（设置 `analysis.tolerance_before/after`）；对齐器只会把整句放进窗口，不会找句子在哪。对齐只用 pydomino。（2026-10-30「【基线变更】阶段 10 发布方式」补充）
- **不入库的原始能力**：`speech.align`（`lines` 多行各当一句对齐）、`text.analyze`、`f0.track`、`subtitles.parse` 给 agent 用，不写资料库；不加“可疑”判定，只给 `edges`、`longestPhone` 这些事实。（2026-10-30 阶段 A 验收反馈第 15 条；2026-10-31「按说话人分组走 skill 的路」）

## 5. 采样

- **统一的建采样动作**：来源可以是选区、段、音效提示、检索命中、分离声部、整段原素材，可批量；同一套默认规则、一律新建。单条用小面板，批量用整页表格。从段建：选区 = 段 ± 字幕采样扩展量（默认 0.1 / 0.1 秒），默认建在默认人声轨上，性质语音；从音效提示建：名称 = 括号内容，性质非调谐单音；其余按资产角色预填性质。（2026-10-09 D 节；C2、C3）
- **判定区间**：每个采样都有，可见可编辑，必须在采样自己的范围内；决定标签继承和读哪些段。（2026-10-09 追问答复）
- **没有父采样**：去掉“采样 → 父采样”，只留创建方式；详情区显示“相关采样”和“加工链”；「返回原素材」换到采样来自的**整轨**、设好选区、在“采样”车道上突出它，永远不把局部成品当音源。详情区波形两边各留 max(1 秒, 采样长度的一半) 余量。（2026-10-12）
- **局部命名**：选区只碰到台词、又没把读到的每一句完整盖住时，名称 = “选中部分（这几句）”，完整的句写原文、完整的词写原文、部分的拍写片假名、半拍写罗马字。（2026-10-12 第 3 条）
- **逐句建完留在原来的页面**，提示里给「打开」；动作条「截取」照旧跳到采样库。（2026-10-09 所有者确认）
- **原素材页的音源下拉**只列整轨，局部音轨只列盖住播放头的；拉平、局部分离、回导是“某一段的另一个版本”，属于采样那一侧。**局部分离（选区）每个声部自动建一个采样**；整轨分离不建采样、不自动设默认轨。（2026-10-13 追加；C2）
- **删除采样**每次都要确认，agent 建的也一样。（2026-10-24 阶段 A 验收反馈第 6 条、L49）

## 6. 节奏、卡拍与交接

- **试听**：分“不卡拍”“卡拍”两种，声音三选一（原声 / 原声＋咔哒 / 纯咔哒）；咔哒与每个音块的起音同步，不是节拍器。（2026-10-08「阶段 6 开始」）
- **量化**只有“原节奏 · 无 mora”加人工占格；「按 mora」「长音补格」是临时开关（不保存，只影响详情区的卡拍试听、导出卡拍 WAV、复制 REAPER）。（同上）
- **算法上的基线修改**：贴边起音的保护核心那一侧为 0；语段切口允许块尾 / 起音伸进停顿 ≤ 50 ms；节奏用修过的元音边界（合块仍按对齐边界）。（2026-10-08「阶段 6 验收」）
- **拖出与复制**：⌥ 拖 = 原声 WAV，⌥⇧ 拖 = 卡拍 WAV（不再跟随最近一次试听；单条用舞台上选的方案，批量用默认方案，2026-11-04）；采样库 ⌘C = 复制 REAPER 交接（勾选集或当前采样），哪种在设置「导出 → ⌘C 复制哪种」（默认卡拍效果）；批量交接在同一轨上依次排开、每条之间空一小节。（同上；2026-10-08「阶段 6 开始」）
- **⌥⌘ 拖 = 拖进 REAPER，带拉伸标记**：拖的是只有 ITEM 的 `.RTrackTemplate`（所有者实测：能落进已有的轨道，带 TRACK 的会新建一条），哪种跟 ⌘C 的设置；菜单里的“导出 REAPER 条目文件”保留。（2026-11-04）
- **REAPER 条目只写秒，不写节拍位置（改了规格 12 §12.3 的格式）**：原来按采样 BPM 写，REAPER 粘贴时按它和工程速度的比例缩放条目、改 Playback rate，听起来变快（所有者 2026-11-04 实测 1.3～1.5 倍）。（2026-11-04）
- **REAPER 交接两种，都用未卡拍的原声 WAV**：“原声”= 每个音头一个 1 倍速拉伸标记，方便手动卡拍；“卡拍效果”= 用非 1 倍速拉伸标记卡好，听上去是卡拍后的，删掉所有标记就回到原声。不再有“卡好拍的 WAV + 起音标记”这一种（规格 12 §12.3 与 2026-10-08 那版执行错了，所有者纠正）。已存的设置按“卡拍效果”读。（2026-11-04）
- **全局 BPM** 存为设置但不进撤销，改了就停止试听；单音没有卡拍和 REAPER 交接。（同上）

## 7. 搜索

- **三大搜索**（节奏、音高、单音的音色 / 瞬态筛选）**只对采样**；不做原片版（会变成要同步的第二套系统）。音高检索另有直接搜整轨的“原片音轨模式”，保留。想搜一整季，先从台词段批量建采样。（2026-10-31「采样的定位」）
- **音高检索是完整检索、不漏检**：每个允许的 10 ms 起点都严格判定、全部存为固定结果；可选忽略八度、时长弹性、滑音块。（2026-10-08「阶段 7 开始」）
- **检索索引自动在后台准备**（语音检索索引、新采样与默认人声轨的 F0），排在用户任务后面；设置「语音分析 → 自动准备检索」可关。（2026-10-08「阶段 7 验收反馈」）
- **台词搜索搜文本层**（原料），结果是原素材上的位置、不是采样：不固定结果、不导出命中、不批量打标签。原素材列表的搜索框（⌘F）同时搜作品与全部台词，台本顶上的搜索框（⌘⇧F 或 `/`）搜这一集；音效提示默认一起搜。匹配规则与采样的“原句”筛选相同（规范化原文或读音子串，读音用 pyopenjtalk-plus + 用户辞典，不经 tsqyomi）。（2026-10-31「台词搜索」；2026-10-09 阶段 8 / 9 细节第 1、2 条）

## 8. 采样库与标签

- **查找栏**在列表正上方（文字 + 主表达式 + ★ 只看星标）；下面一行小字是范围。**筛选器只放标签条件**（分面 + 可选标签表达式），文字、星标、原素材、性质都不存进筛选器；性质 = 顶栏用途切换。（Q5、Q16、Q17）
- **未分类按语音呈现**，不是收件箱。（Q13）
- **说话人是段的属性**：只对带人声角色的资产生效，一人 `character:`，多人 `participants:` + `speaker-status:多人未分段`；全局改名 / 移除人物会连段的说话人一起改。（2026-10-09 四类对象细节；阶段 8 / 9 细节第 4 条）
- **命令面板**按业务做的简单版：最上面是作用于当前对象（勾选集，或当前采样 / 当前原素材）的右键菜单，然后本页动作、全局；新页面的动作在那一页登记，不另写一份。（2026-10-10，L35）

## 9. 分离与拉平

- **分离不做自动复用**：点一次就真的跑一次，多出来的音轨用户自己删；规格 05 §5.5.2、04 写的是“可以复用”，不是必须。（2026-10-30“让用户和 agent 自己管理”；2026-11-03 确认）
- **音轨删除**：音轨弹窗里删单条，设置 › 存储列出没有采样在用的音轨批量删；原混音不能删，有采样在用的不让删，默认轨删除后不自动换。（2026-11-03）
- 分离只调用用户自装的 PyMSS Studio（worker 协议，`download` 永远 false，不改它的环境）。分离结果**不自动**保存为采样、**不自动**设为默认轨（局部分离例外，见 §5）。（规格 14 §14.6；C2）
- **一个分离任务可以交多段**（`ranges`）：拼成一个输入分离一次再切回。分离成功后自动删除任务目录里的中间文件，失败的保留。（2026-10-30 阶段 A 验收反馈第 17 条；2026-10-29）
- **拉平**的处理范围与定音方式都由用户在拉平台上选，改范围不自动改定音；**批量拉平只有自动定音**（段内 / 交界）。（Q6、Q10）

## 10. 画面、独立化与导出

- **独立化**的声音切片存 WAV（整数 PCM → 24 位，MP3 或浮点 → 32 位浮点）；画面是原素材自带视频时生成视频片段；独立化之前的分析与 F0 在切片上照常可读。（Q4；2026-10-09 阶段 8 / 9 细节第 14、15 条）
- **没有画面的采样导出视频时报错**并给画面绑定入口，不生成黑屏。（Q8）
- **导出文件名的固定目录名用英文**，按原素材、按日期生成的子目录可以用可读名称。（Q12）
- WAV 导出结果带 `mapping`（文件秒 → 原素材秒），给外部工具换回原片时间。（2026-10-29「第二轮生产实测」，阶段 A 验收反馈第 13 条）

## 11. 任务、撤销与存储

- **任务队列**：模型通道并行数 `jobs.concurrency_model` 默认 1、轻量通道 `jobs.concurrency_light` 默认 2；排队中的任务可以「提到最前」（最近提的在前，运行中的不打断）；自动准备的后台任务排在用户提交的任务后面。（2026-10-30「任务插队与全部失败」）
- **一条都没做成的批量任务 = 失败**（`job-all-items-failed`），逐条原因照样登记、可重试；有一条做成就是成功，逐项失败看结果。（同上）
- **撤销**：资料修改都能撤销（⌘Z、按会话撤回）；新建的采样、原素材、音轨不能撤销，删除它们要确认。（2026-10-30「审查指令系统后的修正」）
- **存储清理**：可清理 = `Data/Cache/` 与 `Data/Staging/` 残留、成功分离的旧中间文件，可选同时清语音检索索引与单音指标；测量、素材库、数据库只列占用不清理。空闲时自动整理。（2026-10-09 阶段 8 / 9 细节第 17 条，2026-10-29 修订）

## 12. 命令行与 agent

- **`otto` 只在应用开着时可用**（`otto open` 能打开带界面的应用，等它就绪；2026-10-25 同意，2026-11-04 才做），调用与界面同一组公开命令；撤销不了的危险操作要所有者在应用里点确认（限时 2 分钟，错过的请求留在「操作历史」）；**只做命令行、不做 MCP**。（2026-10-24「命令行与 agent 接入」）
- **命令分两层**：业务命令（操作资料库）与原始能力（只算、不改资料库），见 §4。（2026-10-30 阶段 A 验收反馈第 15 条）
- **agent 的说明分三处，按“谁会改它”放**（所有者 2026-11-04，取代 2026-10-30 的三层）：说明书跟版本走，由 `otto guide` 给出，只写 agent 看不出来的事实与硬规定，**只有英文**；做法是工作区 `Agent/skills/` 里符合 Agent Skills 规范的文件夹，用户随时能改，内置版本中英各一份；约定是工作区 `Agent/playbook.md`，优先于做法。三者都改不了说明书的基本规则。
- **内置 skill 怎么更新**（所有者 2026-11-04）：第一次用时复制到工作区并记哈希。用户没改过的自动换新版本；改过的不动，新版本放旁边的 `.new`；用户删掉的不补回来。语言在第一次复制时定下。原因：不确定的流程要常被用户编辑，放在只读的程序目录里改不了，放进工作区又不能靠覆盖来更新。
- **音频工具是通用要求，skill 按任务读**（所有者 2026-11-04）：只要不是严格按固定步骤做、需要 agent 自己判断的任务（例如编排音 MAD rap、挑音色），都要先真实调用一次音频工具，这条写在说明书总览，不放进某个 skill。skill 只在任务和它的用途相符时才读，所以用途要写清什么时候不需要，也不按命令提示 skill：相关命令在普通任务里也常用，提示了 agent 容易保险起见都去读。声纹只有 `grouping-speakers` 需要。
- **人声分离的说法**（所有者 2026-11-04）：教程主线要分离，用 HyperACE v2 示范，写明模型要预先在 PyMSS Studio 手动下载。可以写“能跳过”，但必须说明背景不干净时后面的语音分析基本不能用。
- **版权**（所有者 2026-11-04）：现阶段有意弱化，README 不写素材版权声明；开发时素材不进 Git 的规定（AGENTS §5）不变。
- **内容放在哪**（所有者 2026-11-04）：skill 只放不显而易见的方法，agent 自己就知道的不写。应用事实尽量绑在用到它的地方：优先放命令的返回结果和错误，其次 `otto describe`，再其次说明书主题；对流程特别关键的，skill 里允许留一句提醒作保底。
- **文档写法**（所有者 2026-11-04）：给人看的文档按 Diátaxis 分成教程、操作指南、参考、概念（`docs/user/`），称呼读者用“你”或祈使句，少用加粗开头的列表和“不是 X 而是 Y”这类句式。给 agent 看的文档里“你”指 agent，真人叫“用户”（不叫“所有者”），小节引用名字不用序号。一个事实只放一处，其他地方链接过去；README 主要写给普通用户：语言仿 HiFiShifter，平实陈述；先讲下载和推荐工作流，再讲功能、安装和常见问题，开发内容放在最后并写明普通用户可以跳过。功能部分写“能做到什么、长什么样”，核心功能每项两三句并配图，其余一句带过并链接到操作指南，操作步骤只放在用户说明里。README 只留卖点，次要细节和实现细节删掉；不够好的功能如实说（如“实验功能，效果可能很差”）。用词：skill（不叫“做法”）、实验功能、item、音素对齐、回导；不把通用能力说成只能配 REAPER 或番剧。
- **agent 怎么找到应用**（2026-11-04）：发布版启动时自动把 `otto` 装成命令（macOS 是 `~/.local/bin/otto` 符号链接；Windows 普通用户不能建符号链接，写转发脚本 `%LOCALAPPDATA%\Microsoft\WindowsApps\otto.cmd`，这个目录 Win10 起默认在 PATH 上；只换自己的旧位置和失效的链接，别的程序的同名文件不动，开发版不装）；运行中的应用把应用路径、`otto` 路径、工作区登记到固定目录（`Application Support/OttoSmasher/instances`，不含连接密钥）。`otto` 连同一种的应用：装好的连发布版，`tools/otto` 连开发版，不交叉，免得开发版的改动写进日常工作区。
- **skill 是可选的**：仓库托管的入口 `skills/ottosmasher/SKILL.md`，只讲怎么找到 `otto`、先读 `otto guide`，想装时 agent 装到项目级。开场白不再要求下载它，直接让 agent 跑 `otto status`、`otto guide`。（2026-10-30 第 17 条；2026-11-04 改）
- **说明书不禁止把素材交给云端服务**（交不交由用户决定）；开发时 `fixtures/` 的规则不变。（同上第 7 条）
- **听觉工具用外部的 audio-mcp**，不内置；对齐、分离不做独立程序，外部音频登记成原素材即可用。（同上第 14 条）
- **按说话人分组走 skill 的路**：应用不加 `speaker.*` 命令、不分发声纹模型；做法、实测数字和声纹脚本都在 skill `grouping-speakers` 里，由 agent 在自己的环境里跑。（2026-10-31「按说话人分组走 skill 的路」）

## 13. 界面

现在的应用就是界面的参照（原型和阶段 0 的界面方案已移进 [history](history/README.md)）。下面这些统一规则是跨页面的约定，新界面照做：

- **工具页只在开发版显示**：里面只有组件样张和开发自检，发布版不显示导航、快捷键和命令面板入口。（所有者 2026-11-04）
- **导入先问选文件还是文件夹，两个平台一致**：Windows 的系统对话框不能同时选两种（同时要求时只能选文件夹，所有者实测），macOS 虽然能，也走同样的流程。原素材页的按钮写明「导入」，并提示推荐导入整理好的文件夹。（所有者 2026-11-04）
- **一屏一个主角**：采样库的主角是右侧详情区；原素材页的主角是画面 + 台本 + 时间线。**用途决定呈现**：统一用列表、每行有画面缩略图，副信息随性质变化。**一条全局播放条**：任何时刻只有一个声音。**安静的视觉**：深色为主可切浅色、主色是 logo 蓝 `--accent`、性质四色（语音青绿、调谐琥珀、非调谐珊瑚、未分类灰）、只用设计令牌。（UI_PLAN §0 D1–D6）
- **弹出物不叠层**：就地编辑 / 锚定小面板 / 浮层（检索）/ 全屏工作台（拉平、导入字幕、批量建采样、设置，同一时刻只有一个）/ 确认框（居中、小，写清删什么和不删什么，补充选择放在同一个框里）/ 抽屉（任务）。（UI_PLAN §5）
- **集合的统一规则**：单击只看（设焦点），从不改变勾选；勾选只靠复选框、⌘ 单击、X、Shift 连选、⌘A；右键不改选择和焦点，菜单第一行写明对象；Esc 分层；条件变化清空勾选并提示；播放按钮左键原声、右键卡拍。（UI_PLAN §6.1，拖出按 §6 本文件）
- **波形的统一规则**：单击移播放头、拖动建唯一选区、Shift 单击选整句 / 整个音素、滚轮缩放；原素材页时间线与详情区共用波形卡 `components/WaveCard.tsx`；标签避让 + 折行（覆盖层最多行数可设，车道固定一行）。（UI_PLAN §6.2；2026-10-13）
- **快捷键分焦点区**（全局 ＞ 工作台 / 确认框 ＞ 集合区 / 波形区 / 画布区 / 输入框）；按键以应用里的「快捷键一览」（`?`）为准。（UI_PLAN §7）
- **控件只从组件库取**（`app/renderer/components/`，基于 React Aria Components）；缺了先补进组件库。（Q18；2026-10-07 阶段 3 开始）
- **界面语言**：简体中文和英语；默认跟随系统（系统是中文就中文，其余英语），设置里可以改，换了窗口重新载入。（2026-11-03）
- **文案只翻译文字**：全部走文案资源 `t()`；数字、时长、日期、文件大小用一种固定格式，不引入国际化框架。（Q21）
- **界面出错有全局兜底**：渲染出错不再黑屏，显示说明、错误信息和“重新加载界面”，错误写进 `Data/Logs/desktop-events.log`（`app/renderer/shell/ErrorBoundary.tsx`）。（2026-11-04）
