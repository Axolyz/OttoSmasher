# 界面原型使用指南（给实现各阶段的开发者）

> 2026-10-07 写（原型的作者，阶段 0 与所有者八轮敲定）。配合 AGENTS.md §2 的规则使用。
> 原型：[`prototype.html`](prototype.html)（v3.3 定稿，之后只改过配色）。界面方案文字版：[`../UI_PLAN.md`](../UI_PLAN.md)。

## 1. 原型是什么，不是什么

**照着做的**（文字说不清、只有原型能表达的东西）：
- 区域划分与比例、信息层级（什么大、什么淡、什么收起来）、密度；
- 每个控件放在哪、叫什么、默认值显示在哪；
- 悬停、右键、Shift/⌘ 单击、双击、Esc 的行为与反馈（提示条、菜单头写对象）；
- 弹出物的形式（就地 / 锚定小面板 / 确认框 / 全屏工作台 / 抽屉，UI_PLAN §5）。

**不要照抄的**：
- 假数据：台词、人名、时长、计数、模型名（hyperacev2、becruily_deux、dnr_v3 只是示意，真实列表来自 PyMSS Studio）。台词是编的（版权规则）。
- 波形：原型用 wavesurfer.js 演示；正式应用是自研组件（ARCHITECTURE §1.2、§10.2）。只学它的交互（覆盖层、车道、Shift 吸附、编辑条），不学实现。
- 弹窗里的长句说明：是示意性的。规格（交接包 03/05/06 等）引号里的提示文字表达的是**概念与规则**，以规格为准；措辞可以沿用原型，前提是不改变意思。
- 原型 `body{min-width:1180px}`：正式应用必须在约 850×600 的最小窗口下可用（规格 15），原型不管这个。
- 原型没有真实的空状态、加载中、出错、超长列表、文件缺失等状态：这些要按同一设计语言自己设计，并在阶段验收时给所有者看。

**原型里的过时残留**（已取消的功能留下的死代码，看到了不要实现）：
- `.triage`、`.classify`、`classify()`：收件箱/分拣台（Q13 已取消，未分类按语音呈现）；
- `.pads`：单音卡片墙；`.shelf`、`.eps`、`S.src.view`、`epItems` 里的“打开查看器”：原片片库海报墙（所有者：不要任何海报墙）；
- `undo()` 的提示是写死的假文字。

## 2. 冲突时以谁为准

从高到低：

1. **交接包规格**（docs/01–19）——除非 `QUESTIONS.md` 里有所有者的【基线变更】；
2. **`QUESTIONS.md` 里所有者的答复**——同一件事有多条时以日期最新的为准（第五节按轮次记录，可以按时间查）；
3. **`UI_PLAN.md` 的文字**（含 §11–§16 各轮修改表）；
4. **原型**；
5. 开发者自己的判断。

判断方法：
- 原型与 UI_PLAN **都写了但不一致** → 一般 UI_PLAN 是对的（后几轮先改文字）。但如果原型的做法在 QUESTIONS 里有更新的答复支持，以答复为准。拿不准就**截两边的图问所有者**，不要猜。
- **原型有、UI_PLAN 没写**（例如某个按钮、某段说明、某个默认值的显示位置）→ 视为有意的布局细节，照做；若与规格冲突，按第 1 条处理并记下来。
- **UI_PLAN 有、原型没做**（例如拖出、焦点区高亮、各种快捷键）→ 照 UI_PLAN 做，外观沿用原型的设计语言。
- **两边都没有**（空状态、错误、加载、边界情况）→ 自己设计，记进 STATUS，验收时请所有者看。
- **技术上做不到或代价很大** → 写替代方案问所有者。

取舍原则（所有者 2026-10-07）：原型与实现对照时，**哪边内容更丰富、更合理就照哪边**（通常是原型）；
样式差距不大的保持实现的样子——应用用 React Aria，套用它的设计语言，原型是按 Radix 风格画的，不必百分百一样，**功能对等**即可。

记录：每处偏离写进 STATUS 当前阶段的“与原型的差异”表（原型怎样 / 实现怎样 / 理由 / 依据：QUESTIONS 编号或规格条目）。
所有者认可的偏离要回写 UI_PLAN（必要时也改原型），避免两份参照越走越远。

## 3. 怎么打开、怎么定位

- Claude 桌面应用的浏览器面板打开 `file:///…/docs/ui/prototype.html`，视口设 1440×900；改完文件后加 `?r=N` 强制刷新。
- 原型从 unpkg 加载 wavesurfer.js，需要联网（只影响原型自己的波形演示）。
- 按 `?` 看快捷键；读文字用 `get_page_text`，比截图准。
- 控制台可以直接调用这些函数打开对应面板：`go("sources")`、`renderSources()`、`subImportSheet()`、`subSampleSheet("line"|"sfx")`、
  `tracksModal()`、`opedModal()`、`sepModal("full"|"sel")`、`analysisModal(1,"source")`、`flattenSheet("stage", samples[2])`、
  `settingsSheet("通用")`、`openComposer("speech"|"pitch")`；状态在 `S`、假数据在 `samples`。
- 原型里键盘事件要 `bubbles:true` 才会被收到；坐标点击偶尔不准时用 DOM 的 `click()`。

## 5. 并排比对的做法

1. 动手前：在原型里把对应部分走一遍，记下区域、文案、默认值、交互（`get_page_text` 抓文字）。
2. 实现后：同一视口（1440×900）各截一张——应用用 Playwright 驱动 Electron，原型用浏览器面板——并排看。
3. 差异逐条处理：改掉，或者按第 2 节记进 STATUS 的差异表。
4. 阶段验收清单里附上差异表和截图位置，请所有者一起看。
