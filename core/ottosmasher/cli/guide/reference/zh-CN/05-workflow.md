# 范围、精度与核验证据

## 开始时确认一次

内容判断任务先明确素材／集数、输入版本、产物、可复用成果和精度。沿用用户明确要求及适用的 playbook；否则问一次快速／标准／精细，解释当前任务的实际区别。用户已说“所有可疑项逐条核对”时，不用再问精度。

| 精度 | 字幕任务 | 台词／音色／分离任务 |
|---|---|---|
| 快速 | 清文字、核版本偏移、统计真实标注规律，检查明显缺陷，说明未精修范围 | 小候选集、有限比较，完成可用初选 |
| 标准 | 全片筛查，核高风险项，再按写法、场景、角色抽查正常项 | 扩展候选并比较代表项，检查是否符合目标 |
| 精细 | 全片筛查，核完全部可疑首尾、换人、重叠项；正常句按场景抽查 | 多轮搜索，核完约定的全部候选 |

用户可以追加每句核验、只精修某集等要求。精度只改变范围和投入，不能放宽身份不确定留待定、完整语音、数据安全、逐项结果和如实汇报。成本说相对多少，不编造 token 数。需要实质降档时先问，未回复不等于同意。

## 约定内的自由度

分页、时间换算、数量和漏项检查交给脚本。技能中的必要依赖要满足，例如单人区间先于声纹判断；具体分析方法根据材料选择。参考路线帮助起步，采用替代方法时说明怎样满足同样目标。不要根据自称模型聪明或较弱来放宽正确性要求。

计划之前读任务技能及适用引用。统计每个来源真实写法，允许发现示例没有列到的情况。实验数字只对对应实验成立。长任务在临时任务目录保存小报告，不在应用里另建一套流程数据库。


## 检查与判断

输入惯例没有穷尽的列表。先理解原始材料，再选方法或写任务脚本。括号、行数、短句时长和能量都不是判断身份、换人或可疑边界的通用规则。未理解的写法保留，发现新形式就修订假设。应用解析器规定交付格式，不负责理解所有来源。

脚本可以核对已声明字段、分页、时钟换算、数量和输入变化，不能决定字幕是否表示换人、声音是否属于下句、核验范围是否足够。按任务选择证据和记录方式，不用固定台账或脚本通过来认证质量。sources.prep 反映应用准备状态，不证明内容核验。

## 完成条件

宣告完成前对上请求范围、处理范围、核验范围、未确定项、失败／跳过项、落盘文件和应用状态。精细档不允许剩下未核可疑项；核过但无法确定可以结束核验，但必须明确汇报。确认修改后统一重查重叠和覆盖。输入版本变化时受影响报告过期。更新编排时间表时，刷新所有依赖行，或精确注明哪些行仍属于旧快照。

仍有独立工作就继续。必要能力或外部限制阻塞时说明原因、保存可恢复进度。不把抽查写成全量核验。
