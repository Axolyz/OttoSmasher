# 音频工具

## 接上工具，试一个短片段

先找宿主已有的 audio-mcp 工具。没有时，`otto setup audio --for other` 会给出接法。audio-mcp 0.4.0 的 view/analyze/timeline/melody 也能通过 CLI 调用，转写走 MCP。

通过 agent 宿主的 MCP 接入功能连接所选音频工具。audio-mcp 是当前示例，也可换成能提供任务所需波形、测量或转写的工具，连接和依赖由宿主管理。Otto 继续通过命令行提供素材、音频导出和时间映射。

CLI 语法可以先查帮助：

```sh
uvx --from 'audio-mcp[speech]==0.4.0' audio-mcp view --help
uvx --from 'audio-mcp[speech]==0.4.0' audio-mcp analyze --help
```

优先复用宿主已有的连接；需要 CLI 时，沿用它的包版本、extras、Python 和缓存配置。`uvx` 是 `uv tool run` 的别名，会在隔离的缓存环境里运行工具，同一配置后续通常直接复用，不必另建环境或重复安装。`audio-mcp` 不在 PATH、`uv tool list` 没列出它，都不能说明 uvx 没有可用缓存；直接用原来的 uvx 命令检查即可。缓存由 uv 管理，使用正常时沿用现状；升级或排错时再按需要刷新。

对一个真实短片段试用可视化工具，打开返回的图片。再试任务需要的其他能力，例如洗字幕时的 transcribe，记下哪些调用成功、哪些还需配置。转写为空时，可以扩大窗口或对照原音核实。

## 准备输入

用 exports.wav 导出短资产范围并保留 mapping，或对应用返回的原片路径用 ffmpeg 截取。短文件可以省去每个疑点都解码整集的时间。片段包含完整句子，并留够理解相邻发言的上下文。

首次使用会安装依赖，首次 turbo 转写可能下载约 1.6 GB，新环境接入时说明这项成本。已有完整模型缓存可以复用，准备好后可用 HF_HUB_OFFLINE=1 离线运行。下载中断时保留错误，检查网络或已配置的代理再续传；全局网络设置由用户管理。

配置音频工具时可以继续其他准备，环境里确实解决不了的部分再请用户协助。otto status 显示应用自己的模型，外部音频工具通过各自的调用检查。

## 怎样使用结果

波形帮助找起止和停顿，转写帮助核对词语；尖声感叹可能漏识别，词时间也有近似误差。对齐适合精修已经找到的那句话。结合字幕、相邻对白和这些结果判断边界与声音归属，需要时再用声纹辅助。
