# 核对与收尾

## 理解当前字幕

先读原文及有关样式／轨道信息，选几段对照声音，弄清当前来源怎样表示名字、换人、读音和音效。cleaning.md 列了一些常见写法，可以从那里开始，再补上这份字幕特有的形式。

需要统计或收集候选时，根据观察写临时脚本。遇到暂时读不懂的写法，留出来结合上下文再看，随后调整统计办法。最终产物可用应用的解析规则检查。

## 按选定精度核对

检查句子首尾、先后换人及重叠，也看看没有静音间隙的相邻发言。筛查办法和阈值根据素材选择；精细档核完发现的全部可疑项，并按场景抽查其他条目。

用 `exports.wav` 取得完整句子及足够上下文，保留 mapping，再用 audio-mcp 看曲线、核内容。边缘声音的归属不清时扩大上下文，需要时加对齐或声纹。轮次已经清楚、名字还未知的，可以先拆开，分别保留已知身份。

长任务记下输入版本、实际覆盖、处理决定和未决项，形式以方便继续工作为准。每项核过后留下简短结论和必要的证据位置。

## 写回并检查结果

确认的修改用带版本的 `edits.apply` 写回，或用于生成导入前的最终字幕。用 `subtitles.parse` 查看最终的说话人、问题和 OP/ED 配对，再检查重叠、覆盖及名字是否一致。

查看逐项分析结果，刷新受修订影响的部分。输入或编排有变化时一起更新相关记录。收尾汇报实际检查的范围、保存的结果和仍待确认的条目。
