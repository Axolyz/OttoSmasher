# 核验证据与收尾

## 先理解当前来源

先读原字幕及有关样式／轨道信息，再决定怎样统计标注。输入格式和惯例没有穷尽的列表，cleaning.md 里的写法只是例子。解析器给出空说话人或非台词分类，不能证明原文没有说话人信息或语音。

从当前来源的实际写法提出假设，用代表片段的声音和上下文验证。需要统计或收集候选的脚本时，根据这些观察临时编写，保留未理解的写法，遇到新惯例就修订。不能强行套已知分类，也不能把脚本没报的条目视为正确。应用解析规则规定的是最终交付格式，不是对所有原始字幕的解释。

## 按约定范围核验

根据素材选择合适的证据和筛查办法。首尾、先后换人及重叠都要看，包括没有静音间隙的相邻发言。不规定通用的能量阈值、短句秒数或括号模式。精细档核完约定范围内综合筛查发现的全部可疑项，并按场景抽查正常项；说明筛查可能漏掉什么。

用 `exports.wav` 取得完整句子及足够上下文，保留返回的 mapping。用 audio-mcp 看实际曲线、核内容，必要时扩大上下文。ASR 词时间、能量和强制对齐都是线索，不是真值，也不能证明声音归属。身份未知不取消拆开已知先后换人的要求。

长任务留下足够恢复进度的记录：输入版本、实际覆盖、观察、决定、证据和未决项。形式按任务选择，不规定台账 schema，也不以脚本退出码认证完成。不能根据阈值输出或生成音频文件就标记已核验。

## 对账与写回

只把确认的修改放进带版本的 `edits.apply` 批次，或用于生成导入前的最终字幕。用 `subtitles.parse` 检查最终产物是否符合当前应用规则；解析成功既不能证明正确理解了原文，也不能证明对轴质量。

修订后复查重叠、覆盖、名字和请求范围。不一律按中点消除重叠，也不固定 padding 扩所有句子。检查逐项分析失败并刷新受影响结果，应用准备状态不等于内容核验。输入变化时受影响结论失效；如实汇报不确定和未核范围，不能把抽查写成全量核验。
