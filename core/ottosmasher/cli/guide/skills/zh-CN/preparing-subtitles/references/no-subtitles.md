# 无字幕打轴

这是一个还在完善的方法，工具没有定型。VAD 和 ASR 用你环境里现有的，并在汇报里写明用了什么。

## 为什么这样做

这是作者试过几种方法后的结论，没有量化对比，也只试过一部分素材：

- **直接 ASR：** 误识别已经不多，但时间轴有轻度偏移，后面的语音分析又依赖这份时间。
- **在时间窗内强制对齐：** 窗口里只包含这句话时对得准。多进来或者少掉 0.5 秒，结果就很差。
- **ASR 后再强制对齐：** 能修一部分偏移，但断句很差，一句话可能被拆到上下两条里，要人工精修。

所以这里用 VAD 提供候选时间，把断句留给 agent，把人工审阅留给拿不准的部分。

## 步骤

1. **准备声音。** 用分离后的人声；原本就是干声的素材可以直接用。
2. **低阈值 VAD 切段。** 保留弱声和尾音，候选起止仍需核验。
3. **逐段 ASR。** VAD 边界只作起点，按约定精度核验首尾。
4. **合并断句。** 由你把碎段合成完整的句子，一条放一个人连续说的话。合并只改边界和分段，不要顺手改写识别出来的词。
5. **标出低置信片段。** 比如识别工具标为不确定的词、很短的碎段、语义接不上的地方、可能几个人重叠的地方。把它们列给用户，说明时间和原因。用户只审这些。
6. **写回。** 写成和视频同名的 UTF-8 `.srt`，再按 `references/cleaning.md` 的最后一节放回应用。

转写的局限见 `otto guide combine`：尖声感叹和人群喊话容易漏，提示词还可能带出没人说过的话。

## 不适用的情况

- **已有字幕：** 字幕组的粗轴微调比这个方法好。对不上轴多半是 TV 版和 BD 版的差异，用 `references/cleaning.md` 里核对时间轴的办法。
- **歌词打轴：** 歌词时间比较准、发音也清楚，又只需要词级，正好适合强制对齐，不用走这个流程。
