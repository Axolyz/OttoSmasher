# 按说话人分组（实验性）

应用不做这件事。用 `scripts/` 里的脚本算声纹，分组和判断由你自己完成，结果写回段的 `speakers`。
下面的做法和数字只来自一部作品，换作品要重新校准。实测结果在 `references/experiments.md`。
用户通常只关心有名有姓的主要角色：话少的路人可以留在待定，一个角色有两套声线时也可以分成两组。

## 准备

1. 先给标注做体检（`references/cleaning.md`）。段的 `speakers` 只有确定能读出的部分，`speakersWithheld` 为真的段在 `raw` 里还有标注。
2. 从 `raw` 或字幕文件读标注样本，并按体检结果解释：整行括号可能标的是下一行，读音括号不是名字，「人」「たち」「一同」之类表示多人。
3. 用分离后的人声。用 `assets.tracks` 找音轨，用 `exports.wav` 导出，它返回的 `mapping` 能把文件秒换成原片秒。
4. 用 `speech.align` 的 `lines` 切开两行字幕，窗口是字幕时间前后各 0.2 秒。试验里，说话人切分模型分不清动画里的女声。
5. 算声纹：`uv run scripts/speaker_embed.py 人声 时间段.json 输出前缀`。需要 uv 和 ffmpeg，第一次运行会下载 PyTorch 和模型，共几百 MB。用法写在脚本开头。

相似度偏低是正常的：同一个人约 0.3–0.4，不同人约 0.2。要比相对高低，不要套 0.7 这类固定门槛。

## 有标注时

把标注直接当声音样本。

1. 主要角色是整季标注行数最多的几个人（试验里至少 40 行）。其余有名字的单人可合成“其他”背景类；它不能直接写成输出身份。多人标注和唱歌不当样本。
2. 逐行计算：每个类别取最像的 5 条样本的平均相似度。两行字幕切开的两半各算一行。
3. 最高的主要角色比第二名高出差距门槛才归给它，否则留在待定。
4. 差距门槛要在这部作品上校准：把样本分成几份，轮流用其余的猜这一份，挑出达到目标准确率的最低差距。
5. 标注少时，把把握很大的结果（按 98% 校准）加入样本，再跑一轮。

## 没有标注时

1. 两行字幕两半的声纹不像时就分开（试验里是 0.36，即双峰分布的中间），并禁止这两半归同一个人。时间重叠的两句也禁止。
2. 让 1.5 秒以上的句子参与分组。先把空隙不超过 1 秒、相似度不低于 0.45 的相邻句连起来，再对整季做带禁止约束的平均连接层次聚类。
3. 按总时长取前 20 组，每组导出几条代表句请用户命名。一个角色可以有好几组；未命名组保持待定，“其他”背景类不能写成输出身份。
4. 逐句判断：和最像的主要角色组相似度够高，且比其他角色和“其他”组高出差距门槛才归。60 秒内已确认出场的角色，差距门槛放宽 0.05。
5. 用归进来的长句重算各组，再判断一轮。

有两条要特别注意：

- 这里要和每组的**平均声纹**比，因为分组来的样本里混着别人的句子，“最像的几条”很容易正好挑中它们。有标注时样本干净，所以那边的做法才更好。
- “其他”只用用户确认过的组，以及明显不像任何主要角色的组。没命名的小组里常混着主要角色的碎片。

## 写回

字幕还没导入时，把名字写进字幕文件（顺序见 `SKILL.md`）。已经在资料库里的段，用 `edits.apply` 写 `speakers`（实体 `segment`，字段 `speakers`）。它会记成“改过说话人”，`segments.regenerateSpeakers` 会跳过。

- 字幕已经标了的段不要覆盖。猜的结果和标注冲突时列给用户。
- 先后两人用 `segments.split` 或在导入前拆 cue，各写一个名字；同时发言才可写多个名字。边界已知时不因为名字待定而合并。
- 待定身份不写。先后两人应按已确定轮次拆开，分别保留已知身份；同时多人且其中身份未知时不虚构其名字。汇报有多少条待定、在哪几集。
- 声音相近的主要角色最容易认错，抽查时先看它们。

## 校准与核验范围

整季、至少 40 行、top-5、98% 或双峰门槛是参考实验，不是跨作品标准。优先复用用户确认的参考，按说话风格／场景取样校准并报告样本数、预测覆盖和误差；交叉验证分组避免同一句或近重复泄漏。样本过少时说明不确定性，不能凭很少验证样本宣称可靠准确率。按任务精度核完声音相近、短句、多人和标注冲突的可疑项。
