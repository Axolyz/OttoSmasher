# 命名与试听交付

## 留下来源关系

候选保留一个稳定 ID，附原切片、适用声部、来源资产与区间、原片时间映射、根音与音分校正、测量和推荐理由。按当前任务选有用字段，可以用 JSON 或表格，不必把所有信息塞进文件名。

沿用已有命名风格。没有约定时，库里的名称可保留原音和原句，如 `aa（原句）`，另用用途标签关联声部；文件可用 `C01_aa_C5.wav`。能从短名分清候选即可。`pitched` 适用于有调性的单音，`unpitched` 适用于无调性的单音；鼓件名称和采样器映射另记，避免把瞬态误当旋律根音。

用 `exports.wav` 导出区间时保留它返回的 mapping，时间换算使用对应文件的映射。短上下文方便用户辨认切到哪个声音；已经有库内采样时附 ID，便于回到原素材。

## 渲染同段试听

为同一用途的候选用相同的音符或鼓型、时值和力度。MIDI 读取实际速度事件；一个轨道可能换通道或程序，一个通道也可能跨轨。按声部和鼓件解释，轨名、通道 10 和程序号作为线索，结合实际事件判断。

保留与目标有关的复音、踏板和弯音，读取弯音范围；文件未声明范围时说明渲染所用的假设。选短而有代表性的活动片段，再补听容易暴露问题的极端音或长音。循环需求按目标音符计算；生成了六秒试听不代表整轨都已核验。

等响比较时检查峰值余量，短音可用 RMS、峰值和听感共同判断；记录归一化、包络、循环、移调方式和效果。原切片保留原样，处理后的试听另存。候选靠较多加工才能成立时，让用户能听出原音与处理后声音的区别。

## 网页对照

有多个声部和备选时，按声部并排放候选通常比长串文件更容易比较。每张卡片放一句差异、关键指标、目标片段试听，再按需展开原切片和上下文。让用户能停播、筛轨和回到原始文件，字号、布局和说明按任务调整。

可用 `scripts/build_audition.py` 从已有切片和渲染结果生成本地 HTML。它只负责展示，不计算指标或渲染 MIDI，也可以自行生成其他样式。脚本只用 Python 标准库，按 JSON 文件所在目录解析音频路径，页面输出到同目录；页面引用原文件，分享时连同音频一起带上。

```sh
python scripts/build_audition.py review.json
```

最小输入示例；`label`、`note`、`facts` 可用用户的语言，候选数与分组数不限：

```json
{
  "title": "Instrument candidates",
  "note": "Same MIDI passage; level matched. Looped sustains are indicated.",
  "groups": [{
    "name": "Lead",
    "note": "MIDI 60-84; short notes",
    "candidates": [{
      "id": "C01",
      "label": "a / bright",
      "note": "Clear harmonics; the longest note needs a loop.",
      "facts": {"root MIDI": 72, "duration ms": 240},
      "audio": [
        {"label": "MIDI preview", "path": "previews/lead_C01.wav"},
        {"label": "Original", "path": "raw/C01.wav"},
        {"label": "Context", "path": "context/C01.wav"}
      ]
    }]
  }]
}
```

`facts`、各级 `note`、候选的 `label` 可省略；`audio` 可只有原切片，适合快速初选。相对路径和共享候选都可复用。网页在窄屏改为纵排；推荐排序由输入顺序决定，脚本不替你评分。

## 收尾核对

把实际选中的声部与交付清单对一遍；检查音频能解码、非空、切点与来源对应，试听链接可以打开。比较页中的根音、处理方式和循环需求要和最终音频一致。

汇报实际筛查范围、每个用途的推荐与备选、已写入库或导出的内容，以及仍待核验的地方。将听辨结果与测量推断分别说清，让用户直接试听作选择。
