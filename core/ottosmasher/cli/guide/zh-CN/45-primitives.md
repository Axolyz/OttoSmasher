# 原始能力：不进库的计算

命令分两层（`otto commands --layer library|primitive`）：**业务命令**操作资料库里的对象（原素材、采样、编辑、撤销）；
**原始能力**只做计算、不改资料库，声音可以是库里的音轨，也可以是任意文件，不用先登记。两层用的是同一套引擎和模型，结果和应用里一致。
要把结果留在库里（能检索、能撤销），就用业务命令；只想算一下、或者处理库外的声音，就用原始能力。

## 声音输入

`{"assetId": "<音轨>", "start": 秒, "end": 秒}`（资产秒）或 `{"path": "/某个/文件.wav", "stream": 0, "start": 秒, "end": 秒}`（文件秒；视频也行，`stream` = 第几条音频流）。
`start` / `end` 不给就是整条。

## 命令

| 命令 | 做什么 | 结果 |
|---|---|---|
| `speech.align {"items": [{"text", <声音输入>}, ...]}` | 日语对齐：音素、音拍、词的时间 | `speech.alignResults {"jobId"}` |
| `text.analyze {"texts": [...]}` | 日语读音：音素、音拍（片假名）、词与读音（用户辞典生效） | `text.analyzeResults {"jobId"}` |
| `f0.track <声音输入>` | 音高（FCPE，和应用的音高检索同一个模型）：每 10 ms 一帧的音高、置信度、能量 + 中位音高 | `f0.trackResults {"jobId"}` |
| `subtitles.parse {"path", "duration"}` | 应用按当前规则会把这个字幕文件读成什么（台词、音效、说话人、OP/ED 配对） | 直接返回 |
| `subtitles.ruleTest`、`dictionary.check`、`spectrum.get` | 一行字幕的解释、用户辞典的校验、一段音轨的频谱 | 直接返回 |

前三个是任务：加 `--wait` 会一直等到结束，并把逐条结果一起打印出来（`{"job", "results"}`）。一批里某一条失败（例如文字只有符号）不影响别的条。
`subtitles.parse` 的 OP / ED 按媒体时长判定，给上 `duration`（缺省用最后一条字幕的结束时间，判定可能不对）。

## 对齐的适用条件

对齐器只会把整句**放进你给的窗口**，不会自己去找这句话在哪，也从不报“对不上”。窗口要紧贴实际说话：前后各留零点一到零点二秒。
2026-10-29 / 30 用 60 句台词试过：窗口放宽到前后 0.5 秒，约一半的句子起止就会偏 0.3 秒以上；时间错开 0.5 秒以上基本都对不准。
结果里的 `edges`（窗口两端到首尾音素的空白）和 `longestPhone`（最长的音素）是事实，不是判定：空白接近 0 可能是说话被窗口截断，某个音长得离谱多半是窗口太宽。
窗口从哪来：已有的台词段、带词时间戳的转写、或者音量起止。日语以外的语言不支持。
