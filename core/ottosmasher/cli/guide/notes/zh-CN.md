# 做法与经验（不是规定）

这里是用 `otto` 做真实任务时攒下的做法和踩过的坑。**它们不是规定，可能过时**；操作上的事实以正式说明书为准，参数以 `otto describe` 为准，
所有者的约定（`otto guide playbook`）优先于这里。拿不准就按自己的判断来。

## 分离策略：整集还是只分离用得到的

- **整集分离**：一次做完，之后洗字幕、对轴、建采样、分析都能用这条人声，返工少；代价是每集十几到几十分钟。用户自己在应用里全选也能跑。
- **只分离用得到的段**（`separation.submit` 给 `start` / `end`）：快，适合只要几句、或者先看看效果；局部声部当不了默认轨，用的时候直接给它的 `assetId`。
- 2026-10-30 实测（HyperACE v2，Apple 芯片）：每个分离任务启动约 8 秒，之后每秒音频约 0.35 秒——5 秒的段 8.5 秒、60 秒的段 29 秒，24 分钟一集约 9 分钟。
  所以一句一个任务、几十句以上时，总时间就接近整集分离了。
  用 `ranges` 一次交多段：应用把它们拼成一个输入一起分离（10 段 × 6 秒实测 31 秒，分开交约 100 秒）。
  分离结果和上下文有关：同一句单独分离、拼在一起分离、放在前后一分钟里分离，三者差别约 −9 dB（单独和拼接彼此一样接近）；要求高的句子用更长的范围或整集。
- 洗字幕、对轴要看清人声，通常**先分离再洗**。整集分离时，把要分离的几集一次提交，然后照总览第 5 条的方式等，不要空转。

## 洗字幕

目标：每集一个和视频**完全同名**的 UTF-8 `.srt`，每条只写实际说出来的话。原来的 `.ass` 不用动（同名时应用优先用 `.srt`）。（改所有者的文件前先留 `backup_` 原件——见总览的基本规则。）

**说话人的写法**（应用只认这一种，见主题 `prepare`；不合这个写法的地方应用宁可不记）：
- 一条字幕 = 一个人连续说的话。原字幕一条里两个人的（CC 字幕很常见），用 `speech.align` 的 `lines` 找到两行的分界拆成两条
  （窗口 = 字幕时间前后各 0.2 秒；切点取两行之间空隙的中点，切出的两条可以延伸到对齐找到的说话起止）；某一行对齐出来不到 0.1 秒，
  多半是在人声里找不到（和别人叠在一起、或在窗口外），这条就不拆、不标。拆分要靠人声，所以先分离再洗。
- **每个台词行**都写行首 `（名字）`，不知道是谁就不写；几个人同时说写 `（A、B）`；同一个角色全季只用一个名字。
- 音效单独成一条（整行一个括号，时间同原来那条）；台词里不留别的括号（读音删掉；说出口的词去掉括号留下）。
- 原字幕的标注习惯（只标第一行、只标第二行、名字单独占一行……）各来源不同，先体检（见“按说话人分组”），再判断后写成明确的名字；判断不出来就不写。
  没有标注的条目可以用声纹补（同一节）。

2026-10-31 按这个写法修过《孤独摇滚》12 集（所有者的 bangumi 里有一份）：227 条两人条目拆开 210 条，17 条找不到其中一行不拆；
没有标注的 2882 条用声纹猜出 2129 条（校准到 97% 准确率），其余不写。

常见问题与改法：
- **字幕组的中日双语 ASS**（最常见）：按样式名（`JP` / `CN` 之类）或文字本身只留日语；同一条里用 `\N` 上下排的只留日语那行；
  去掉特效标签、只有特效的行（标题字、注释、屏幕文字翻译）；OP/ED 与插入曲的歌词行删掉，按歌词的时间写成 `♪～` / `～♪` 标记，或导入后 `oped.add`。
- 正文里的读音括号 `歳納(としのう)京子` → 删掉括号。
- 第一行音效、第二行台词的条目 → 拆成两个时间相同的条目（音效一条、台词一条）。
- 哼歌写成 `♪（ハミング）` → 改成音效行 `（ハミング）`，有歌词就写歌词。
- 文件名和视频不同（多前缀、语言后缀）→ 写一份同名的。机器转写（`.ja.srt`）和正式字幕都有时，优先正式字幕（有说话人）。
- 内挂字幕：`ffmpeg -i ep01.mkv -map 0:s:0 ep01.ass` 提取；图形字幕要先做文字识别。
- **时间轴对不上**（TV 版字幕配 BD 视频之类）：整体差几秒，或在原来 CM 的位置之后才开始差。开头、中间、结尾各抽几句，
  用人声对照（转写的词时间、音量起止）；整体偏就平移全部，从某处开始偏就从那里起平移。
- 没有字幕：可以在本机做语音识别生成同名 `.srt`。

洗完的检查：`subtitles.parse {"path", "duration"}` 或（已登记的）`sources.rescan --wait` → `subtitles.preview {"sourceId"}`，
看 `speakers`（出现台词片段、读音、奇怪的名字 = 还有括号没清干净）、`withheld` 为真的条（有标注但没记：还有没标全的条目）、`problems`、要对齐的 `text`、`oped`。

## 对轴：先粗对，再用对齐精修

2026-10-29 / 30 用 60 句已分析的台词试过：对齐器会把整句硬塞进给它的窗口，不会自己找这句话在哪；窗口宽了、偏了都对不准（数字见主题 `primitives`）。
做法：先用带词时间戳的转写（例如 audio-mcp 的 `audio_transcribe`，Whisper）或音量起止把边界粗对到零点一到零点二秒，
再用 `speech.align`（不入库，窗口前后各留零点一到零点二秒）拿首尾音素精修，最后写回段。分离出的人声比原混音稳。
结果里 `edges` 接近 0、或某个音长得离谱（例如 0.8 秒的「ン」），多半是窗口没盖准或和别人的台词重叠。

## 外部工具的时间换回原片

WAV 导出的结果带 `mapping`（文件秒 → 原素材秒，折线）：外部工具给出文件里的时间 t，按 `mapping` 插值就是原片时间。
用 `otto run` 跑的脚本也可以直接用应用的实现：`from ottosmasher.domain.mapping import Mapping; Mapping.of(m).to_source(t)`。
写回台词边界：`segments.get` 拿版本 → `edits.apply`（实体 `segment`，字段 `start` / `end`）。

## 批量改台词

一批 `segment` 的 `start` / `end` 更新放进同一个 `edits.apply` 的 `ops`，一次提交、一次撤销。删掉不要的段：字段 `{"deleted": true}`。
改了文字或边界的段原来的分析会停用；设置 `analysis.auto_rerun_segments`（默认关）开着时应用会在后台重新分析，否则要自己提交。

## 挑台词

几千行台词不要全读进上下文：先在本地按关键词或规则粗筛出候选，再逐条读候选和前后文判断。
关键词会误中（《兽娘动物园》里「ボス」是角色、「プレーリー」是动物）。拿不准的列给所有者。

## 没有字幕时找 OP / ED

同一部作品每集的 OP / ED 是同一首歌：抽出几集开头和结尾几分钟的音频互相比对，最长的一段近乎相同的就是 OP（或 ED），再 `oped.add`。
对不上的集（换了版本、没有 OP）如实告诉所有者，不要硬标。2026-10-24 在摇曳百合上试过：起点误差 < 0.1 秒，终点多约 6 秒。

## 分析结果看着不对

先找原因：字幕错字、人声轨不对（原混音里有音乐）、段的边界不准；改正后重新分析。拿不准就导出那段音频自己听或看频谱。

## 听不到声音时

audio-mcp（所有者用 `otto setup audio` 接上）：`audio_view`（频谱 / 波形图）、`audio_analyze`（响度、峰值、起音、音高等）、
`audio_transcribe`（Whisper turbo，带词时间和不确定词，只能经 MCP 调用）。只用 CPU，长音频用 `start` / `end` 分段。
粗看音高它够用；要和应用的音高检索一致就用 `f0.track`。

## 按说话人分组（实验性）

给台词标上“谁说的”。应用不做这件事：声纹用附带的脚本在你自己的环境里算，分组和判断你自己算，结果写回段的 `speakers`。
下面的做法和数字只来自一部作品（2026-10-30，《孤独摇滚》整季 12 集、Netflix 日语 CC 字幕、HyperACE v2 分离的人声），换作品要重新校准。
所有者通常只关心有名有姓的主要角色：话少的路人全进待定也可以；一个角色有两套声线时分成两组没关系。

**先给字幕做体检**（只看文字，几秒钟）。能确定的只有一条：换人必换行（一行文字 = 一个人）。其余的标注习惯因来源而异：
- 一条里两行都标了 = 换人；只标第一行 = 多半同一个人；只标第二行、相邻两条标同一个名字，各来源差别很大
  （试过的字幕里，相邻两条都带标注时是同一个人的比例从 3% 到 47%；只标第二行的两行字幕从 0 条到上千条）。先统计，再决定标注能信多硬。
- 字幕组的字幕一般没有标注；CC 字幕只在看不出是谁时才标，所以有标注的行往往更难。
- 应用只按“洗好的写法”读说话人，拿不准就不记：段的 `speakers` 只是**确定能读出**的那部分（孤独摇滚没洗时只有约六成标注被记下），
  `speakersWithheld` 为真的段原文里还有标注。标注样本要从段的 `raw`（原文）或字幕文件里自己读，按体检的结果解释
  （整行括号可能标的是下一行；读音括号不是名字；「人」「たち」「一同」之类是多人）。字幕已经洗好时 `speakers` 就是全部。

**材料**
- 用分离后的人声，不用原混音。人声轨的音轨号：`assets.tracks`；导出：`exports.wav`（返回的 `mapping` 是文件秒 → 原片秒）。
- 两行字幕先切开：`speech.align` 用 `lines` 代替 `text`，一次对齐两行，结果里每行有起止；窗口 = 字幕时间前后各 0.2 秒。
  试验里，真实换人的两行两半都切对：对齐 63%，pyannote 和 Nemotron 这类说话人切分模型 11–12%——它们分不清动画里的女声。
- 声纹：`otto guide speaker_embed.py > <你的临时目录>/speaker_embed.py` 存下脚本，再 `uv run speaker_embed.py 人声 时间段.json 输出前缀`
  （要 uv 和 ffmpeg；第一次会下载 PyTorch 和模型，几百 MB；用法和容易做错的细节写在脚本开头）。12 集约 9000 段，CPU 上两三分钟。
  模型 anime_speaker_embedding（char）：试验里跨集认人 87%，ReDimNet2+ 80%，WeSpeaker ResNet293 72%。
- 相似度偏低是正常的（同一个人平均 0.3–0.4，不同人 0.2 左右）：比相对高低，不要套 0.7 这类固定门槛。

**有标注时**：标注直接当声音样本。
- 主要角色 = 整季标注行数多的几个人（试验里 ≥ 40 行，8 人）；其余有名字的单人合成“其他”；多人标注、唱歌的不当样本。
- 每行（两行字幕切开的两半各算一行）：每个类别取最像的 5 条样本的平均相似度，最高的主要角色比第二名高出差距门槛才归，否则待定。
- 门槛不要借别的作品：把样本分成几份，轮流用其余的猜这一份，挑出准确率达到目标的最低差距——这就是这部作品自己的校准。
- 试验（藏起五分之一的标注来猜，轮 5 次）：准确率 95%、找回率 73%；1 秒以内的短句 49%，1–2 秒 77%，2 秒以上 85%。要 97% 准确率时找回率 66%。
  逻辑回归、每人一个平均声纹都不如这样做；“附近有这个角色的标注”加分没有用。
- 标注少时：只有约 240 行样本时找回率 53%；把把握很大的结果（按 98% 校准）当样本再来一轮，升到 61%。样本够多时这一步几乎没用。

**没有标注时**
1. 两行字幕两半的声纹不像（相似度的双峰分布中间，试验里 0.36）就分开，并禁止两半归同一个人；时间重叠的两句也禁止。
2. 1.5 秒以上的句子参与分组：相邻（空隙 ≤ 1 秒）且很像（≥ 0.45）的先连成段，再整季做带禁止约束的平均连接层次聚类。
3. 按总时长排前 20 组，导出每组几条代表句让所有者听、命名；一个角色可以有好几组声线，各自保留；没名字的当“其他”。试验里听 20 组就够，再多找回率不升。
4. 逐句：和最像的主要角色声线组相似度够高，且比其他角色和“其他”组高出差距门槛才归；60 秒内已确定出场的角色，差距门槛放宽 0.05；
   用归进来的长句重算各组，再判断一轮。“其他”只用所有者确认过的组和明显不像任何主要角色的组——没命名的小组里常混着主要角色的碎片，拿它们当反面，找回率会掉一半。
   这里每组用**平均声纹**比，不要用有标注时那种“最像的几条样本”：分组来的样本里混着别人的句子（重算时还会加进判错的），“最像的几条”很容易正好挑中这些错样本，把句子带偏；平均能把少数错样本冲淡。试验里换成“最像的 5 条”，找回率从 65% 降到 60%，1 秒以内从 36% 降到 14%。有标注时样本干净，“最像的几条”才更好。
5. 试验（门槛在 1–6 集挑、7–12 集打分）：准确率 94%、找回率 65%，1 秒以内 36%。用全部标注当声音样本的理想上限也只有 63% 左右：卡在声纹本身（短句、相近的声音），不在分组。

**写回**：段的 `speakers` 用 `edits.apply`（实体 `segment`、字段 `speakers`；会自动记成“改过说话人”，`segments.regenerateSpeakers` 会跳过它）。
- 字幕本来标了的段不要覆盖；猜的和标注冲突的列给所有者。
- 一条里两个人：要么在这个段上写两个名字，要么用 `segments.split` 在两行之间切成两段再各写一个（切开的段受保护，原来的分析停用）。按所有者的约定，没有约定就问。
- 待定的不写（一条里有一行待定，整条都不写，免得把半条当成整条），汇报里说有多少、在哪几集。认错多发生在声音相近的主要角色之间（试验里虹夏 ↔ リョウ、ひとり ↔ 虹夏 / 喜多），抽查时重点看这些。

## 一个完整例子（提纲）

“把这几集里说到游戏的台词建成语音采样、打 `topic:game`，在里面找某个节奏，导出命中”：
看 playbook → 登记 → 分离（整集，后台等）→ 洗字幕、导入 → 脚本粗筛 + 逐条判断 → `samples.plan` / `samples.createPlanned` → `speech.submit`
→ `samples.batchEdit` 加标签 → `search.speech` → `hits.export` → 汇报建了什么、拿不准什么、文件在哪；要撤回用 `edits.undoSession`。

## 以前用过的外部工具（2026-10-26 的生产任务，之后已删除）

多语言句向量（MiniLM，ONNX）做中日字幕逐句匹配；mlx-whisper（small、large-v3-turbo）本地转写疑点；Matplotlib 画波形 / 音高 / 频谱；Mido 读 MIDI；
RAR / UnRAR 解压字幕包。用完的工具和模型要清理，列出删了什么。

## 踩过的坑

- 长时间开着一条连接做外部计算时，事件可能积压；短连接（每次 `otto call`）更稳。
- 65 集整集分离曾经把磁盘占满（中间文件，已修：成功后自动删）；大批分离前看看磁盘空间，分批提交。
- 工作文件不要堆在工作区根目录；放在自己的临时目录，做完列出留下了什么。
