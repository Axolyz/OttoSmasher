# 做法与经验（不是规定）

这里是用 `otto` 做真实任务时攒下的做法和踩过的坑。**它们不是规定，可能过时**；操作上的事实以正式说明书为准，参数以 `otto describe` 为准，
所有者的约定（`otto guide playbook`）优先于这里。拿不准就按自己的判断来。

## 分离策略：整集还是只分离用得到的

- **整集分离**：一次做完，之后洗字幕、对轴、建采样、分析都能用这条人声，返工少；代价是每集十几到几十分钟。用户自己在应用里全选也能跑。
- **只分离用得到的段**（`separation.submit` 给 `start` / `end`）：快，适合只要几句、或者先看看效果；局部声部当不了默认轨，用的时候直接给它的 `assetId`。
- 2026-10-30 实测（HyperACE v2，Apple 芯片）：每个分离任务启动约 8 秒，之后每秒音频约 0.35 秒——5 秒的段 8.5 秒、60 秒的段 29 秒，24 分钟一集约 9 分钟。
  所以一句一个任务、几十句以上时，总时间就接近整集分离了。
  用 `ranges` 一次交多段：应用把它们拼成一个输入一起分离（10 段 × 6 秒实测 31 秒，分开交约 100 秒）。
  分离结果和上下文有关：同一句单独分离、拼在一起分离、放在前后一分钟里分离，三者差别约 −9 dB（单独和拼接彼此一样接近）；要求高的句子用更长的范围或整集。
- 洗字幕、对轴要看清人声，通常**先分离再洗**。整集分离时，把要分离的几集一次提交，然后照总览第 5 条的方式等，不要空转。

## 洗字幕

目标：每集一个和视频**完全同名**的 UTF-8 `.srt`，每条只写实际说出来的话；看得出说话人就写成行首括号，看不出就不写（字幕组的字幕通常没有说话人，这是正常的）。
原来的 `.ass` 不用动（同名时应用优先用 `.srt`）。（改所有者的文件前先留 `backup_` 原件——见总览的基本规则。）

常见问题与改法：
- **字幕组的中日双语 ASS**（最常见）：按样式名（`JP` / `CN` 之类）或文字本身只留日语；同一条里用 `\N` 上下排的只留日语那行；
  去掉特效标签、只有特效的行（标题字、注释、屏幕文字翻译）；OP/ED 与插入曲的歌词行删掉，按歌词的时间写成 `♪～` / `～♪` 标记，或导入后 `oped.add`。
- 正文里的读音括号 `歳納(としのう)京子` → 删掉括号。
- 第一行音效、第二行台词的条目 → 拆成两个时间相同的条目。
- 哼歌写成 `♪（ハミング）` → 改成音效行 `（ハミング）`，有歌词就写歌词。
- 文件名和视频不同（多前缀、语言后缀）→ 写一份同名的。机器转写（`.ja.srt`）和正式字幕都有时，优先正式字幕（有说话人）。
- 内挂字幕：`ffmpeg -i ep01.mkv -map 0:s:0 ep01.ass` 提取；图形字幕要先做文字识别。
- **时间轴对不上**（TV 版字幕配 BD 视频之类）：整体差几秒，或在原来 CM 的位置之后才开始差。开头、中间、结尾各抽几句，
  用人声对照（转写的词时间、音量起止）；整体偏就平移全部，从某处开始偏就从那里起平移。
- 没有字幕：可以在本机做语音识别生成同名 `.srt`。

洗完的检查：`subtitles.parse {"path", "duration"}` 或（已登记的）`sources.rescan --wait` → `subtitles.preview {"sourceId"}`，
看 `speakers`（出现台词片段、读音、奇怪的名字 = 还有括号没清干净）、`problems`、要对齐的 `text`、`oped`。

## 对轴：先粗对，再用对齐精修

2026-10-29 / 30 用 60 句已分析的台词试过：对齐器会把整句硬塞进给它的窗口，不会自己找这句话在哪；窗口宽了、偏了都对不准（数字见主题 `primitives`）。
做法：先用带词时间戳的转写（例如 audio-mcp 的 `audio_transcribe`，Whisper）或音量起止把边界粗对到零点一到零点二秒，
再用 `speech.align`（不入库，窗口前后各留零点一到零点二秒）拿首尾音素精修，最后写回段。分离出的人声比原混音稳。
结果里 `edges` 接近 0、或某个音长得离谱（例如 0.8 秒的「ン」），多半是窗口没盖准或和别人的台词重叠。

## 外部工具的时间换回原片

WAV 导出的结果带 `mapping`（文件秒 → 原素材秒，折线）：外部工具给出文件里的时间 t，按 `mapping` 插值就是原片时间。
用 `otto run` 跑的脚本也可以直接用应用的实现：`from ottosmasher.domain.mapping import Mapping; Mapping.of(m).to_source(t)`。
写回台词边界：`segments.get` 拿版本 → `edits.apply`（实体 `segment`，字段 `start` / `end`）。

## 批量改台词

一批 `segment` 的 `start` / `end` 更新放进同一个 `edits.apply` 的 `ops`，一次提交、一次撤销。删掉不要的段：字段 `{"deleted": true}`。
改了文字或边界的段原来的分析会停用；设置 `analysis.auto_rerun_segments`（默认关）开着时应用会在后台重新分析，否则要自己提交。

## 挑台词

几千行台词不要全读进上下文：先在本地按关键词或规则粗筛出候选，再逐条读候选和前后文判断。
关键词会误中（《兽娘动物园》里「ボス」是角色、「プレーリー」是动物）。拿不准的列给所有者。

## 没有字幕时找 OP / ED

同一部作品每集的 OP / ED 是同一首歌：抽出几集开头和结尾几分钟的音频互相比对，最长的一段近乎相同的就是 OP（或 ED），再 `oped.add`。
对不上的集（换了版本、没有 OP）如实告诉所有者，不要硬标。2026-10-24 在摇曳百合上试过：起点误差 < 0.1 秒，终点多约 6 秒。

## 分析结果看着不对

先找原因：字幕错字、人声轨不对（原混音里有音乐）、段的边界不准；改正后重新分析。拿不准就导出那段音频自己听或看频谱。

## 听不到声音时

audio-mcp（所有者用 `otto setup audio` 接上）：`audio_view`（频谱 / 波形图）、`audio_analyze`（响度、峰值、起音、音高等）、
`audio_transcribe`（Whisper turbo，带词时间和不确定词，只能经 MCP 调用）。只用 CPU，长音频用 `start` / `end` 分段。
粗看音高它够用；要和应用的音高检索一致就用 `f0.track`。

## 一个完整例子（提纲）

“把这几集里说到游戏的台词建成语音采样、打 `topic:game`，在里面找某个节奏，导出命中”：
看 playbook → 登记 → 分离（整集，后台等）→ 洗字幕、导入 → 脚本粗筛 + 逐条判断 → `samples.plan` / `samples.createPlanned` → `speech.submit`
→ `samples.batchEdit` 加标签 → `search.speech` → `hits.export` → 汇报建了什么、拿不准什么、文件在哪；要撤回用 `edits.undoSession`。

## 以前用过的外部工具（2026-10-26 的生产任务，之后已删除）

多语言句向量（MiniLM，ONNX）做中日字幕逐句匹配；mlx-whisper（small、large-v3-turbo）本地转写疑点；Matplotlib 画波形 / 音高 / 频谱；Mido 读 MIDI；
RAR / UnRAR 解压字幕包。用完的工具和模型要清理，列出删了什么。

## 踩过的坑

- 测音高任务 `succeeded`，结果可能是空的、错误在 `f0Errors` 里；看结果，不只看状态。
- 长时间开着一条连接做外部计算时，事件可能积压；短连接（每次 `otto call`）更稳。
- 65 集整集分离曾经把磁盘占满（中间文件，已修：成功后自动删）；大批分离前看看磁盘空间，分批提交。
- 工作文件不要堆在工作区根目录；放在自己的临时目录，做完列出留下了什么。
