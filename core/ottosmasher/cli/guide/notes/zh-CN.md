# 经验笔记（不是规定）

这里是用 `otto` 做真实任务时攒下的做法和踩过的坑。**它们不是规定，可能过时**；和正式主题冲突时以正式主题为准，
参数以 `otto describe` 为准。拿不准就按自己的判断来。

## 从手头的问题找入口

| 想做什么 | 先看 |
|---|---|
| 库里已经有什么（素材、字幕、人声、分析） | `sources.list`、`sources.get`、`assets.tracks`、`textLayer.list`、`sources.prep`、`jobs.list` |
| 整理字幕、拿整集或局部人声 | 主题 `prepare`；分离不依赖字幕，可以先拿人声帮自己处理字幕，最后再导入 |
| 挑台词、截取、分析、打标签 | 主题 `samples` |
| 把声音交给外部工具，再把结论写回 | 主题 `combine`、`export`（结果里的 `mapping`） |

不用每次从头准备一遍：已有的结果直接接上。

## 几种组合

- 字幕已经合适：导入文本层 → 结合前后文筛台词 → 只对选中的段分析或建采样。
- 处理字幕时要听清人声：登记原片 → 用已有或新分离的人声（可以只分离一段）→ `exports.wav` 导出相关区间给外部工具 → 字幕处理完再导入。
- 只有某个声音值得用：局部分离、导出或截取，定好范围再建采样或拉平；不必先补齐整集字幕。
- 比较乐器 / 单音素材：读音高、导出片段，在外部比较频谱等特征，把候选打标签交给所有者试听。

## 外部工具的时间换回原片

`exports.wav` / `exports.range` / `exports.stretched` / `hits.export` 的结果带 `mapping`（文件秒 → 原素材秒，折线）。
外部工具给出文件里的时间 t，按 `mapping` 线性插值就是原片时间；写回台词边界用原素材秒（`segments.get` 拿版本 → `edits.apply`，实体 `segment`，字段 `start` / `end`）。
用 `otto run` 跑的脚本也可以直接用应用的实现：`from ottosmasher.domain.mapping import Mapping; Mapping.of(m).to_source(t)`。

## 批量平移台词时间

一批 `segment` 的 `start` / `end` 更新放进同一个 `edits.apply` 的 `ops`，一次提交、一次撤销。删掉不要的段：同样的更新，字段 `{"deleted": true}`。
改了文字或边界的段原来的分析会停用；设置 `analysis.auto_rerun_segments`（默认关）开着时应用会在后台重新分析，否则要自己提交。

## 对轴：先粗对，再用对齐精修

2026-10-29 用 20 句已分析的台词试过：把时间人为错开 ±0.5 / ±1.5 秒、分析窗口放宽到 ±2 秒，对齐**每次都“成功”**，
但找回的起止大多差 1–2 秒（只有少数在 50 ms 以内）——对齐器会把整句硬塞进窗口，不会自己找出这句话在哪。
所以：先用带词时间戳的转写（例如 audio-mcp 的 `audio_transcribe`，Whisper）把台词边界粗对到零点几秒，再用 `speech.align`（不入库，窗口前后各留零点一到零点二秒）
拿首尾音素的时间精修，最后写回段（主题 `primitives`）。分离出的人声比原混音稳一些。

## 听不到声音时

没有原生听觉的模型可以接 audio-mcp（所有者用 `uvx` 装、注册为 MCP 服务器）：`audio_view`（频谱 / 波形图，直接看图）、
`audio_analyze`（响度、峰值、起音、音高等）、`audio_transcribe`（Whisper turbo，带词时间和不确定词）。
对象是导出的 WAV 或原媒体文件；只用 CPU，长音频用 `start` / `end` 分段。

## 以前用过的外部工具（2026-10-26 的生产任务，之后已删除）

- 多语言句向量（MiniLM，ONNX）：中日字幕逐句候选匹配。
- mlx-whisper（small 与 large-v3-turbo）：本地转写字幕疑点，两轮复核。
- Matplotlib：画波形、音高、频谱自己看；Mido：读 MIDI 的轨道与音高；RAR / UnRAR：解压某些字幕包。
用完的工具和模型要清理，列出删了什么。

## 踩过的坑

- 关键词会误中（《兽娘动物园》里「ボス」是角色、「プレーリー」是动物）；先本地粗筛，再逐条结合前后文判断，不要把几千行台词全读进上下文。
- 字幕重新导入只替换时间交叠的旧段，不交叠的旧段会留下，需要自己删（正式主题 `prepare` 也写了）。
- 测音高任务 `succeeded`，结果可能是空的、错误在 `f0Errors` 里；看结果，不只看状态。
- 长时间开着一条连接做外部计算时，事件可能积压；用短连接（每次 `otto call`）更稳。
- 65 集整集分离：中间文件曾经把磁盘占满（已修，成功后会自动删）；大批分离前看看磁盘空间，分批提交。
- 工作文件不要堆在工作区根目录；放在自己的临时目录，做完列出留下了什么。
